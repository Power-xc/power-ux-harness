# 한국어 UX 라이팅 규칙

출처: 토스「토스의 8가지 라이팅 원칙들」(2022)·「좋은 에러 메시지를 만드는 6가지 원칙」(2022)·「Value first, Cost later」(2023), 앱인토스 UI/UX 가이드, NN/g Rachel Krause「10 Design Guidelines for Reporting Errors in Forms」(2019), GOV.UK Design System 오류 메시지 지침, Material Design 3 대화상자 지침. 규칙만 요약했고 원문 예문은 쓰지 않았다. 브랜드 보이스 문서가 있으면 그것이 우선한다.

## 1. 문체 기본값

- 해요체로 통일한다. 합쇼체와 섞지 않는다.
- 능동형으로 쓴다(「저장됐어요」보다 「저장했어요」).
- 「되어요」가 아니라 「돼요」로 쓴다.
- 긍정형으로 쓴다. 안 된다는 말 뒤에 할 수 있는 일을 붙인다.
- 지나친 높임(「\~하시겠어요?」·「\~께」·「\~시나요?」)을 줄인다.
- 명사를 이어 붙인 문장(「결제 실패 안내」)으로 끝내지 않고 동사로 끝낸다.
- 예외: 서비스 종료·만료·연체 같은 영향 안내는 수동형을 허용한다.
- 보이스는 고정하고 톤만 사용자의 감정에 맞춘다. 실패 직후에는 짧고 차분하게, 성공 뒤에는 가볍게.

## 2. 작성 원칙

| 원칙           | 확인 질문                                      |
| -------------- | ---------------------------------------------- |
| 다음 화면 힌트 | 이 문구만 읽고 다음에 무엇이 나올지 알 수 있나 |
| 덜어내기       | 빼도 뜻이 같은 단어가 있나                     |
| 빈 문장 없애기 | 아무 정보도 없는 문장(「안내드립니다」)이 있나 |
| 메시지 하나    | 한 문구가 두 가지를 말하나                     |
| 말하듯 쉽게    | 소리 내어 읽으면 자연스럽나                    |
| 강요보다 권유  | 겁주거나 몰아붙이나                            |
| 누구나 아는 말 | 내부 용어·업계 용어가 있나                     |
| 숨은 감정      | 사용자가 지금 불안·짜증·기대 중 무엇을 느끼나  |

가치를 먼저 보여 주고 비용은 나중에 묻는다. 질문이 많거나 민감한 정보를 요구하는 단계 앞에는 무엇을 얻는지 먼저 말한다.

## 3. 표면별 규칙

| 표면      | 규칙                                                                                                                                                                                                      | 예                                                                                                 |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 오류      | 무엇이 · 왜 · 어떻게 고치는지 순서. 사용자를 탓하지 않고 입력값을 지우지 않는다. 가장 좋은 오류는 나지 않는 오류다 — 문구 전에 막을 수 있는지 본다                                                        | 「카드 번호 16자리 중 15자리만 입력됐어요. 마지막 자리를 확인해 주세요」                           |
| 입력 오류 | 해당 칸 바로 아래. 빈 칸에는 할 일, 그 밖에는 조건을 쓴다                                                                                                                                                 | 「이름을 입력해 주세요」 · 「이름은 35자까지 쓸 수 있어요」                                        |
| 버튼      | 결과 동사. 한 화면의 주요 행동은 하나. 버튼만 읽어도 다음 행동이 예측돼야 한다                                                                                                                            | 「결제하기」 · 「해지하기」 · 「다음」                                                             |
| 대화상자  | 제목은 행동을 묻는다(「정말 ~하시겠어요?」처럼 확신을 묻지 않는다). 본문은 결과 한 줄, 되돌릴 수 없으면 그 사실까지. 버튼은 둘까지, 왼쪽은 「닫기」로 통일(「취소」는 작업 자체를 취소하는 뜻으로 읽힌다) | 제목 「구독을 해지할까요?」 · 본문 「해지해도 11월 30일까지 쓸 수 있어요」 · 「닫기」/「해지하기」 |
| 토스트    | 이미 끝난 일을 짧게. 버튼 없음. 설명이 필요한 내용은 담지 않는다(몇 초 뒤 사라진다)                                                                                                                       | 「저장했어요」                                                                                     |
| 스낵바    | 결과 한 줄 + 행동 하나                                                                                                                                                                                    | 「노트를 삭제했어요」 · 「되돌리기」                                                               |
| 빈 상태   | 비었다는 사실보다 다음 행동을 먼저                                                                                                                                                                        | 「첫 노트를 남겨 보세요」 + 「노트 쓰기」                                                          |
| 온보딩    | 한 화면에 메시지 하나. 다음 화면에서 얻는 것을 힌트로                                                                                                                                                     |                                                                                                    |
| 권한 요청 | 지금 왜 필요한지, 무엇에 쓰는지, 거절해도 되는 것                                                                                                                                                         | 「사진을 첨부하려면 사진 접근 권한이 필요해요」                                                    |
| 성공      | 결과와 다음 할 일. 과장된 축하는 줄인다                                                                                                                                                                   | 「신청했어요. 결과는 3일 안에 알림으로 보내 드려요」                                               |
| 진행      | 「처리 중」 대신 지금 하는 일을 구체적으로                                                                                                                                                                | 「카드사에 승인을 요청하고 있어요」                                                                |

## 4. 쓰지 않는 표현

| 표현                                      | 이유                   | 바꿀 방향                    |
| ----------------------------------------- | ---------------------- | ---------------------------- |
| 「오류가 발생했습니다」만 있음            | 원인도 할 일도 없다    | 무엇이·왜·어떻게             |
| 「유효하지 않습니다」 · 「잘못된 입력」   | 무엇이 틀렸는지 모른다 | 조건을 말한다                |
| 「필수 항목입니다」만 있음                | 할 일이 없다           | 「~를 입력해 주세요」        |
| 결정 버튼의 「확인」 · 「예」             | 결과를 말하지 않는다   | 결과 동사                    |
| 대화상자 왼쪽 「취소」                    | 작업 취소로 오해       | 「닫기」                     |
| 거절 버튼의 죄책감(「혜택을 포기할게요」) | 압박                   | 「다음에 할게요」 · 「닫기」 |
| 「앗!」 · 「죄송합니다」 반복             | 정보가 없다            | 빼고 할 일을 쓴다            |
| 「여기」 · 「더 보기」만 있는 링크        | 맥락 없이 뜻이 없다    | 「요금 안내 보기」           |
| 근거 없는 「최초」 · 「최고」 · 「1위」   | 표시·광고 문제         | 사실과 근거만                |
