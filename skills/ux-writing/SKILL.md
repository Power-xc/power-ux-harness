# UX Writing

사용자가 지금 무엇을 해야 하는지 한 번에 알게 하는 문구를 쓴다. 좋은 문구는 다음 화면을 예측하게 하고, 실수했을 때 고치는 방법을 말한다.

## Trigger

- `@ux write <화면|표면>`: 문구 작성
- `@ux copy-review <화면|문구 목록>`: 기존 문구 점검
- 「오류 문구 다듬어 줘」, 「버튼 이름 정해 줘」, 「빈 화면 문구」, 「해요체로 바꿔 줘」, 「영어 UI 문구 검토」

## Input

- `surface`: 오류 · 버튼 · 빈 상태 · 알림(토스트·스낵바·배너) · 확인 대화상자 · 온보딩 · 권한 요청 · 폼 라벨·도움말 · 성공·진행
- `context`: 화면, 사용자가 방금 한 일, 사용자의 감정 상태(예: 결제 실패 직후의 불안)
- `voice`: 브랜드 보이스 문서(있으면 기본 규칙보다 우선)
- `language`: 한국어·영어(둘 다면 둘 다)
- `limits`: 글자 수·줄 수·플랫폼 제약

## Process

1. 표면과 상황을 한 줄로 적는다 — 누가, 방금 무엇을 했고, 지금 어떤 기분이고, 다음에 무엇을 해야 하는가.
2. 언어에 맞는 규칙을 고른다. 한국어는 [`references/ko-rules.md`](./references/ko-rules.md), 영어는 [`references/en-rules.md`](./references/en-rules.md). 브랜드 보이스가 있으면 그것을 먼저 따른다.
3. 표면 규칙을 적용한다. 오류는 무엇이·왜·어떻게 고치는지, 버튼은 결과 동사, 빈 상태는 다음 행동, 확인 대화상자는 행동을 묻는 제목과 결과 한 줄, 권한 요청은 지금 왜 필요한지와 거절해도 되는 것.
4. 추천안 하나와 대안 둘을 쓰고, 안마다 따른 규칙을 적는다.
5. 금지 표현 목록으로 점검한다 — 원인 없는 오류 문구, 탓하는 말, 「확인」·「OK」만 있는 결정 버튼, 대화상자 왼쪽의 「취소」, 압박하거나 죄책감을 주는 거절 문구.
6. 같은 대상을 같은 말로 부르는지 용어를 맞춘다. 화면마다 다르게 부르는 말은 용어 목록으로 정리한다.
7. 접근성을 점검한다 — 앞뒤 맥락 없이도 뜻이 통하는 링크·버튼 이름(「여기」·「더 보기」만 쓰지 않음), 색이 아닌 글로 알리는 오류, 아이콘 버튼의 이름, 이미지 대체 텍스트.
8. 번역·확장에 대비한다. 문장을 조각내 이어 붙이지 않고, 날짜·숫자·통화·복수형은 변수로 남긴다(`{만료일}`·`{count}`).
9. 글자 수 제한이 있으면 세어서 적는다.

## Output

- 문구 표: 위치(화면 ID·영역), 표면, 현재 문구, 추천안, 대안 2개, 따른 규칙, 글자 수
- 용어 목록: 정한 말과 쓰지 않을 말
- 점검 결과: 금지 표현·접근성·번역 대비 항목별 `PASS`·`FAIL`
- 판정: 점검 FAIL이 없으면 `PASS`, 있으면 `FAIL`과 고칠 줄

## Hard Gates

| ID  | FAIL 조건                                         |
| --- | ------------------------------------------------- |
| G1  | 오류 문구가 고치는 방법 없이 틀렸다는 사실만 말함 |
| G2  | 결과가 큰 행동의 버튼이 「확인」·「OK」·「예」    |
| G3  | 사용자를 탓하거나 자주 나는 오류에 농담을 씀      |
| G4  | 같은 대상을 화면마다 다른 말로 부름               |
| G5  | 꼭 알아야 할 정보를 몇 초 뒤 사라지는 문구에만 둠 |
| G6  | 거절 선택지에 압박·죄책감을 주는 문구를 씀        |
| G7  | 가격·날짜·정책 같은 제품 사실을 근거 없이 지어 씀 |

## Skill Chaining

- 어떤 알림 패턴에 담을지 판정: `ux-review`
- 정한 문구를 화면 설계서에 넣기: `ux-spec`
- 압박·기만 문구 점검: `ux-dark-patterns`
- 링크·대체 텍스트 기준: `ux-a11y`
- AI 응답의 안내·경고 문구: `ux-ai`

## Constraints

- 제품 사실을 모르면 변수로 남기고 「정해야 할 것」에 적는다.
- 「최초」·「최고」·「1위」처럼 근거가 필요한 표현을 쓰지 않는다.
- 브랜드 보이스가 정하지 않았으면 이모지를 쓰지 않는다.
- 광고·랜딩·스토어 카피는 범위 밖이다. 제품 안의 문구만 다룬다.
- 원문 예시 문장을 다른 서비스에서 그대로 옮기지 않는다.
