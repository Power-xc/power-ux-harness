# 인터뷰 가이드 작성 규칙

출처: NN/g의 사용자 인터뷰·사용성 테스트 진행 지침(Nielsen 2012, McCloskey 2014), Rohrer(2022)의 태도·행동 구분을 인터뷰 질문 작성 규칙으로 정리했다. 원문 문장을 복사하지 않았다.

## 1. 가이드 골격 (60분 기준)

| 구간      | 시간 | 내용                                                                           |
| --------- | ---- | ------------------------------------------------------------------------------ |
| 시작      | 5분  | 자기소개, 목적, 녹화·녹취 동의, 정답이 없다는 안내, 언제든 멈출 수 있다는 안내 |
| 배경      | 10분 | 참가자의 상황과 역할 — 질문의 맥락을 잡는다                                    |
| 최근 경험 | 25분 | 가장 최근에 그 일을 한 때를 처음부터 끝까지 순서대로 확인한다                  |
| 깊이 파기 | 15분 | 앞에서 나온 막힘·우회·감정에 대해 더 묻는다                                    |
| 마무리    | 5분  | 빠뜨린 것, 마지막으로 하고 싶은 말, 보상 안내                                  |

## 2. 질문 고치기

| 고칠 질문                            | 문제                             | 고친 질문                                                   |
| ------------------------------------ | -------------------------------- | ----------------------------------------------------------- |
| 「이 기능이 유용하다고 생각하세요?」 | 유도 · 예/아니요로 끝남          | 「이 기능을 마지막으로 쓴 때를 이야기해 주세요」            |
| 「앞으로 이 서비스를 쓰실 건가요?」  | 미래 의향은 행동을 예측하지 못함 | 「지금은 이 일을 어떻게 하세요?」                           |
| 「검색이 불편하셨죠?」               | 답을 정해 줌                     | 「원하는 것을 찾을 때 어떻게 하셨어요?」                    |
| 「가격과 디자인은 어떠세요?」        | 한 번에 두 가지                  | 둘로 나눠 따로 묻는다                                       |
| 「왜 그렇게 하셨어요?」(바로)        | 방어적으로 들림                  | 「그때 무슨 생각이 드셨어요?」                              |
| 「저희가 만든 새 기능인데요…」       | 만든 사람이 묻으면 칭찬이 나옴   | 소속을 밝히지 않거나 「저는 만든 사람이 아니에요」라고 안내 |

## 3. 진행 중 원칙

- 참가자가 말한 단어를 그대로 받아 다시 묻는다(「‘귀찮다’고 하셨는데, 어떤 순간이었어요?」).
- 침묵을 바로 채우지 않는다. 몇 초 기다리면 더 말한다.
- 진행자가 해결책을 설명하거나 오해를 바로잡지 않는다. 오해 자체가 발견이다.
- 의견(「좋아요」)이 나오면 그 뒤의 경험을 묻는다(「좋다고 느낀 때가 언제였어요?」).

## 4. 기록과 정리

- 관찰 메모는 한 줄에 한 사실만 쓰고 참가자 ID와 시각을 붙인다.
- 한 일과 말한 것을 다른 표시로 구분한다(예: `[행동]` `[발언]`).
- 묶기는 결과를 다 모은 뒤에 한다. 진행 중에 결론을 내리지 않는다.
- 인용은 짧게, 참가자를 알아볼 수 있는 정보(회사명·지역·이름)를 지운다.
