# 리서치 방법 고르기

출처: NN/g Christian Rohrer「When to Use Which User-Experience Research Methods」(2022, 2026 검토)·Jakob Nielsen「Why You Only Need to Test with 5 Users」(2000)·Raluca Budiu·Kate Moran「How Many Participants for Quantitative Usability Studies」(2021)·Jakob Nielsen「Thinking Aloud: The #1 Usability Tool」(2012)·Marieke McCloskey「Turn User Goals into Task Scenarios for Usability Testing」(2014). 원문 문장을 옮기지 않고 요약했다.

## 1. 질문을 세 축에 놓는다

| 축          | 한쪽                           | 다른 쪽                                      |
| ----------- | ------------------------------ | -------------------------------------------- |
| 증거의 종류 | 말한 것(태도) — 생각·선호·의견 | 한 일(행동) — 실제로 누르고 멈추고 포기한 것 |
| 답의 종류   | 왜·어떻게(정성) — 원인과 맥락  | 얼마나·몇 명(정량) — 크기와 빈도             |
| 사용 맥락   | 실제 환경에서 자연스럽게       | 짜인 과제 · 맥락 없음                        |

말한 것과 한 일은 자주 다르다. 「쓸 것 같다」는 답은 실제 사용을 예측하지 못한다. 결정이 행동에 달려 있으면 행동을 보는 방법을 고른다.

## 2. 단계별로 자주 쓰는 방법

| 단계      | 방법                           | 맞는 질문                                        |
| --------- | ------------------------------ | ------------------------------------------------ |
| 방향 잡기 | 맥락 인터뷰·현장 관찰          | 사람들이 지금 이 일을 어떻게 하고, 어디서 막히나 |
| 방향 잡기 | 다이어리 연구                  | 며칠·몇 주에 걸친 사용과 습관                    |
| 방향 잡기 | 설문                           | 경험의 크기와 분포 — 원인은 따로 확인            |
| 방향 잡기 | 콘셉트 테스트                  | 아이디어가 문제를 푸는 것으로 이해되나           |
| 설계      | 카드 소팅                      | 사용자가 정보를 어떻게 묶고 부르나               |
| 설계      | 트리 테스트                    | 정한 메뉴 구조에서 원하는 것을 찾나              |
| 설계      | 사용성 테스트(진행형·비진행형) | 이 화면으로 과제를 끝낼 수 있나, 어디서 막히나   |
| 출시·평가 | 벤치마크 테스트                | 이전 버전·경쟁 대비 성공률·시간                  |
| 출시·평가 | A/B 테스트                     | 두 안 중 어느 쪽이 지표를 움직이나               |
| 출시·평가 | 로그·분석                      | 어디서 얼마나 이탈하나                           |

## 3. 인원 기준

| 상황                     | 기준         | 메모                                                                        |
| ------------------------ | ------------ | --------------------------------------------------------------------------- |
| 반복 사용성 테스트(정성) | 라운드당 5명 | 5명이 문제의 대부분을 드러낸다. 15명 예산이면 5명씩 세 번 고치며 테스트한다 |
| 사용자 집단이 둘         | 집단당 3~4명 | 집단마다 쓰는 방식이 다를 때                                                |
| 사용자 집단이 셋 이상    | 집단당 3명   |                                                                             |
| 카드 소팅                | 15명         |                                                                             |
| 정량 사용성 연구         | 40명         | 95% 신뢰수준·오차 15%. 위험이 낮으면 28명(90%·15%)이나 15명(90%·20%)        |

정성 테스트 결과를 비율로 쓰지 않는다. 5명 중 3명은 「60%」가 아니라 「5명 중 3명」이다.

## 4. 생각 말하기 진행 규칙

- 대표 사용자에게 대표 과제를 준다.
- 진행자는 조용히 있고, 참가자가 말을 멈추면 계속 말하게 하는 말만 한다(「지금 무엇을 보고 계세요?」). 힌트·설명·확인 질문을 하지 않는다.
- 진행자가 개입해 바뀐 행동은 결과에서 뺀다.
- 생각 말하기는 통계용이 아니다. 시간 측정과 함께 쓰지 않는다.

## 5. 과제 쓰기

- 현실적인 목표와 동기를 준다(「친구 생일 선물로 3만 원 안쪽 책을 골라 주세요」).
- 설명하게 하지 말고 하게 한다.
- 화면의 라벨이나 단계를 과제 문장에 쓰지 않는다(「‘선물하기’ 버튼을 눌러」 금지).
- 이름·날짜처럼 과제에 필요한 세부는 주되, 어디를 누를지는 알려 주지 않는다.
- 과제마다 성공 기준(끝 화면·입력 결과)과 실패로 볼 행동을 미리 정한다.
