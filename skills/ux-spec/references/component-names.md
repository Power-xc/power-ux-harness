# 컴포넌트 이름 대조표

설계서에는 왼쪽 열의 표준 이름을 쓴다. 팀의 디자인 시스템에 정해진 이름이 있으면 그 이름이 우선이고, 처음 등장할 때 괄호로 표준 이름을 붙인다.

출처: Google Material Design 3 컴포넌트 목록(2025 Expressive·2026 I/O 갱신 포함), Apple Human Interface Guidelines 컴포넌트 목록, 행정안전부 KRDS(Korea Design System) 컴포넌트 이름, The Component Gallery(component.gallery)의 별칭 정리, Material Symbols 아이콘 이름(google/material-design-icons 코드포인트 목록, 2026-11-03 확인). 5절의 위치 표시와 7절부터는 W3C WCAG 2.2(1.1.1·1.3.2·1.4.1·1.4.3·1.4.10·1.4.11·1.4.13·2.5.8·4.1.2), NN/g Angie Li「Dropdowns: Design Guidelines」(2017)·Kate Moran「Flat UI Elements Attract Less Attention and Cause Uncertainty」(2017)·Megan Brown「Glassmorphism: Definition and Best Practices」(2024), Material Components for Android 모션 문서의 전환 패턴 4가지, Apple HIG의 Page controls·Layout(홈 인디케이터와 안전 영역), SF Symbols, Android 개발자 문서「Send simple data to other apps」(Android Sharesheet), Baymard Institute의 별점 인식·평점 분포 요약 연구, NIST SP 800-63B(비밀번호 강도 안내), Fred Reichheld「The One Number You Need to Grow」(HBR, 2003), Apple의 Liquid Glass 발표(2025-06)를 더했다(2026-11-08 확인). 「—」는 해당 체계에 같은 이름의 컴포넌트가 없거나 확인하지 못했다는 뜻이다.

| 강도 표시기       | 비밀번호 강도          | —                                          | —                               |

- 진행 바는 일이 얼마나 끝났는지, 단계 표시(4절)는 흐름의 몇 번째 단계인지, 페이지 인디케이터는 넘겨 보는 화면 몇 장 중 어디인지를 말한다. 순서 없이 오가는 화면에는 페이지 인디케이터를 쓰지 않는다.
- 강도 표시기는 색만으로 말하지 않고 기준을 글로 함께 보인다(「8자 이상이면 충분해요」 — WCAG 1.4.1). 비밀번호를 정할 때 강도 안내를 주는 것은 NIST SP 800-63B가 권한다.
- 홈 인디케이터는 앱이 그리지 않는다. 그 가까이에 누르는 요소나 끄는 제스처를 두지 않고, 화면 폭 하단 버튼은 안전 영역의 아래 끝에 맞춘다(Apple HIG Layout).

## 6. 아이콘만 있는 메뉴 버튼

모양에 붙은 별명은 기능 이름이 아니다. 설계서에는 기능으로 쓴 표준 이름을 적고 모양은 괄호에 별명으로 붙인다(예: 더 보기 메뉴(케밥)). 팀 밖에서도 통하는 별명은 햄버거·케밥 정도다.

| 모양                    | 별명      | 흔한 기능 → 설계서에 쓸 이름                  | Material Symbols |
| ----------------------- | --------- | --------------------------------------------- | ---------------- |
| 가로줄 셋               | 햄버거    | 내비게이션 드로어 열기                        | `menu`           |
| 세로 점 셋              | 케밥      | 더 보기 메뉴                                  | `more_vert`      |
| 가로 점 셋              | 미트볼    | 더 보기 메뉴                                  | `more_horiz`     |
| 점 아홉(3×3)            | 와플      | 앱 전환·서비스 모음                           | —                |
| 네모 아홉(3×3)          | 벤토      | 앱 전환·서비스 모음                           | `apps`           |
| 가운데로 짧아지는 줄 셋 | 도너      | 필터                                          | `filter_list`    |
| 가로줄 둘               | 베지 버거 | 메뉴, 또는 끌어서 옮기는 손잡이 — 뜻이 갈린다 | `drag_handle`    |
| 왼쪽 정렬로 짧아지는 줄 | 계단      | 정렬                                          | `sort`           |
| 손잡이가 달린 줄        | 슬라이더  | 필터·세부 조정                                | `tune`           |

- 아이콘만 있는 버튼에는 기능을 말하는 접근 가능한 이름을 단다(「더 보기」, 「필터」 — WCAG 4.1.2). 「케밥」, 「메뉴 아이콘」은 이름이 아니다.
- 한 제품 안에서 같은 기능에 케밥과 미트볼을 섞어 쓰지 않는다.
- 주요 메뉴를 햄버거 뒤에 숨기기로 했으면 설계서에 이유를 적는다. 숨긴 메뉴는 덜 쓰이고 찾는 데 오래 걸린다(`ux-review`의 패턴 쓰임 대조표 4절).

## 7. 닮은 짝 가르기

생김새가 비슷해도 하는 일이 다르면 다른 컴포넌트다. 가르는 질문에 답한 쪽의 이름을 설계서에 쓴다. 잘못 고르면 사용자가 누른 뒤의 결과를 잘못 예상한다. 쓰임 판정은 `ux-review`의 패턴 쓰임 대조표가 맡는다.

| 짝                             | 가르는 질문                              | 답 → 이름                                                                          | 섞어 쓰면                                                                                           |
| ------------------------------ | ---------------------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 스위치 · 체크박스              | 누르는 순간 반영되나                     | 즉시 → 스위치 · 저장해야 반영 → 체크박스                                           | 저장 버튼이 있는 폼의 스위치                                                                        |
| 라디오 버튼 · 체크박스         | 하나만 고르나                            | 하나 → 라디오 · 여러 개 → 체크박스                                                 | 하나만 골라야 하는데 체크박스                                                                       |
| 상단 탭 · 세그먼트 컨트롤      | 다른 내용 묶음으로 옮기나                | 내용 묶음 이동 → 탭 · 같은 내용의 보기·조건 바꾸기 → 세그먼트                      | 세그먼트에 실행 동작                                                                                |
| 대화상자 · 바텀시트            | 답해야 진행하나                          | 결정 강요 → 대화상자 · 지금 화면을 둔 채 하나 고르기 → 바텀시트                    | 행동 목록을 가운데 대화상자로 띄움                                                                  |
| 토스트 · 스낵바                | 되돌릴 행동이 있나                       | 결과만 → 토스트 · 행동 하나 → 스낵바                                               | 토스트에 버튼 · 행동 있는 스낵바가 저절로 사라짐                                                    |
| 툴팁 · 팝오버                  | 안에서 누를 것이 있나                    | 짧은 글자만, 가리키거나 포커스할 때 → 툴팁 · 링크·버튼을 담고 눌러서 연다 → 팝오버 | 툴팁 안에 링크 · 포인터를 옮기면 사라지는 팝오버 · 터치 화면에서 툴팁에만 둔 필수 정보(WCAG 1.4.13) |
| 칩 · 뱃지                      | 누를 수 있나                             | 고르기·거르기·입력 → 칩 · 상태·개수 표시만 → 뱃지                                  | 칩 모양인데 눌리지 않음                                                                             |
| 스피너 · 스켈레톤              | 나올 내용의 배치를 아나                  | 모름·한 영역 → 스피너 · 배치가 정해진 화면 → 스켈레톤                              | 패턴 쓰임 대조표 2절                                                                                |
| 수량 스테퍼 · 슬라이더         | 정확한 작은 수인가                       | 작은 정수 → 스테퍼 · 범위의 대략 값 → 슬라이더                                     | 큰 수를 ±로만 · 정확한 값을 슬라이더로만                                                            |
| 메뉴 · 셀렉트                  | 고른 값이 칸에 남나                      | 고르면 바로 실행(복사·삭제) → 메뉴 · 값이 남음(배송 방법) → 셀렉트                 | 명령을 셀렉트에 넣고 「적용」 버튼을 따로 둠                                                        |
| 버튼 · 링크                    | 일이 일어나나, 다른 곳으로 가나          | 실행 → 버튼(`button`) · 이동 → 링크(`a href`)                                      | 이동하는 버튼은 새 탭 열기·주소 복사가 안 되고, 화면 낭독기가 역할을 잘못 읽는다(WCAG 4.1.2)        |
| 플레이스홀더 · 라벨            | 입력하면 사라지나                        | 예시, 사라짐 → 플레이스홀더 · 칸 이름, 늘 보임 → 라벨                              | 라벨 없이 플레이스홀더만                                                                            |
| 햄버거 · 케밥                  | 앱의 목적지인가, 이 화면·항목의 동작인가 | 목적지 → 내비게이션 드로어 열기 · 동작 → 더 보기 메뉴                              | 6절                                                                                                 |
| 상단 앱 바 · 하단 탭           | 이 화면의 제목·동작인가                  | 제목·동작 → 상단 앱 바 · 최상위 목적지 → 하단 탭                                   | 1절                                                                                                 |
| 카드 · 목록                    | 같은 형식을 훑어 비교하나                | 항목마다 모양·행동이 다름 → 카드 · 같은 형식을 빠르게 훑음 → 목록                  | 같은 형식의 긴 목록을 카드로 만들어 한 화면에 몇 개만 보임                                          |
| 아바타 · 썸네일                | 사람인가                                 | 사람·계정 → 아바타 · 글·영상·상품 → 썸네일                                         | 둘을 같은 모양으로 그려 누구의 것인지 헷갈림                                                        |
| 배너 · 팝업                    | 흐름을 막나                              | 화면 위 띠, 막지 않음 → 배너 · 화면을 가리고 답을 요구 → 대화상자                  | 패턴 쓰임 대조표 1절                                                                                |
| 플로팅 액션 버튼 · 아이콘 버튼 | 이 화면의 가장 중요한 동작인가           | 주 동작 하나 → 플로팅 액션 버튼 · 보조 동작 → 아이콘 버튼                          | 한 화면에 플로팅 액션 버튼 여럿 · 삭제를 플로팅 액션 버튼으로                                       |

## 8. 평가·후기

「별점 넣어 주세요」로는 아홉 가지 중 무엇인지 모른다. 사용자에게 무엇을 묻는지(입력) 또는 무엇을 보여 주는지(표시)를 먼저 적는다.

| 이름          | 입력·표시 | 묻는 것·보여 주는 것                      | 이렇게 쓰면 finding                                                                 |
| ------------- | --------- | ----------------------------------------- | ----------------------------------------------------------------------------------- |
| 별점          | 입력·표시 | 1\~5점 만족                               | 점수마다 뜻(「별로예요」\~「최고예요」)이 없음                                      |
| 반 별점       | 표시      | 평균을 0.5 단위로                         | 입력에서 반 칸을 고르게 해 누를 자리가 작아짐(WCAG 2.5.8) — 입력은 온 칸으로 받는다 |
| NPS 점수      | 입력      | 0\~10, 이 서비스를 추천할 의향(관계 지표) | 과업이 끝날 때마다 물음 · 1\~5 별점을 NPS라고 부름                                  |
| 이모지 평가   | 입력      | 3\~5단계 기분                             | 얼굴마다 글자 이름이 없음(WCAG 1.1.1)                                               |
| 좋아요·싫어요 | 입력      | 도움이 됐나, 둘 중 하나                   | 싫어요 뒤에 이유를 고를 수 없음(`ux-ai`의 피드백 + 이유)                            |
| 평점 슬라이더 | 입력      | 넓은 범위의 점수                          | 현재 값이 숫자로 안 보임 · 정확한 값을 슬라이더로만 받음                            |
| 평점 요약     | 표시      | 평균 · 평가 수 · 점수별 분포 막대         | 평가 수나 분포 없이 평균만 · 분포 막대를 눌러 그 점수의 후기로 갈 수 없음           |
| 평가 태그     | 입력·표시 | 「빠른 배송」처럼 고른 이유               | 긍정 태그만 있어 불만을 고를 수 없음                                                |
| 평점 배지     | 표시      | 목록 카드의 평균 한 줄(「4.3 (128)」)     | 평가 수 없이 평균만                                                                 |

- 평균만으로는 평가 2개짜리 5.0과 2,000개짜리 4.6을 구분할 수 없다. Baymard 조사에서 사용자는 평균이 조금 낮아도 평가가 많은 상품을 골랐고, 개별 후기보다 평점 분포 요약에 더 기댔다.
- NPS는 서비스 전체에 대한 관계를 가끔 묻는 지표다. 화면 하나·과업 하나의 만족은 별점이나 좋아요·싫어요로 묻고, 지표 정의는 `ux-metrics`를 따른다.
- 대가를 받은 후기가 섞이면 `ux-dark-patterns`의 광고 구분 표시를 따른다.

## 9. 공유 아이콘

공유 아이콘은 무엇을 어디로 보내는지에 따라 모양이 다르고, 같은 「공유」도 플랫폼마다 모양이 다르다. 설계서에는 기능 이름을 쓴다.

| 모양                           | 기능 → 설계서에 쓸 이름                                                        | 아이콘 이름                                                     |
| ------------------------------ | ------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| 위로 나가는 화살표가 달린 상자 | 공유(iOS) — 시스템 공유 시트 열기                                              | SF Symbols `square.and.arrow.up` · Material Symbols `ios_share` |
| 선으로 이어진 점 셋            | 공유(Android) — 시스템 공유 시트 열기                                          | `share`                                                         |
| 꺾인 화살표                    | 전달 — 받은 메시지를 다른 사람에게                                             | `forward`                                                       |
| 종이비행기                     | 보내기 — 메시지로                                                              | `send`                                                          |
| 사슬 고리                      | 링크 복사                                                                      | `link`                                                          |
| 맞물린 화살표 둘               | 리포스트 — 내 피드에 다시 올리기                                               | `repeat`                                                        |
| QR 코드                        | QR 공유 — 코드로 열게 하기                                                     | `qr_code`                                                       |
| 주변 기기                      | 근처 공유 — 가까운 기기로, 플랫폼 기능 이름(AirDrop·Quick Share)을 그대로 쓴다 | —                                                               |
| 보낼 곳 목록                   | 공유 시트 — 보낼 곳 고르기                                                     | Apple Activity view · Android Sharesheet                        |

- iOS와 Android를 함께 만드는 앱은 공유 아이콘을 플랫폼마다 그 플랫폼의 모양으로 쓴다. 한쪽 모양으로 맞추면 다른 쪽 사용자에게는 낯선 아이콘이 된다.
- 앱 안에 보낼 곳 목록을 따로 만들지 않고 시스템 공유 시트를 연다. Android 개발자 문서는 앱 고유의 공유 대상 목록이나 변형 시트를 만들지 말라고 한다.
- 아이콘만 있는 공유 버튼의 접근 가능한 이름은 기능으로 쓴다(「공유」, 「링크 복사」).

## 10. 화면 전환

「자연스럽게 넘어가게」는 설계서가 아니다. 전환은 두 화면의 관계를 말하므로 관계로 이름을 고른다. 시간과 곡선은 `ux-review` 패턴 쓰임 대조표 4절을 따른다.

| 이름        | 두 화면의 관계                                           | 모습                       | Material 모션 이름      |
| ----------- | -------------------------------------------------------- | -------------------------- | ----------------------- |
| 푸시        | 위계 한 단계 아래 — 뒤로 가기로 돌아온다                 | 옆에서 밀고 들어옴         | 공유 축(앞뒤)           |
| 모달 등장   | 하던 흐름과 떨어진 과제 — 닫기·완료로 끝낸다             | 아래에서 올라와 덮음       | —                       |
| 페이드 스루 | 관계가 약한 최상위 목적지 사이(하단 탭)                  | 사라진 뒤 새 화면이 나타남 | 페이드 스루(최상위)     |
| 공유 요소   | 두 화면에 같은 사진·제목이 이어짐                        | 그 요소만 자리를 옮김      | —                       |
| 카드 확장   | 목록 항목이 그 항목의 상세가 됨                          | 카드가 커져 화면이 됨      | 컨테이너 변환           |
| 줌          | 작은 미리보기가 그 내용 전체가 됨                        | 확대되며 들어감            | —                       |
| 순차 등장   | 한 화면에 여러 항목이 처음 나타남                        | 항목이 시차를 두고 나타남  | —                       |
| 탭 전환     | 같은 층위의 보기 사이                                    | 옆으로 바뀜                | 공유 축(좌우)           |
| 시트 확장   | 바텀시트가 더 많은 내용을 보여 줌                        | 시트가 위로 늘어남         | —                       |
| 페이드      | 화면 안에서 요소가 나타나고 사라짐(대화상자·메뉴·스낵바) | 서서히 나타나고 사라짐     | 페이드(들어오고 나가기) |

- 하단 탭 목적지 사이를 푸시로 넘기면 위계가 있는 것처럼 보여 뒤로 가기가 어디로 갈지 헷갈린다. 페이드 스루를 쓴다.
- 위계 아래로 들어가는 화면을 모달 등장으로 띄우면 닫기와 뒤로 가기가 섞인다.
- 순차 등장은 처음 한 번, 몇 개 항목에만 쓴다. 스크롤할 때마다 반복하면 내용보다 움직임을 기다리게 된다.
- 모든 전환은 움직임 줄이기 설정(`prefers-reduced-motion`)에서 페이드나 즉시 전환으로 바꾼다.

## 11. 시각 스타일 이름 — AI에게 화면을 그리게 할 때

「예쁘게」는 읽는 사람이나 AI마다 다른 화면이 된다. 스타일을 정할 때는 이름을 쓰고, 그 스타일이 먼저 깨뜨리는 접근성 기준을 함께 적는다. 스타일 이름은 겉모습만 바꾼다 — 컴포넌트·상태·문구는 이 설계서가 정한다.

| 이름          | 알아보는 표시                                   | 먼저 볼 접근성 기준                                                                          |
| ------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 플랫          | 그림자·질감 없는 단색 면                        | 누를 수 있는 것이 구분되나 — 단서가 약한 화면에서 찾는 시간이 22% 길었다(NN/g 2017) · 1.4.11 |
| 스큐어모피즘  | 실물의 질감·그림자를 흉내                       | 질감 위 글자 대비(1.4.3)                                                                     |
| 뉴모피즘      | 배경과 같은 색 위의 부드러운 볼록·오목 그림자   | 경계가 그림자뿐이면 비텍스트 대비(1.4.11)를 놓치기 쉽다                                      |
| 글래스모피즘  | 반투명 유리 면, 뒤 배경 흐림                    | 배경 따라 바뀌는 글자 대비 — 렌더 픽셀로 잰다(`ux-a11y`), 투명도 줄이기 설정                 |
| 클레이모피즘  | 점토처럼 둥글게 부푼 입체, 파스텔               | 파스텔 위 글자 대비, 요소 경계 대비                                                          |
| 머티리얼      | Material Design의 면·높이·컴포넌트              | 기본 컴포넌트의 대비·대상 크기를 바꾸지 않았나                                               |
| 브루탈리즘    | 굵은 테두리, 원색, 날것의 배치                  | 원색 조합의 대비, 읽기 순서(1.3.2)                                                           |
| 벤토 그리드   | 크기가 다른 칸을 도시락처럼 배치                | 좁은 화면에서 한 줄로 다시 흐르나(1.4.10), 읽기 순서(1.3.2)                                  |
| 다크 모드     | 어두운 배경 테마                                | 두 테마 모두의 대비, 색만으로 말하는 상태(1.4.1)                                             |
| 리퀴드 글래스 | 주변을 비추고 굴절하는 반투명 재질(Apple, 2025) | 글래스모피즘과 같음, 투명도 줄이기 설정에서의 모습                                           |
| Y2K           | 크롬·홀로그램 그라데이션                        | 그라데이션 위 글자 대비 — 렌더 픽셀로 잰다                                                   |
| 미니멀        | 넓은 여백, 적은 요소                            | 아이콘만 있는 버튼의 이름(4.1.2), 연한 회색 글자 대비(1.4.3)                                 |

- AI에게 화면을 그리게 할 때는 스타일 이름 하나와 이 문서의 컴포넌트 이름·상태를 함께 준다. 스타일 이름만 바꾸면 겉모습만 달라지고 빠진 상태는 그대로 빠져 있다.
- 반투명 스타일은 가능하면 투명도 줄이기·대비 높이기 설정을 따르게 한다(NN/g Glassmorphism, 2024).
