# 컴포넌트 이름 대조표

설계서에는 왼쪽 열의 표준 이름을 쓴다. 팀의 디자인 시스템에 정해진 이름이 있으면 그 이름이 우선이고, 처음 등장할 때 괄호로 표준 이름을 붙인다.

출처: Google Material Design 3 컴포넌트 목록(2025 Expressive·2026 I/O 갱신 포함), Apple Human Interface Guidelines 컴포넌트 목록, 행정안전부 KRDS(Korea Design System) 컴포넌트 이름, The Component Gallery(component.gallery)의 별칭 정리, Material Symbols 아이콘 이름(google/material-design-icons 코드포인트 목록, 2026-11-03 확인). 5절의 위치 표시와 7절부터는 W3C WCAG 2.2(1.1.1·1.3.2·1.4.1·1.4.3·1.4.10·1.4.11·1.4.13·2.5.8·4.1.2), NN/g Angie Li「Dropdowns: Design Guidelines」(2017)·Kate Moran「Flat UI Elements Attract Less Attention and Cause Uncertainty」(2017)·Megan Brown「Glassmorphism: Definition and Best Practices」(2024), Material Components for Android 모션 문서의 전환 패턴 4가지, Apple HIG의 Page controls·Layout(홈 인디케이터와 안전 영역), SF Symbols, Android 개발자 문서「Send simple data to other apps」(Android Sharesheet), Baymard Institute의 별점 인식·평점 분포 요약 연구, NIST SP 800-63B(비밀번호 강도 안내), Fred Reichheld「The One Number You Need to Grow」(HBR, 2003), Apple의 Liquid Glass 발표(2025-06)를 더했다(2026-11-08 확인). 12절부터는 NN/g Angie Li「Date-Input Form Fields: UX Design Guidelines」(2017), Apple HIG의 Launching·Onboarding·Privacy(권한 요청), Material Design 3의 Date pickers·Time pickers·상태(States) 문서, WCAG 2.2(1.3.5·2.2.2·2.3.3·2.4.7·2.5.1·2.5.7·3.3.7·4.1.3)를 더했다(2026-11-12 확인). 「—」는 해당 체계에 같은 이름의 컴포넌트가 없거나 확인하지 못했다는 뜻이다.

## 1. 이름이 겹치는 곳 — 먼저 확인한다

| 모달          | 성격(흐름을 막음)이지 컴포넌트가 아니다                                 | 대화상자, 모달 바텀시트, 전체 화면 대화상자   |

## 5. 로딩·진행·위치 표시

| 점진적 이미지     | 이미지 블러 로딩       | —                                          | —                               |
| 페이지 인디케이터 | 페이지 점              | —                                          | Page control                    |
| 스토리 진행 바    | 조각 진행 바           | —                                          | —                               |
| 스크롤 진행 바    | 읽기 진행 바           | —                                          | —                               |
| 강도 표시기       | 비밀번호 강도          | —                                          | —                               |
| 탭 인디케이터     | 선택 밑줄              | Tabs의 활성 표시(active indicator)         | —                               |
| 홈 인디케이터     | 하단 가로 막대         | —                                          | Home indicator(시스템이 그린다) |

- 진행 바는 일이 얼마나 끝났는지, 단계 표시(4절)는 흐름의 몇 번째 단계인지, 페이지 인디케이터는 넘겨 보는 화면 몇 장 중 어디인지를 말한다. 순서 없이 오가는 화면에는 페이지 인디케이터를 쓰지 않는다.
- 강도 표시기는 색만으로 말하지 않고 기준을 글로 함께 보인다(「8자 이상이면 충분해요」 — WCAG 1.4.1). 비밀번호를 정할 때 강도 안내를 주는 것은 NIST SP 800-63B가 권한다.
- 낙관적 업데이트는 컴포넌트가 아니라 동작이다. 서버 응답을 기다리지 않고 결과를 먼저 보여 주므로, 설계서에는 실패했을 때 되돌리는 모습과 알리는 문구를 함께 적는다. 결제·삭제처럼 되돌릴 수 없는 일에는 쓰지 않는다.
- 상단 로딩 바는 화면 전체가 바뀌는 이동에 쓴다. 한 영역만 기다릴 때는 그 영역 안의 스피너나 스켈레톤을 쓴다.
- 홈 인디케이터는 앱이 그리지 않는다. 그 가까이에 누르는 요소나 끄는 제스처를 두지 않고, 화면 폭 하단 버튼은 안전 영역의 아래 끝에 맞춘다(Apple HIG Layout).

## 6. 아이콘만 있는 메뉴 버튼

모양에 붙은 별명은 기능 이름이 아니다. 설계서에는 기능으로 쓴 표준 이름을 적고 모양은 괄호에 별명으로 붙인다(예: 더 보기 메뉴(케밥)). 팀 밖에서도 통하는 별명은 햄버거·케밥 정도다.

| 모양                    | 별명      | 흔한 기능 → 설계서에 쓸 이름                  | Material Symbols |
| ----------------------- | --------- | --------------------------------------------- | ---------------- |
| 가로줄 셋               | 햄버거    | 내비게이션 드로어 열기                        | `menu`           |
| 세로 점 셋              | 케밥      | 더 보기 메뉴                                  | `more_vert`      |
| 가로 점 셋              | 미트볼    | 더 보기 메뉴                                  | `more_horiz`     |
| 점 아홉(3×3)            | 와플      | 앱 전환·서비스 모음                           | —                |
| 네모 아홉(3×3)          | 벤토      | 앱 전환·서비스 모음                           | `apps`           |
| 가운데로 짧아지는 줄 셋 | 도너      | 필터                                          | `filter_list`    |
| 가로줄 둘               | 베지 버거 | 메뉴, 또는 끌어서 옮기는 손잡이 — 뜻이 갈린다 | `drag_handle`    |
| 왼쪽 정렬로 짧아지는 줄 | 계단      | 정렬                                          | `sort`           |
| 손잡이가 달린 줄        | 슬라이더  | 필터·세부 조정                                | `tune`           |

- 아이콘만 있는 버튼에는 기능을 말하는 접근 가능한 이름을 단다(「더 보기」, 「필터」 — WCAG 4.1.2). 「케밥」, 「메뉴 아이콘」은 이름이 아니다.
- 한 제품 안에서 같은 기능에 케밥과 미트볼을 섞어 쓰지 않는다.
- 주요 메뉴를 햄버거 뒤에 숨기기로 했으면 설계서에 이유를 적는다. 숨긴 메뉴는 덜 쓰이고 찾는 데 오래 걸린다(`ux-review`의 패턴 쓰임 대조표 4절).

## 7. 닮은 짝 가르기

생김새가 비슷해도 하는 일이 다르면 다른 컴포넌트다. 구분하는 질문에 답한 쪽의 이름을 설계서에 쓴다. 잘못 고르면 사용자가 누른 뒤의 결과를 잘못 예상한다. 쓰임 판정은 `ux-review`의 패턴 쓰임 대조표가 맡는다.

| 짝                             | 구분하는 질문                            | 답 → 이름                                                                          | 섞어 쓰면                                                                                             |
| ------------------------------ | ---------------------------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 스위치 · 체크박스              | 누르는 순간 반영되나                     | 즉시 → 스위치 · 저장해야 반영 → 체크박스                                           | 저장 버튼이 있는 폼의 스위치                                                                          |
| 라디오 버튼 · 체크박스         | 하나만 고르나                            | 하나 → 라디오 · 여러 개 → 체크박스                                                 | 하나만 골라야 하는데 체크박스                                                                         |
| 상단 탭 · 세그먼트 컨트롤      | 다른 내용 묶음으로 이동하나              | 내용 묶음 이동 → 탭 · 같은 내용의 보기·조건 바꾸기 → 세그먼트                      | 세그먼트에 실행 동작                                                                                  |
| 대화상자 · 바텀시트            | 답해야 진행하나                          | 결정 강요 → 대화상자 · 지금 화면을 둔 채 하나 고르기 → 바텀시트                    | 행동 목록을 가운데 대화상자로 띄움                                                                    |
| 토스트 · 스낵바                | 되돌릴 행동이 있나                       | 결과만 → 토스트 · 행동 하나 → 스낵바                                               | 토스트에 버튼 · 행동 있는 스낵바가 저절로 사라짐                                                      |
| 툴팁 · 팝오버                  | 안에서 누를 것이 있나                    | 짧은 글자만, 가리키거나 포커스할 때 → 툴팁 · 링크·버튼을 담고 눌러서 연다 → 팝오버 | 툴팁 안에 링크 · 포인터를 이동하면 사라지는 팝오버 · 터치 화면에서 툴팁에만 둔 필수 정보(WCAG 1.4.13) |
| 칩 · 뱃지                      | 누를 수 있나                             | 고르기·거르기·입력 → 칩 · 상태·개수 표시만 → 뱃지                                  | 칩 모양인데 눌리지 않음                                                                               |
| 스피너 · 스켈레톤              | 나올 내용의 배치를 아나                  | 모름·한 영역 → 스피너 · 배치가 정해진 화면 → 스켈레톤                              | 패턴 쓰임 대조표 2절                                                                                  |
| 수량 스테퍼 · 슬라이더         | 정확한 작은 수인가                       | 작은 정수 → 스테퍼 · 범위의 대략 값 → 슬라이더                                     | 큰 수를 ±로만 · 정확한 값을 슬라이더로만                                                              |
| 메뉴 · 셀렉트                  | 고른 값이 칸에 남나                      | 고르면 바로 실행(복사·삭제) → 메뉴 · 값이 남음(배송 방법) → 셀렉트                 | 명령을 셀렉트에 넣고 「적용」 버튼을 따로 둠                                                          |
| 버튼 · 링크                    | 일이 일어나나, 다른 곳으로 가나          | 실행 → 버튼(`button`) · 이동 → 링크(`a href`)                                      | 이동하는 버튼은 새 탭 열기·주소 복사가 안 되고, 화면 낭독기가 역할을 잘못 읽는다(WCAG 4.1.2)          |
| 플레이스홀더 · 라벨            | 입력하면 사라지나                        | 예시, 사라짐 → 플레이스홀더 · 칸 이름, 늘 보임 → 라벨                              | 라벨 없이 플레이스홀더만                                                                              |
| 햄버거 · 케밥                  | 앱의 목적지인가, 이 화면·항목의 동작인가 | 목적지 → 내비게이션 드로어 열기 · 동작 → 더 보기 메뉴                              | 6절                                                                                                   |
| 상단 앱 바 · 하단 탭           | 이 화면의 제목·동작인가                  | 제목·동작 → 상단 앱 바 · 최상위 목적지 → 하단 탭                                   | 1절                                                                                                   |
| 카드 · 목록                    | 같은 형식을 훑어 비교하나                | 항목마다 모양·행동이 다름 → 카드 · 같은 형식을 빠르게 훑음 → 목록                  | 같은 형식의 긴 목록을 카드로 만들어 한 화면에 몇 개만 보임                                            |
| 아바타 · 썸네일                | 사람인가                                 | 사람·계정 → 아바타 · 글·영상·상품 → 썸네일                                         | 둘을 같은 모양으로 그려 누구의 것인지 헷갈림                                                          |
| 배너 · 팝업                    | 흐름을 막나                              | 화면 위 띠, 막지 않음 → 배너 · 화면을 가리고 답을 요구 → 대화상자                  | 패턴 쓰임 대조표 1절                                                                                  |
| 플로팅 액션 버튼 · 아이콘 버튼 | 이 화면의 가장 중요한 동작인가           | 주 동작 하나 → 플로팅 액션 버튼 · 보조 동작 → 아이콘 버튼                          | 한 화면에 플로팅 액션 버튼 여럿 · 삭제를 플로팅 액션 버튼으로                                         |

## 8. 평가·후기

「별점 넣어 주세요」로는 아홉 가지 중 무엇인지 모른다. 사용자에게 무엇을 묻는지(입력) 또는 무엇을 보여 주는지(표시)를 먼저 적는다.

| 이름          | 입력·표시 | 묻는 것·보여 주는 것                      | 이렇게 쓰면 finding                                                                 |
| ------------- | --------- | ----------------------------------------- | ----------------------------------------------------------------------------------- |
| 별점          | 입력·표시 | 1\~5점 만족                               | 점수마다 뜻(「별로예요」\~「최고예요」)이 없음                                      |
| 반 별점       | 표시      | 평균을 0.5 단위로                         | 입력에서 반 칸을 고르게 해 누를 자리가 작아짐(WCAG 2.5.8) — 입력은 온 칸으로 받는다 |
| NPS 점수      | 입력      | 0\~10, 이 서비스를 추천할 의향(관계 지표) | 과업이 끝날 때마다 물음 · 1\~5 별점을 NPS라고 부름                                  |
| 이모지 평가   | 입력      | 3\~5단계 기분                             | 얼굴마다 글자 이름이 없음(WCAG 1.1.1)                                               |
| 좋아요·싫어요 | 입력      | 도움이 됐나, 둘 중 하나                   | 싫어요 뒤에 이유를 고를 수 없음(`ux-ai`의 피드백 + 이유)                            |
| 평점 슬라이더 | 입력      | 넓은 범위의 점수                          | 현재 값이 숫자로 안 보임 · 정확한 값을 슬라이더로만 받음                            |
| 평점 요약     | 표시      | 평균 · 평가 수 · 점수별 분포 막대         | 평가 수나 분포 없이 평균만 · 분포 막대를 눌러 그 점수의 후기로 갈 수 없음           |
| 평가 태그     | 입력·표시 | 「빠른 배송」처럼 고른 이유               | 긍정 태그만 있어 불만을 고를 수 없음                                                |
| 평점 배지     | 표시      | 목록 카드의 평균 한 줄(「4.3 (128)」)     | 평가 수 없이 평균만                                                                 |

- 평균만으로는 평가 2개짜리 5.0과 2,000개짜리 4.6을 구분할 수 없다. Baymard 조사에서 사용자는 평균이 조금 낮아도 평가가 많은 상품을 골랐고, 개별 후기보다 평점 분포 요약에 더 기댔다.
- NPS는 서비스 전체에 대한 관계를 가끔 묻는 지표다. 화면 하나·과업 하나의 만족은 별점이나 좋아요·싫어요로 묻고, 지표 정의는 `ux-metrics`를 따른다.
- 대가를 받은 후기가 섞이면 `ux-dark-patterns`의 광고 구분 표시를 따른다.

## 9. 공유 아이콘

공유 아이콘은 무엇을 어디로 보내는지에 따라 모양이 다르고, 같은 「공유」도 플랫폼마다 모양이 다르다. 설계서에는 기능 이름을 쓴다.

| 모양                           | 기능 → 설계서에 쓸 이름                                                        | 아이콘 이름                                                     |
| ------------------------------ | ------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| 위로 나가는 화살표가 달린 상자 | 공유(iOS) — 시스템 공유 시트 열기                                              | SF Symbols `square.and.arrow.up` · Material Symbols `ios_share` |
| 선으로 이어진 점 셋            | 공유(Android) — 시스템 공유 시트 열기                                          | `share`                                                         |
| 꺾인 화살표                    | 전달 — 받은 메시지를 다른 사람에게                                             | `forward`                                                       |
| 종이비행기                     | 보내기 — 메시지로                                                              | `send`                                                          |
| 사슬 고리                      | 링크 복사                                                                      | `link`                                                          |
| 맞물린 화살표 둘               | 리포스트 — 내 피드에 다시 올리기                                               | `repeat`                                                        |
| QR 코드                        | QR 공유 — 코드로 열게 하기                                                     | `qr_code`                                                       |
| 주변 기기                      | 근처 공유 — 가까운 기기로, 플랫폼 기능 이름(AirDrop·Quick Share)을 그대로 쓴다 | —                                                               |
| 보낼 곳 목록                   | 공유 시트 — 보낼 곳 고르기                                                     | Apple Activity view · Android Sharesheet                        |

- iOS와 Android를 함께 만드는 앱은 공유 아이콘을 플랫폼마다 그 플랫폼의 모양으로 쓴다. 한쪽 모양으로 맞추면 다른 쪽 사용자에게는 낯선 아이콘이 된다.
- 앱 안에 보낼 곳 목록을 따로 만들지 않고 시스템 공유 시트를 연다. Android 개발자 문서는 앱 고유의 공유 대상 목록이나 변형 시트를 만들지 말라고 한다.
- 아이콘만 있는 공유 버튼의 접근 가능한 이름은 기능으로 쓴다(「공유」, 「링크 복사」).

## 10. 화면 전환

「자연스럽게 넘어가게」는 설계서가 아니다. 전환은 두 화면의 관계를 말하므로 관계로 이름을 고른다. 시간과 곡선은 `ux-review` 패턴 쓰임 대조표 4절을 따른다.

| 이름        | 두 화면의 관계                                           | 모습                       | Material 모션 이름      |
| ----------- | -------------------------------------------------------- | -------------------------- | ----------------------- |
| 푸시        | 위계 한 단계 아래 — 뒤로 가기로 돌아온다                 | 옆에서 밀고 들어옴         | 공유 축(앞뒤)           |
| 모달 등장   | 하던 흐름과 떨어진 과제 — 닫기·완료로 끝낸다             | 아래에서 올라와 덮음       | —                       |
| 페이드 스루 | 관계가 약한 최상위 목적지 사이(하단 탭)                  | 사라진 뒤 새 화면이 나타남 | 페이드 스루(최상위)     |
| 공유 요소   | 두 화면에 같은 사진·제목이 이어짐                        | 그 요소만 자리를 이동함    | —                       |
| 카드 확장   | 목록 항목이 그 항목의 상세가 됨                          | 카드가 커져 화면이 됨      | 컨테이너 변환           |
| 줌          | 작은 미리보기가 그 내용 전체가 됨                        | 확대되며 들어감            | —                       |
| 순차 등장   | 한 화면에 여러 항목이 처음 나타남                        | 항목이 시차를 두고 나타남  | —                       |
| 탭 전환     | 같은 수준의 보기 사이                                    | 옆으로 바뀜                | 공유 축(좌우)           |
| 시트 확장   | 바텀시트가 더 많은 내용을 보여 줌                        | 시트가 위로 늘어남         | —                       |
| 페이드      | 화면 안에서 요소가 나타나고 사라짐(대화상자·메뉴·스낵바) | 서서히 나타나고 사라짐     | 페이드(들어오고 나가기) |

- 하단 탭 목적지 사이를 푸시로 넘기면 위계가 있는 것처럼 보여 뒤로 가기가 어디로 갈지 헷갈린다. 페이드 스루를 쓴다.
- 위계 아래로 들어가는 화면을 모달 등장으로 띄우면 닫기와 뒤로 가기가 섞인다.
- 순차 등장은 처음 한 번, 몇 개 항목에만 쓴다. 스크롤할 때마다 반복하면 내용보다 움직임을 기다리게 된다.
- 모든 전환은 움직임 줄이기 설정(`prefers-reduced-motion`)에서 페이드나 즉시 전환으로 바꾼다.

## 11. 시각 스타일 이름 — AI에게 화면을 그리게 할 때

「예쁘게」는 읽는 사람이나 AI마다 다른 화면이 된다. 스타일을 정할 때는 이름을 쓰고, 그 스타일이 먼저 깨뜨리는 접근성 기준을 함께 적는다. 스타일 이름은 겉모습만 바꾼다 — 컴포넌트·상태·문구는 이 설계서가 정한다.

| 이름          | 알아보는 표시                                   | 먼저 볼 접근성 기준                                                                          |
| ------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 플랫          | 그림자·질감 없는 단색 면                        | 누를 수 있는 것이 구분되나 — 단서가 약한 화면에서 찾는 시간이 22% 길었다(NN/g 2017) · 1.4.11 |
| 스큐어모피즘  | 실물의 질감·그림자를 흉내                       | 질감 위 글자 대비(1.4.3)                                                                     |
| 뉴모피즘      | 배경과 같은 색 위의 부드러운 볼록·오목 그림자   | 경계가 그림자뿐이면 비텍스트 대비(1.4.11)를 놓치기 쉽다                                      |
| 글래스모피즘  | 반투명 유리 면, 뒤 배경 흐림                    | 배경 따라 바뀌는 글자 대비 — 렌더 픽셀로 잰다(`ux-a11y`), 투명도 줄이기 설정                 |
| 클레이모피즘  | 점토처럼 둥글게 부푼 입체, 파스텔               | 파스텔 위 글자 대비, 요소 경계 대비                                                          |
| 머티리얼      | Material Design의 면·높이·컴포넌트              | 기본 컴포넌트의 대비·대상 크기를 바꾸지 않았나                                               |
| 브루탈리즘    | 굵은 테두리, 원색, 날것의 배치                  | 원색 조합의 대비, 읽기 순서(1.3.2)                                                           |
| 벤토 그리드   | 크기가 다른 칸을 도시락처럼 배치                | 좁은 화면에서 한 줄로 다시 흐르나(1.4.10), 읽기 순서(1.3.2)                                  |
| 다크 모드     | 어두운 배경 테마                                | 두 테마 모두의 대비, 색만으로 말하는 상태(1.4.1)                                             |
| 리퀴드 글래스 | 주변을 비추고 굴절하는 반투명 재질(Apple, 2025) | 글래스모피즘과 같음, 투명도 줄이기 설정에서 보이는 모습                                      |
| Y2K           | 크롬·홀로그램 그라데이션                        | 그라데이션 위 글자 대비 — 렌더 픽셀로 잰다                                                   |
| 미니멀        | 넓은 여백, 적은 요소                            | 아이콘만 있는 버튼의 이름(4.1.2), 연한 회색 글자 대비(1.4.3)                                 |

- AI에게 화면을 그리게 할 때는 스타일 이름 하나와 이 문서의 컴포넌트 이름·상태를 함께 준다. 스타일 이름만 바꾸면 겉모습만 달라지고 빠진 상태는 그대로 빠져 있다.
- 반투명 스타일은 가능하면 투명도 줄이기·대비 높이기 설정을 따르게 한다(NN/g Glassmorphism, 2024).

## 12. 화면 배치

「깔끔하게 배치해 줘」는 그릴 때마다 다른 화면이 된다. 배치에도 이름이 있다. 영역마다 배치 이름과 열 수를 적고(「맨 위 히어로, 그 아래 카드 그리드 3열」), 좁은 화면에서 어떻게 바뀌는지를 함께 적는다.

| 이름          | 모습                                       | 맞는 내용                      | 좁은 화면에서 먼저 볼 것                            |
| ------------- | ------------------------------------------ | ------------------------------ | --------------------------------------------------- |
| 히어로        | 화면 맨 위의 큰 제목·한 줄 설명·주 버튼    | 랜딩·홈의 첫 메시지 하나       | 주 버튼이 첫 화면 안에 보이나                       |
| 벤토 그리드   | 크기가 다른 칸을 격자에 맞춰 채움          | 무게가 다른 기능·지표 소개     | 한 줄로 다시 흐르나(1.4.10), 읽기 순서(1.3.2)       |
| 스플릿        | 화면을 좌우 둘로 나눔                      | 글과 그림, 폼과 설명           | 위아래로 쌓일 때 어느 쪽이 먼저 오나                |
| 카드 그리드   | 같은 크기의 카드를 열 맞춰 반복            | 상품·글 목록 훑어보기          | 열 수가 줄어도 카드 안 글자가 잘리지 않나           |
| 사이드바 배치 | 옆의 고정 메뉴와 본문                      | 메뉴가 많은 업무 도구·설정     | 메뉴가 드로어나 하단 탭으로 바뀌나                  |
| 매거진        | 큰 기사 하나와 작은 기사 여럿, 크기로 위계 | 읽을거리 모음                  | 큰 기사와 작은 기사의 순서가 유지되나               |
| 대시보드      | 지표 카드·차트·표를 한 화면에              | 상태를 한눈에 확인             | 가장 중요한 지표가 맨 위에 오나, 표가 가로로 넘치나 |
| Z 패턴        | 글과 그림을 줄마다 좌우로 번갈아 둠        | 기능을 차례로 설명하는 긴 화면 | 쌓일 때 글과 그림의 짝이 떨어지지 않나              |
| 풀블리드      | 사진·영상이 화면 폭을 끝까지 채움          | 분위기를 먼저 전하는 첫 화면   | 사진 위 글자의 대비(1.4.3) — 렌더 픽셀로 잰다       |

- 배치 이름은 뼈대만 정한다. 칸 안의 컴포넌트와 상태는 2\~8절의 이름으로 따로 적는다.
- 벤토 그리드는 11절에서는 스타일 이름으로도 쓰인다. 설계서에는 배치로 적고 칸마다 내용의 우선순위를 붙인다.

## 13. 날짜·시간 고르기

「날짜 고르게 해 줘」는 대개 달력이 된다. 고를 날짜가 오늘에서 얼마나 먼지, 하루인지 기간인지, 고를 수 있는 값이 정해져 있는지로 이름을 고른다.

| 이름            | 맞는 경우                                            | 이렇게 쓰면 finding                                      |
| --------------- | ---------------------------------------------------- | -------------------------------------------------------- |
| 캘린더          | 오늘에서 가까운 하루(예약일·배송일)                  | 생년월일을 달력으로 받아 달을 수십 번 넘기게 함          |
| 휠 피커         | 값이 차례로 이어지는 짧은 범위(시·분)                | 긴 범위를 휠로만 고르게 함 · 직접 입력할 길이 없음       |
| 날짜 입력       | 생년월일처럼 먼 날짜, 이미 외우고 있는 날짜          | 형식 예시가 없음 · 구분자나 앞자리 0이 다르다고 거절함   |
| 기간 선택       | 시작일과 종료일을 한 번에(조회 기간)                 | 시작보다 앞선 종료일을 고를 수 있음                      |
| 체크인 체크아웃 | 숙박·대여처럼 두 날짜가 한 쌍                        | 두 번째 날짜를 고를 때 보이는 달이 바뀌어 다른 날을 누름 |
| 빠른 선택 칩    | 「오늘」·「이번 주」·「최근 3개월」처럼 자주 쓰는 값 | 칩만 있고 직접 고를 길이 없음                            |
| 시간 슬롯       | 고를 수 있는 시간이 정해져 있음(예약)                | 마감된 시간을 숨겨서 빈 시간이 왜 적은지 알 수 없음      |
| 월 선택         | 날짜 없이 달만(명세서·통계)                          | 달만 필요한데 날짜까지 고르게 함                         |
| 반복 설정       | 매일·매주·매월 되풀이                                | 끝나는 날을 정할 수 없음 · 다음 실행일이 보이지 않음     |

- 달력은 오늘에서 1년 안쪽의 날짜에 맞는다. 생년월일처럼 먼 날짜는 직접 입력이 빠르고, 다른 방식을 주더라도 입력을 함께 허용한다(NN/g 2017).
- 고를 수 없는 날짜는 숨기지 않고 비활성으로 보인다. 숨기면 달력의 요일 줄이 어긋나 다른 날을 누른다.
- 「10/11」은 나라에 따라 10월 11일과 11월 10일로 읽힌다. 여러 나라에서 쓰는 화면은 달 이름을 글자로 쓴다.
- 생년월일 칸에는 자동 완성 속성(`bday`)을 달고(WCAG 1.3.5), 같은 흐름에서 이미 받은 날짜는 다시 묻지 않는다(3.3.7).

## 14. 앱을 처음 켤 때 지나가는 화면

「첫 화면 고쳐 주세요」는 아래 아홉 가지 중 무엇인지 알 수 없다. 이름으로 지정하고, 화면마다 건너뛸 수 있는지와 두 번째 실행부터 보이는지를 적는다.

| 이름        | 하는 일                                 | 이렇게 쓰면 finding                                             |
| ----------- | --------------------------------------- | --------------------------------------------------------------- |
| 스플래시    | 앱이 뜨는 동안 잠깐 보이는 화면         | 준비가 끝났는데도 로고를 몇 초 더 보여 줌 · 광고를 넣음         |
| 온보딩      | 넘기면서 앱이 하는 일을 소개            | 건너뛰기가 없음 · 써 보기 전에 기능 설명을 다섯 장 넘기게 함    |
| 권한 요청   | 위치·알림·카메라 접근을 물음            | 첫 실행에 한꺼번에 물음 · 왜 필요한지 말하지 않음               |
| 코치마크    | 화면 위에 덮어 한 곳을 가리켜 줌        | 여러 개를 연달아 띄움 · 닫으면 다시 볼 길이 없음                |
| 간편 로그인 | 다른 서비스 계정으로 가입·로그인        | 둘러보기 전에 로그인을 요구함 · 이전에 쓴 방법을 알려 주지 않음 |
| 약관 동의   | 필수·선택 약관에 동의                   | 선택 항목을 미리 체크함 · 「전체 동의」에 선택 항목을 섞음      |
| 프로필 설정 | 닉네임·사진·관심사 입력                 | 지금 필요 없는 정보를 필수로 받음 · 나중에 하기가 없음          |
| 스켈레톤    | 첫 내용을 불러오는 동안의 자리 표시     | 실제 배치와 다른 모양 — 내용이 뜰 때 화면이 밀림                |
| 웰컴 화면   | 가입을 마쳤음을 알리고 첫 행동으로 안내 | 다음 행동 없이 축하만 함                                        |

- 스플래시는 첫 화면과 비슷한 모습으로 두고 브랜드 홍보에 쓰지 않는다. 권한은 그 기능을 쓰려는 순간에 묻는다(Apple HIG).
- 약관 동의의 기본값과 「전체 동의」 구성은 `ux-dark-patterns`가 판정한다. 가입 흐름 전체의 단계 수와 순서는 `ux-flow`가 맡는다.
- 아홉 가지를 모두 넣을 필요는 없다. 화면마다 「없으면 사용자가 무엇을 못 하나」에 답이 없으면 뺀다.

## 15. 상태 이름 — 버튼

상태를 적지 않고 맡기면 기본 상태만 나오고, 눌러도 반응이 없는 버튼이 된다. 설계서에는 그 컴포넌트에 적용되는 상태를 아래 이름으로 빠짐없이 적는다.

| 상태   | 영문     | 언제                                   | 적을 것                                                       |
| ------ | -------- | -------------------------------------- | ------------------------------------------------------------- |
| 기본   | Default  | 아무 일도 없을 때                      | 색·글자·크기                                                  |
| 호버   | Hover    | 포인터를 올렸을 때(마우스가 있는 기기) | 터치 화면에는 없다 — 호버에만 있는 정보를 두지 않는다         |
| 눌림   | Pressed  | 누르고 있는 동안                       | 눌렸다는 표시가 바로 보이나                                   |
| 포커스 | Focus    | 키보드로 이동했을 때                   | 포커스 표시가 보이나(WCAG 2.4.7)                              |
| 비활성 | Disabled | 지금은 누를 수 없을 때                 | 왜 누를 수 없는지 가까이에 글로 적었나                        |
| 로딩   | Loading  | 누른 뒤 처리 중                        | 두 번 눌러도 한 번만 처리되나 · 버튼 폭이 바뀌지 않나         |
| 성공   | Success  | 처리가 끝났을 때                       | 화면 낭독기에도 알리나(4.1.3) · 언제 기본으로 돌아가나        |
| 오류   | Error    | 처리가 실패했을 때                     | 이유와 다시 시도하는 방법이 보이나                            |
| 선택됨 | Selected | 켜진 상태를 유지할 때(토글 버튼·칩)    | 색만으로 구분하지 않나(1.4.1) · 상태를 속성으로 알리나(4.1.2) |

- 모든 버튼에 아홉 가지가 다 필요하지는 않다. 이동만 하는 버튼에는 로딩·성공·오류가 없다. 해당 없는 상태는 「없음」으로 적어 빠뜨린 것과 구분한다.
- 텍스트 필드·카드·목록 항목도 같은 이름을 쓴다. 텍스트 필드에는 입력 중·입력됨·읽기 전용이 더 있다.

## 16. 글자가 나타나는 방식

글자에 움직임을 줄 때도 「멋지게」가 아니라 이름으로 적는다. 글자 움직임은 읽기를 늦추므로, 쓰는 자리를 정하고 움직임 줄이기 설정에서 보이는 모습을 함께 적는다.

| 이름           | 영문           | 모습                          | 맞는 자리                           |
| -------------- | -------------- | ----------------------------- | ----------------------------------- |
| 타이핑         | Typewriter     | 한 글자씩 쳐짐                | AI 응답이 실제로 이어져 올 때       |
| 페이드 업      | Fade up        | 아래에서 떠오르며 나타남      | 구역 제목이 처음 보일 때            |
| 글자 순차 등장 | Letter stagger | 글자가 하나씩 차례로 나타남   | 짧은 제목 한 줄                     |
| 카운트 업      | Count up       | 숫자가 0에서 값까지 올라감    | 한 화면의 대표 지표 한두 개         |
| 스크램블       | Scramble       | 섞인 글자가 맞춰짐            | 장식 제목 — 정보 글자에는 쓰지 않음 |
| 마스크 리빌    | Mask reveal    | 가려져 있다가 한쪽부터 드러남 | 큰 제목                             |
| 하이라이트     | Highlight      | 글자 뒤에 형광펜이 그어짐     | 문장에서 강조할 한 구절             |
| 단어 교체      | Word rotate    | 한 단어만 차례로 바뀜         | 제목 속 바뀌는 낱말 하나            |
| 블러 인        | Blur in        | 흐릿하다가 뚜렷해짐           | 큰 제목                             |

- 본문·오류·가격처럼 바로 읽어야 하는 글자에는 쓰지 않는다. 금액을 카운트 업으로 보이면 끝날 때까지 값을 읽을 수 없다.
- 5초 넘게 저절로 움직이는 글자(단어 교체)는 멈출 수 있어야 한다(WCAG 2.2.2).
- 화면 낭독기에는 움직임이 끝난 최종 글자를 한 번만 읽힌다. 타이핑·카운트 업이 글자마다 읽히지 않게 한다.
- 움직임 줄이기 설정에서는 최종 글자를 바로 보인다(2.3.3).

## 17. 제스처

제스처는 화면에 보이지 않는다. 설계서에는 제스처 이름과 결과를 적고, 같은 일을 하는 보이는 컨트롤을 함께 적는다.

| 이름              | 영문            | 흔한 결과                | 함께 둘 보이는 길                  |
| ----------------- | --------------- | ------------------------ | ---------------------------------- |
| 탭                | Tap             | 고르기·실행              | —                                  |
| 두 번 탭          | Double tap      | 좋아요 · 확대            | 좋아요 버튼 · 확대 버튼            |
| 길게 누르기       | Long press      | 그 항목의 메뉴 열기      | 더 보기 메뉴 버튼                  |
| 스와이프          | Swipe           | 옆 화면·다음 카드로 넘김 | 페이지 인디케이터 · 이전·다음 버튼 |
| 밀어서 삭제       | Swipe to delete | 목록 항목 삭제·보관      | 편집 모드나 항목 메뉴의 삭제       |
| 드래그            | Drag            | 순서 바꾸기 · 이동       | 위로·아래로 이동 버튼              |
| 핀치              | Pinch           | 확대·축소                | 확대·축소 버튼                     |
| 당겨서 새로고침   | Pull to refresh | 목록 새로 불러오기       | 새로고침 버튼 또는 자동 갱신       |
| 가장자리 스와이프 | Edge swipe      | 뒤로 가기                | 뒤로 가기 버튼                     |

- 경로를 그리거나 손가락 둘을 쓰는 제스처에는 한 손가락으로 누르는 대체 수단을 둔다(WCAG 2.5.1). 드래그에도 누르기만으로 되는 길을 둔다(2.5.7).
- 가장자리 스와이프는 시스템이 쓴다. 화면 가장자리에서 시작하는 가로 캐러셀이나 드로어를 두면 뒤로 가기와 부딪힌다.
- 밀어서 삭제는 스낵바의 되돌리기와 함께 쓴다.

## 18. 생김새로 이름 찾기

이름이 떠오르지 않으면 생김새나 하는 일로 찾는다. 요청에 왼쪽 열의 말이 있으면 오른쪽 이름으로 바꿔 적고, 닮은 짝이 있으면 7절의 질문으로 한 번 더 구분한다.

| 생김새·하는 일                           | 이름                         |
| ---------------------------------------- | ---------------------------- |
| 아래에서 올라오는 창                     | 바텀시트                     |
| 화면 가운데 뜨는 창                      | 대화상자                     |
| 잠깐 떴다 사라지는 한 줄                 | 토스트(버튼이 있으면 스낵바) |
| 화면 위에 계속 떠 있는 띠                | 배너                         |
| 칸 바로 아래의 빨간 글자                 | 인라인 오류                  |
| 올리면 뜨는 작은 설명                    | 툴팁                         |
| 화면을 어둡게 하고 한 곳을 가리키는 안내 | 코치마크                     |
| 아이콘 위의 빨간 숫자·점                 | 뱃지                         |
| 빙글빙글 도는 동그라미                   | 스피너                       |
| 깜빡이는 회색 박스                       | 스켈레톤                     |
| 채워지는 막대 · 채워지는 원              | 진행 바 · 진행 링            |
| 페이지가 바뀔 때 맨 위의 얇은 줄         | 상단 로딩 바                 |
| 흐릿하다가 또렷해지는 사진               | 점진적 이미지                |
| 켜고 끄는 것                             | 스위치                       |
| 둘셋 중 하나를 고르는 붙은 버튼          | 세그먼트 컨트롤              |
| 끌어서 조절하는 막대                     | 슬라이더                     |
| 플러스·마이너스로 개수 조절              | 수량 스테퍼                  |
| 누르면 펼쳐져 하나를 고르는 칸           | 셀렉트                       |
| 동그란 알약 모양의 고르는 버튼           | 칩                           |
| 화면 맨 아래의 메뉴 줄                   | 하단 탭                      |
| 옆에서 밀려 나오는 메뉴                  | 내비게이션 드로어            |
| 「홈 > 여행 > 일본」처럼 이어진 경로     | 브레드크럼                   |
| 스크롤해도 위에 붙어 있는 줄             | 고정 헤더                    |
| 화면 구석에 떠 있는 동그란 버튼          | 플로팅 액션 버튼             |
| 끝없이 이어 불러오는 목록                | 무한 스크롤                  |
| 점 세 개가 움직이는 대기 표시            | 생각 중 표시(`ux-ai`)        |
| 한 글자씩 이어지는 답                    | 스트리밍 응답(`ux-ai`)       |
| 답 아래의 엄지 둘                        | 좋아요·싫어요(8절)           |

뭉뚱그린 지시는 가장 흔한 화면을 낳는다. AI나 개발자에게 넘길 때는 이름·조건·시간까지 적는다.

| 뭉뚱그린 지시         | 이름으로 쓴 지시                                                        |
| --------------------- | ----------------------------------------------------------------------- |
| 로딩 넣어 줘          | 목록을 불러오는 동안 카드 모양 스켈레톤 3개를 보인다                    |
| 확인 창 띄워 줘       | 삭제 전에 바텀시트로 「삭제」·「취소」를 묻는다                         |
| 저장됐다고 알려 줘    | 저장하면 토스트를 2초 띄운다                                            |
| 틀리면 알려 줘        | 칸을 벗어날 때 그 칸 아래에 인라인 오류로 고치는 방법을 보인다          |
| 비밀번호 칸 만들어 줘 | 비밀번호 칸에 보기 전환 버튼과 강도 표시기를 붙이고 기준을 글로 적는다  |
| 날짜 고르게 해 줘     | 생년월일은 날짜 입력(YYYY-MM-DD)으로, 예약일은 캘린더로 받는다          |
| 버튼 만들어 줘        | 버튼을 기본·눌림·포커스·비활성·로딩 상태로 만든다                       |
| 깔끔하게 배치해 줘    | 맨 위는 히어로, 그 아래는 카드 그리드 3열, 좁은 화면에서는 1열로 쌓는다 |
| 색 예쁘게 써 줘       | 배경색·글자색·포인트색 토큰만 쓰고 새 색을 만들지 않는다                |

- 색은 화면을 시키기 전에 역할 이름(배경·글자·포인트·오류)부터 정한다. 이름 없이 맡기면 비슷한 색이 화면마다 조금씩 다르게 늘어난다. 이름이 있으면 값 하나를 바꿔 모든 화면을 한 번에 고친다.
- 이름으로 지시했다고 판정이 끝난 것은 아니다. 그 이름이 이 자리에 맞는지는 `ux-review`의 패턴 쓰임 대조표로 확인한다.
