# 화면 설계서 양식과 핸드오프 점검표

출처: 국내 화면설계서 관례(이랜서 블로그 2022, 요즘IT 2022, brunch @planbasic 2026 — 표지·개정 이력·화면 ID·번호 붙인 설명), Figma Help「Guide to Dev Mode」·「Name and organize components」, Figma Developer Docs「Structure your Figma file for better code」, Figma Blog「Introducing Specs」(2026). 양식은 이 저장소에서 정리했다.

## 1. 양식

```markdown
# 독서 노트 앱 — 구독 관리 화면 설계서

| 버전 | 날짜       | 작성   | 변경                                 |
| ---- | ---------- | ------ | ------------------------------------ |
| v1.2 | 2026-11-02 | 담당자 | SCR-SUB-03 버튼 문구 변경            |
| v1.1 | 2026-10-28 | 담당자 | SCR-SUB-02 해지 이유를 선택 사항으로 |

## SCR-SUB-03 구독 해지 확인

- 경로: 설정 > 구독 관리 > 해지하기
- 목적: 해지했을 때 무엇이 바뀌는지 이해하고 해지를 확정한다
- 진입: SCR-SUB-01 「해지하기」, SCR-SUB-02 「다음」
- 이탈: 「닫기」 → SCR-SUB-01 · 해지 성공 → SCR-SUB-04 · 실패 → 이 화면(인라인 오류)

### 영역

| 번호 | 컴포넌트              | 동작                                                | 상태                           | 문구                                                                      | 데이터                                                   |
| ---- | --------------------- | --------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------- | -------------------------------------------------------- |
| ①    | 대화상자              | 열리면 제목으로 포커스                              | 기본                           | 제목 「구독을 해지할까요?」 · 본문 「해지해도 {만료일}까지 쓸 수 있어요」 | 만료일: 구독 정보의 다음 결제일 전날, 「11월 30일」 형식 |
| ②    | 버튼 2개(같은 크기)   | 「닫기」 → 대화상자 닫힘 · 「해지하기」 → 해지 요청 | 기본 · 누름 · 포커스 · 처리 중 | 「닫기」 · 「해지하기」                                                   | —                                                        |
| ③    | 로딩 버튼             | 요청 중 두 버튼 비활성, 중복 요청 막음              | 처리 중                        | —                                                                         | —                                                        |
| ④    | 스낵바(SCR-SUB-01 위) | 「되돌리기」 → 해지 취소 요청                       | 누르거나 닫을 때까지 유지      | 「구독을 해지했어요」 · 「되돌리기」                                      | 되돌리기는 다음 결제일 전까지                            |

### 화면 상태

| 상태    | 모습                                                                                    |
| ------- | --------------------------------------------------------------------------------------- |
| 처리 중 | ②의 「해지하기」가 로딩 버튼으로 바뀌고 두 버튼이 비활성                                |
| 오류    | 본문 아래 인라인 오류 「해지하지 못했어요. 잠시 뒤 다시 시도해 주세요」 + 「다시 시도」 |
| 끝      | SCR-SUB-04에서 남은 이용 기간과 「다시 구독하기」                                       |

### 모션

- 대화상자 등장 200ms 이즈 아웃(배경 어둡게 함께), 닫힘 150ms 이즈 인
- 움직임 줄이기 설정: 페이드만

### 접근성

- 열리면 제목으로 포커스, 포커스는 대화상자 안에서만 돈다, Esc로 닫는다
- 닫히면 SCR-SUB-01의 「해지하기」로 포커스가 돌아간다
- 버튼 터치 영역 44×44pt 이상(iOS) · 48×48dp 이상(Android) · 24×24px 이상(웹 최소)
- 해지 결과 스낵바는 `role="status"`로 알린다

### 이벤트

| 이벤트                | 시점                | 속성                      |
| --------------------- | ------------------- | ------------------------- |
| `cancel_confirm_view` | 대화상자 열림       | `plan`, `days_left`       |
| `cancel_complete`     | 해지 성공           | `plan`, `reason_selected` |
| `cancel_undo`         | 스낵바 「되돌리기」 | `plan`                    |

### 예외

- 결제 처리 중 해지 요청 → 「결제가 끝난 뒤 다시 시도해 주세요」
- 만료일을 불러오지 못함 → 본문에서 날짜를 빼고 「남은 기간은 구독 관리에서 볼 수 있어요」

### 완료 조건

- 「해지하기」를 두 번 눌러도 해지 요청은 한 번만 간다
- 해지 뒤 SCR-SUB-04에 남은 이용 기간이 날짜로 보인다
- 키보드만으로 열고, 해지하고, 닫을 수 있다

## 정해야 할 것

| 질문                    | 선택지                | 영향 화면     | 담당 |
| ----------------------- | --------------------- | ------------- | ---- |
| 남은 기간 환불을 하는가 | 환불 없음 / 일할 환불 | SCR-SUB-03·04 | 사업 |
```

## 2. 핸드오프 점검표

| 항목             | 기준                                                                                |
| ---------------- | ----------------------------------------------------------------------------------- |
| 화면 ID          | 모든 화면에 고유 ID, 흐름도·화면 목록과 일치                                        |
| 컴포넌트         | 디자인 시스템 컴포넌트를 떼어 내지 않고 인스턴스로 사용, 표준 이름                  |
| 변수·토큰        | 색·간격·글자·모서리에 변수나 스타일 적용 — 숫자를 직접 박지 않음                    |
| 레이어 이름      | 의미 있는 이름(`CardContainer`), 자동 이름(`Frame 1268`) 없음                       |
| 오토 레이아웃    | 프레임 크기를 바꿔도 깨지지 않음                                                    |
| 상태 프레임      | 화면 상태와 컴포넌트 상태가 각각 프레임으로 있음                                    |
| 주석             | 화면에 안 보이는 동작·간격·데이터는 주석으로                                        |
| 개발 준비 표시   | 넘길 프레임을 Dev Mode의 Ready for dev로 표시                                       |
| 코드 연결        | Code Connect를 쓰면 컴포넌트를 코드 컴포넌트와 연결                                 |
| 문구             | 실제 문구, 자리표시 글(Lorem ipsum) 없음                                            |
| 에셋             | 내보내기 형식·배율 설정                                                             |
| 에이전트용 명세  | 코딩 에이전트에게 넘기면 이 설계서(마크다운)나 캔버스 위 명세 문서 링크를 함께 준다 |
| 부서지는 상황 축 | 3절의 축마다 넣을지 뺄지 적었고, 뺀 축은 이유 한 줄이 있다                          |

## 3. 부서지는 상황 축

화면이나 컴포넌트가 「무엇이 들어와도 깨지면 안 되는지」를 설계서에 미리 적는 절이다. 만든 뒤에는 이 표의 값으로 한 번 렌더해서 한 번 본다. 출처: jakubkrehel/skills(커밋 6c21201, MIT)의 `break` — scenarios.md와 한 번 렌더하고 한 번 보는 원칙. 원문 문장을 복사하지 않고 이 하네스의 절차에 맞게 다시 썼고, 한글 입력 조합 행은 한국어 화면 기준으로 더했다.

| 축            | 넣는 조건(단서)                                        | 값                                                                                                   | 잡는 것                                                                                                                                      | 고칠 기준                                                                                              |
| ------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 글 길이       | 컴포넌트가 직접 쓰지 않은 글(사용자 입력·CMS·API·번역) | 빈 글 · 한 단어 · 보통 · 여러 문장 · 끊을 데 없는 긴 문자열(긴 URL, 독일어 합성어)                   | 무너진 상자, 보여 줄 것 없이 떠 있는 라벨, 한 단어에 맞춘 버튼, 한 줄을 전제한 컨테이너, 끊을 데 없는 문자열의 넘침                          | 줄바꿈·잘림은 `visual-type.md`, 칸에 자리가 없으면 `visual-layout.md`, 원문 문구가 문제면 `ux-writing` |
| 글 모양       | 팀이 쓰지 않는 사용자·언어의 글                        | 이모지(단독·섞임) · 오른쪽에서 왼쪽 글 · 섞인 방향 · 발음 기호·위아래로 긴 문자 · 정렬해야 하는 숫자 | 행간 튐, 세로 가운데 어긋남, 글자 한가운데서 끊긴 잘림, 방향·문장 부호 위치, 잘린 위아래 획, 흔들리는 숫자                                   | `visual-type.md`, 공간 뒤집기는 `visual-layout.md`                                                     |
| 글 모양(한글) | 한글을 입력받는 칸                                     | 한글 입력 조합 중 Enter                                                                              | 일부 브라우저는 조합을 끝내는 keydown이 한 번 더 와서 마지막 글자가 중복되거나 두 번 제출된다. `event.isComposing`이 true면 Enter를 무시한다 | `ux-a11y`                                                                                              |
| 개수          | 항목을 반복(목록·표·격자·태그 줄·아바타 묶음)          | 0개 · 1개 · 보통 · 보통의 10배                                                                       | 빈 영역과 빠진 빈 상태, 복수만 전제한 레이아웃, 스크롤·쪽 나누기 부재, 고정 요소 풀림                                                        | 빈 상태 문구는 `ux-writing`, 영역과 나머지는 `visual-layout.md`                                        |
| 담는 폭       | 항상                                                   | 320px 칸 · 옆 요소에 눌림 · 아주 넓은 칸(화면 크기를 바꾸지 않고 고정 폭 칸으로)                     | 잘림·가로 스크롤·상자 밖으로 나간 컨트롤, 줄어들지 않는 최소 폭, 끝없이 늘어난 줄 길이와 가장자리에 붙은 내용                                | `visual-layout.md`                                                                                     |
| 상태          | 그 상태가 prop으로 옴                                  | 로딩 · 오류 · 비활성. 포커스·호버는 사람이 직접 눌러 본다                                            | 내용이 들어올 때의 레이아웃 이동, 이름 없는 로딩 표시, 넘치는 오류 문구, 색만으로 전달하는 오류, 비활성의 대비 붕괴                          | 접근성은 `ux-a11y`, 색은 `visual-color.md`, 상태 모양 다듬기는 `visual-surface-motion.md`              |
| 환경          | 프로젝트가 지원                                        | 어두운 모드 · 브라우저 확대 · 움직임 줄이기                                                          | 어두운 모드의 대비·토큰 누락, 확대에서 잘림, 움직임 설정을 무시하는 전환                                                                     | 어두운 모드는 `visual-color.md`, 확대와 움직임은 `ux-a11y`                                             |

규칙:

- 조건이 맞는 축만 넣는다. 뺀 축은 이유 한 줄을 적는다(예: 「라벨을 코드가 정한다 → 글 길이 뺌」). 한 번 읽고 잘못 뺐는지 알 수 있어야 한다.
- 환경 축은 화면 안에서 흉내 내지 않고 켜 보는 항목으로 적는다. 어두운 모드 토큰을 클래스로 다시 선언하는 식으로 시뮬레이션하면 다른 컴포넌트를 보게 된다.
- 담는 폭은 화면 크기를 바꾸지 않고 고정 폭 칸으로 시험한다.
- 깨진 것은 본 그대로 적는다(예: 「글이 칸 오른쪽으로 넘침」). 예상만으로는 finding이 아니다.
- 「고칠 기준」 열은 `visual-type.md`·`visual-layout.md`·`visual-color.md`·`ux-writing`·`ux-a11y` 중 하나를 적는다.

```markdown
### 부서지는 상황 축 — 상품 카드

| 축              | 값                                               | 기대하는 모습                         | 고칠 기준                 |
| --------------- | ------------------------------------------------ | ------------------------------------- | ------------------------- |
| 글 길이         | 상품명 빈 글 / 한 단어 / 80자 / 끊을 데 없는 URL | 2줄에서 잘리고 상세로 갈 길이 있다    | visual-type               |
| 개수            | 0개 / 1개 / 500개                                | 0개는 빈 상태 문구, 500개는 쪽 나누기 | ux-writing, visual-layout |
| 담는 폭         | 320px / 사이드바에 눌림                          | 한 열로 접힌다                        | visual-layout             |
| 상태            | 로딩 / 오류                                      | 이동 없이 같은 크기                   | ux-a11y                   |
| 환경            | 어두운 모드 / 확대 200%                          | 대비 유지, 잘림 없음                  | visual-color, ux-a11y     |
| (뺀 축) 글 모양 | 사용자 글이 없다                                 | —                                     | —                         |
```
