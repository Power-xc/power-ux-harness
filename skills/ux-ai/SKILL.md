# UX for AI

AI가 틀릴 수 있다는 전제에서 사용자가 기대를 맞추고, 결과를 확인하고, 멈추고, 고치고, AI 없이도 끝낼 수 있게 만든다.

## Trigger

- `@ux ai <기능|화면>`: AI 기능의 UX 설계·점검
- 「AI 챗 화면 설계」, 「AI 답변 화면 리뷰」, 「에이전트 UI」, 「출처 표시 어떻게」, 「AI 오류 화면」, 「AI 기능 첫 사용 안내」

## Input

- `feature`: AI가 하는 일(요약·생성·추천·검색·에이전트 실행)
- `limits`: 알려진 한계와 실패 유형(모르면 `NOT_CHECKED`)
- `task`: 사용자가 끝내려는 일과 AI 없이 하는 방법
- `risk`: 결과가 돈·건강·법·안전·되돌릴 수 없는 행동에 닿는지
- `target`: 화면·프로토타입·설계서

## Process

1. 사용자의 과제와 AI가 돕는 부분을 나눠 적는다. 핵심 과제를 AI 없이 끝내는 길이 있는지 확인한다. 데모·목 응답에서만 그려지는 분기가 있으면 운영 분기를 코드 분기 표(조건·플래그 | 데모 | 운영 | 화면 차이 | 코드 위치)로 적는다.
2. 첫 사용에서 할 수 있는 일·할 수 없는 일·얼마나 잘하는지를 알리는지 본다. AI가 만든 결과임을 밝히고, 사람이 쓴 것처럼 보이게 하지 않는다. 사람 같은 캐릭터는 그만큼 해낼 수 있을 때만 쓴다. 가이드·온보딩·소개 문구의 약속(「칼로리를 약속하지 않아요」 같은)을 결과 화면의 기본값·실제 동작과 한 줄씩 대조하고, 어긋나면 finding으로 적는다.
3. 입력 단계 — 빈 입력에 추천 질문 칩, 예시, 첨부의 진행·실패·재시도, 파일 형식·크기 제한 안내.
4. 기다림 — 「처리 중」 대신 지금 하는 일을 구체적으로 알리고, 단계가 길면 단계 표시를 쓴다. 생성 중에는 **중지** 버튼을 같은 자리에 계속 둔다. 긴 작업은 멈췄다 이어 할 수 있게 한다.
5. 결과 — 주장마다 출처를 정확한 위치로 연결하고, 출처가 없으면 없다고 말한다. 주의 문구는 결과 바로 옆에 구체적으로 둔다. 확신도는 사용자의 결정을 바꿀 때만, 맨 숫자 대신 단계와 권하는 행동으로 보여 준다.
6. 통제 — 고쳐 묻기, 다시 생성(이전 결과를 버전으로 남김), 되돌리기, 재시도를 결과 옆에 둔다. 되돌릴 수 없거나 민감한 실행은 실행 전에 확인을 받고, 파괴적인 실행을 자동으로 하지 않는다.
7. 에이전트 실행 — 실행 전 계획과 범위(무엇을 바꾸는지)를 보여 주고, 진행 중 멈출 수 있고, 끝나면 바뀐 것을 요약하고 기록을 남긴다.
8. 피드백 — 좋아요·싫어요에 이유 선택과 자세한 신고를 붙이고, 피드백이 무엇을 바꾸는지 알린다. 개인화를 초기화할 수 있게 한다.
9. 실패 — 쉬운 말로 무엇이 안 됐고 다음에 무엇을 하면 되는지 말한다. 막힌 요청은 이유와 되는 요청을 제안한다. 도울 수 없으면 그렇다고 말하고, 맥락을 넘겨주며 사용자에게 통제를 돌려준다. 확신이 낮으면 범위를 좁혀 답한다.
10. 시간이 지나며 — 무엇을 기억하는지 보이고, 동작이 바뀌면 알린다. 요청마다 화면을 조립해 보여 주는 기능(생성형 UI)이면 같은 요청에 같은 구조와 이름이 나오는지, 상황이 바뀌어 다시 짤 때 바뀐 점을 보여 주는지, 확정한 예약·결제는 묻고 바꾸는지, 이전 안으로 돌아갈 수 있는지 본다.
11. [`references/hax-checklist.md`](./references/hax-checklist.md)로 H1~H18을 판정하고, 화면 요소는 [`references/ai-patterns.md`](./references/ai-patterns.md)의 패턴 이름으로 적는다.

## Output

- HAX 점검표: H1~H18 각각 `PASS`·`FAIL`·`N/A`·`NOT_CHECKED`와 근거
- 화면 패턴 목록: 패턴 이름, 상태, 문구
- finding 표: 우선순위(P1~P3), 위치, 문제, 사용자 영향, 수정(패턴·상태·문구)
- 판정: `PASS | FAIL | BLOCKED` — P1이 있으면 FAIL

## Hard Gates

| ID  | FAIL 조건                                                     |
| --- | ------------------------------------------------------------- |
| G1  | 생성 중에 멈출 수 없음                                        |
| G2  | 다시 생성이 이전 결과를 버전 없이 덮어씀                      |
| G3  | 출처를 정확한 위치 없이 표시하거나, 확인하지 않은 출처를 붙임 |
| G4  | 되돌릴 수 없는 에이전트 실행을 확인 없이 진행                 |
| G5  | 실패 화면이 다음 행동 없이 일반 오류만 보여 줌                |
| G6  | AI가 만든 결과임을 밝히지 않거나 사람이 쓴 것처럼 보이게 함   |
| G7  | 핵심 과제를 AI 없이 끝낼 길이 없는데 그 사실을 검토하지 않음  |

## Skill Chaining

- AI 밖의 화면 사용성: `ux-review`
- AI 안내·주의·오류 문구: `ux-writing`
- 스트리밍 알림·중지 버튼의 접근성: `ux-a11y`
- 다시 생성률·고침률·싫어요 이유 같은 품질 지표: `ux-metrics`
- 화면 설계서에 반영하기: `ux-spec`

## Constraints

- 모델 이름이나 버전에 기대는 설계를 하지 않는다. 모델이 바뀌어도 맞는 화면을 설계한다.
- 「AI가 다 해 줘요」처럼 할 수 없는 일을 약속하는 문구를 쓰지 않는다.
- 사용자가 입력한 개인정보를 학습·기억하는지 알리지 않은 채 설계하지 않는다.
- 사람의 확인이 필요한 결정(의료·법률·금융)을 AI 결과만으로 끝내게 하지 않는다.
- 산출물은 실무에서 쓰는 낱말로 쓴다 — 「꾸리다」는 「구성하다」, 「잣대」는 「기준」(`ux-writing`의 낱말 목록).
