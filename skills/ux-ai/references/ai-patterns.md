# AI 화면 패턴

출처: Emily Campbell「The Shape of AI」(2025)의 패턴 범주(길잡이·프롬프트 동작·조율·통제·신뢰·식별), Apple HIG「Generative AI」, Google PAIR「People + AI Guidebook」의 피드백·통제·오류 장, Microsoft HAX(2019), NN/g Kate Moran·Sarah Gibbons「Generative UI and Outcome-Oriented Design」(2024). 패턴 이름은 이 저장소에서 한국어로 정했다.

| 패턴              | 쓰는 때                                              | 이렇게 쓰면 finding                                                                                                           |
| ----------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 추천 질문 칩      | 빈 입력, 첫 사용                                     | 실제로 잘 답하지 못하는 질문을 추천                                                                                           |
| 예시 입력         | 무엇을 물을지 모를 때                                | 예시가 기능 범위를 넘음                                                                                                       |
| 첨부              | 파일·이미지를 근거로 쓸 때                           | 업로드 진행·실패·재시도가 안 보임, 형식·크기 제한을 실패 뒤에야 알림                                                          |
| 진행 문구         | 몇 초 넘는 기다림                                    | 「처리 중」·「생각 중」만 계속 표시                                                                                           |
| 단계 표시         | 여러 단계를 거치는 생성·에이전트 실행                | 지금 단계·끝난 단계·실패한 단계를 구분하지 않음                                                                               |
| 스트리밍 + 중지   | 긴 생성                                              | 중지 버튼이 없거나 위치가 바뀜, 중지하면 받은 부분이 사라짐                                                                   |
| 출처 칩           | 사실 주장·요약                                       | 칩이 문서 첫 페이지로만 연결, 확인하지 않은 출처                                                                              |
| 주의 문구         | 틀릴 위험이 있는 결과                                | 화면 맨 아래 일반 문구 하나로만 처리                                                                                          |
| 확신 단계         | 확신이 결정을 바꿀 때                                | 맨 퍼센트만 표시, 권하는 행동이 없음                                                                                          |
| 다시 생성(버전)   | 마음에 들지 않을 때                                  | 이전 결과를 덮어씀, 버전을 비교할 수 없음                                                                                     |
| 고쳐 묻기         | 질문을 바꾸고 싶을 때                                | 처음부터 다시 입력해야 함                                                                                                     |
| 결과 고치기       | 결과 일부만 바꾸고 싶을 때                           | 전체를 다시 생성해야만 함                                                                                                     |
| 피드백 + 이유     | 품질 개선                                            | 좋아요·싫어요만 있고 이유를 남길 수 없음, 피드백이 어디에 쓰이는지 모름                                                       |
| 실행 전 승인      | 에이전트가 무언가를 바꿀 때                          | 계획·범위를 보여 주지 않고 실행, 되돌릴 수 없는 실행을 확인 없이                                                              |
| 활동 기록         | 에이전트가 여러 일을 한 뒤                           | 무엇을 바꿨는지 요약·기록이 없음                                                                                              |
| AI 표시           | AI가 만든 결과                                       | 사람이 쓴 것처럼 보이게 함                                                                                                    |
| 기억 보기·지우기  | 개인화·기억이 있을 때                                | 무엇을 기억하는지 볼 수 없음, 지울 수 없음                                                                                    |
| AI 없이 하기      | 핵심 과제                                            | AI가 실패하면 과제를 끝낼 길이 없음                                                                                           |
| 조립되는 화면     | 요청마다 화면을 만들어 보여 줄 때(생성형 UI)         | 같은 요청에 매번 다른 배치·이름이라 다시 익혀야 함 · 디자인 시스템에 없는 컴포넌트를 지어냄 · 조립된 화면을 직접 고칠 수 없음 |
| 다시 짠 결과 비교 | 상황(날씨·일정·재고)이 바뀌어 AI가 결과를 다시 짤 때 | 바뀐 점을 표시하지 않고 통째로 바꿈 · 확정한 예약·결제를 묻지 않고 바꿈 · 이전 안으로 돌아갈 수 없음                          |

접근성: 스트리밍되는 글자를 한 글자씩 화면 낭독기에 알리지 않는다. 생성이 끝났을 때 한 번 알리고(`role="status"`), 중지 버튼은 생성 중 포커스로 닿을 수 있게 둔다.
