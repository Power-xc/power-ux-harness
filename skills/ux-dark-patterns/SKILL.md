# UX Dark Patterns

사용자의 착각·부주의를 이용해 돈·동의·데이터를 얻는 설계를 찾아내고, 사업 목표를 지키는 정직한 대안을 낸다. 법 위반 여부는 판단하지 않는다 — 해당 소지와 근거를 적고 법무 확인을 권한다.

## Trigger

- `@ux dark <흐름|화면>`: 기만 패턴 점검
- 「다크패턴 있는지 봐 줘」, 「구독 해지 흐름이 법에 걸리나」, 「결제 화면 기만 요소」, 「동의 화면 점검」, 「팝업이 너무 자주 뜨는데 괜찮나」
- 「가운데 요금제로 유도해도 되나」, 「미끼 요금제 넣어도 되나」, 「취소선 정가 표시 괜찮나」처럼 가격 심리 장치의 선을 묻는 요청
- 「뒷광고 아닌가」, 「광고 표시가 충분한가」처럼 광고와 콘텐츠의 구분을 묻는 요청

## Input

- `target`: 흐름의 화면·URL·설계서
- `jurisdiction`: 기본 한국. EU·미국 서비스면 함께 지정
- `business`: 구독·커머스·플랫폼·금융 등 사업 형태
- `signup_path`: 가입·구매 경로(해지 경로와 비교하려면 필요)

## Process

1. 흐름에서 돈·동의·데이터가 오가는 결정 지점을 모두 찾는다 — 가격 표시, 요금제 비교, 옵션 선택, 동의, 구독 시작, 갱신·가격 변경, 해지·탈퇴, 반복 팝업.
2. 결정 지점마다 [`references/kr-guideline.md`](./references/kr-guideline.md)의 13개 유형을 대조한다. EU·미국 범위면 [`references/global-rules.md`](./references/global-rules.md)를 함께 대조한다.
3. 잴 수 있는 것은 잰다 — 가입과 해지의 단계·클릭 수와 경로(같은 채널인가, 로그인 첫 화면이나 한 번 이동으로 닿는가), 첫 가격 화면의 금액과 최종 결제 금액, 미리 선택된 항목, 수락·거절 버튼의 크기·색·대비, 거절 뒤 같은 요구의 재노출 횟수, 「7일간 다시 보지 않기」 선택지, 가격 인상·유료 전환 전 동의 절차.
4. 마감 시계·재고·「지금 N명이 보는 중」·후기는 데이터 출처를 확인한다. 출처를 확인하지 못하면 PASS가 아니라 `NOT_CHECKED`다.
5. 심리 장치는 [`references/decision-devices.md`](./references/decision-devices.md)로 정직한 쓰임과 기만의 경계를 판정한다. 요금제 표·할인가는 같은 문서의 가격표 장치 표와 확인 항목 4개를 적용한다. 광고·협찬·추천으로 버는 서비스면 광고와 콘텐츠의 구분 표시를 [`references/ad-disclosure.md`](./references/ad-disclosure.md)로 확인한다.
6. finding마다 유형(국내 가이드라인 유형·근거 조항, 해외 유형), 위치, 측정값이나 캡처, 사용자 피해, 정직한 대안, 우선순위, 법무 확인 필요 여부를 적는다. 법정 유형과 기만 유형은 P1, 법정 기준에 못 미치는 압박(죄책감 문구 등)은 P2다.
7. 정직한 대안은 사업 목표를 함께 지킨다 — 해지 화면의 한 번뿐인 혜택 안내, 일시 정지 선택지, 남은 이용 기간 안내, 선택 사항인 해지 이유 설문, 같은 무게의 두 버튼.
8. 결론은 「위법이다」가 아니라 「○○ 유형 해당 소지 — 법무 확인 권장」으로 쓴다. 법령과 지침은 바뀌므로 판정에 쓴 자료의 날짜를 적는다.

## Output

- 결정 지점 지도: 단계, 화면, 오가는 것(돈·동의·데이터)
- finding 표: `type`, `basis`(조항·지침), `evidence`(측정값·캡처), `harm`, `honest_alternative`, `priority`, `legal_review`
- 가입·해지 비교표: 단계 수, 클릭 수, 채널, 진입 위치
- 판정: `PASS | FAIL | BLOCKED` — P1이 하나라도 있으면 FAIL. 범위에 돈·동의·데이터 결정 지점이 없으면 지도에 「없음」을 적고 판정은 `N/A`(이유)로 두되, 광고 구분처럼 확인한 항목은 따로 PASS·FAIL로 적는다
- 법률 자문이 아니라는 고지와 사용한 자료의 날짜

## Hard Gates

| ID  | FAIL 조건                                                     |
| --- | ------------------------------------------------------------- |
| G1  | 해지가 범위에 있는데 가입 경로와 비교하지 않고 PASS           |
| G2  | 마감·재고·사회적 증거를 데이터 출처 확인 없이 정직하다고 판정 |
| G3  | 「위법이다」처럼 법적 결론을 단정                             |
| G4  | finding에 정직한 대안이 없음                                  |
| G5  | 전환을 높이려고 기만 패턴을 권고                              |
| G6  | 옵션·동의 화면에서 미리 선택된 항목을 확인하지 않음           |

## Skill Chaining

- 정직한 대안의 사용성 점검: `ux-review`
- 중립적인 거절·해지 문구: `ux-writing`
- 해지 경로 다시 그리기: `ux-flow`
- 대안을 화면 설계서로: `ux-spec`
- 해지율만이 아닌 가드레일 지표(문의·환불 요청): `ux-metrics`

## Constraints

- 법률 자문이 아니다. 판단은 법무 확인으로 넘긴다.
- 보고서에 다른 회사의 이름을 사례로 적지 않는다. 유형과 화면 위치로 쓴다.
- 법령·지침의 최신 개정을 확인하고 날짜를 적는다. 모르면 `NOT_CHECKED`로 둔다.
- 개인정보가 담긴 캡처를 보고서에 넣지 않는다.
- 운영 환경을 열 때는 쓰기·분석 요청(POST·비콘)을 막고 본다. 관찰이 운영 데이터를 바꾸지 않게 한다.
