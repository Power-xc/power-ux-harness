# 실험 계획 양식

출처: 통제 실험(A/B 테스트) 설계의 일반 원칙 — 사전 등록, 단일 주 지표, 가드레일, 최소 검출 효과와 검정력, 고정 기간, 중간 확인으로 멈추지 않기. 양식은 이 저장소에서 정리했다. 표본 수는 실제 기준선과 분산으로 계산 도구에서 구하고, 이 문서의 숫자를 대신 쓰지 않는다.

## 양식

```markdown
## 실험: 해지 확인 화면에 남은 이용 기간 표시

- 가설: 해지 확인 화면에 남은 이용 기간을 날짜로 보여 주면,
  해지 뒤 「언제까지 쓸 수 있나요」 문의가 줄어든다.
  사용자가 해지 결과를 미리 이해하기 때문이다.
- 대상: 해지 확인 화면에 들어온 구독자(직원·테스트 계정 제외)
- 배정: 사용자 단위 무작위 50:50
- 주 지표: 해지 확인 화면 진입 사용자당 7일 안 해지 관련 문의 비율
- 가드레일: 해지 완료까지 걸린 시간 중앙값, 해지 철회율, 오류율
- 최소 검출 효과: 상대 -20% (기준선: 지난 4주 실측값)
- 필요한 표본: 군당 N명 — 기준선·분산으로 계산, 계산 도구와 입력값 기록
- 기간: 온전한 2주(요일 효과 포함), 표본이 차기 전 중간 결과로 멈추지 않음
- 미리 정한 세그먼트: 플랫폼(iOS·Android·웹), 구독 기간(3개월 미만·이상)
- 판단 규칙:
  - 주 지표 개선이 유의하고 가드레일이 모두 유지 → 전체 적용
  - 주 지표 변화 없음 → 문구·위치를 바꾼 2차 안을 리서치로 먼저 확인
  - 가드레일 악화 → 중단하고 원인 확인
```

## 규칙

- 주 지표는 하나다. 나머지는 보조 지표나 가드레일로 둔다.
- 판단 규칙은 실험 시작 전에 쓴다. 결과를 본 뒤 기준을 바꾸지 않는다.
- 트래픽이 적어 기간 안에 필요한 표본에 닿지 못하면 실험이 아니다. 출시 전후 비교도 계절·홍보 효과와 섞이므로 판정에 쓰지 않는다. 이벤트를 먼저 깔고 비율을 관찰 지표로만 기록하며, 사용성 테스트·인터뷰(`ux-research`)로 방향을 정하고, 판단 규칙은 표본이 정한 수에 닿은 뒤부터 적용한다.
- 표본이 차기 전에 결과를 보고 멈추지 않는다. 중간 확인이 필요하면 순차 검정처럼 그에 맞는 방법을 미리 정한다.
- 세그먼트는 미리 정한 것만 판단에 쓴다. 나머지는 다음 가설의 재료다.
- 새로움 효과가 있을 수 있는 변화(새 화면·새 기능)는 기간을 늘리거나 신규 사용자만 따로 본다.
- 트래픽이 작아 검출할 수 없으면 실험 대신 사용성 테스트와 전후 비교로 바꾸고 그 한계를 적는다.
