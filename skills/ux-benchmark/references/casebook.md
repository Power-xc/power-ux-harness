# 맥락 사례집 — 같은 문제, 다른 정답

비교 대상을 고를 때 출발점으로 쓰는 사례 모음이다. 사례마다 무엇을 했는지보다 왜 거기서 통했는지(맥락 칸)를 먼저 본다. 모든 사례는 출처를 직접 열어 확인했고 확인한 날짜를 적었다. 제품은 바뀌므로, 사례를 인용하기 전에 지금도 그런지 다시 확인한다.

| 파일                                                         | 결정적 맥락                                             | 다루는 상황                                        |
| ------------------------------------------------------------ | ------------------------------------------------------- | -------------------------------------------------- |
| [`cases/money-trust.md`](./cases/money-trust.md)             | 실수 비용 · 되돌릴 수 있는지 · 낯선 사람 간 신뢰 · 규제 | 잘못 보냄, 사기 의심, 공개 범위, 위험한 축하       |
| [`cases/age-ability.md`](./cases/age-ability.md)             | 연령 · 디지털 숙련도 · 시력·인지 · 보호자               | 나이별 기본값, 쉬운 모드, 대리 사용, 디지털 소외   |
| [`cases/situation.md`](./cases/situation.md)                 | 기기·환경 · 시간 압박 · 위급 · 감정 상태                | 운전 중, 잠든 사이, 오작동 경보, 위치 노출         |
| [`cases/scale-market.md`](./cases/scale-market.md)           | 규모 · 사업 방식 · 시장과 문화 · 규제 변화              | 사용자층이 바뀔 때, 퍼지는 속도, 문화가 다를 때    |
| [`cases/sensitive-sharing.md`](./cases/sensitive-sharing.md) | 내용 민감도 · 재식별 · 콘텐츠 공급 · 사업 방식          | 건강·신체 기록 공개, 회원 공개의 한계, 광고성 후기 |

## 사례 양식

파일 머리에 출처 표를 두고, 사례는 아래 양식으로 쓴다. ID는 파일 머리글자와 번호다(`MT-01`, `AA-01`, `SI-01`, `SM-01`, `SS-01`).

```markdown
| ID  | 제목 | 발행처 | 주소 | 확인일     |
| --- | ---- | ------ | ---- | ---------- |
| S1  | …    | …      | …    | 2026-11-02 |

### MT-01 <같은 문제, 다른 정답을 한 줄로>

| 칸          | 내용                                                            |
| ----------- | --------------------------------------------------------------- |
| 상황        | 어떤 예외·상황인가                                              |
| 해법        | 서비스 — 패턴 이름·기본값·흐름 수준 (`observed`·`reported`, S1) |
| 대조        | 같은 문제를 다르게 푼 서비스, 또는 같은 서비스의 이전 방식      |
| 결정적 맥락 | 맥락 카드의 칸 이름 — 그 칸이 왜 정답을 바꿨나                  |
| 대가        | 포기한 것, 부작용, 논란                                         |
| 가져갈 원리 | 다른 서비스로 적용할 수 있는 한 문장                            |
| 안 맞는 곳  | 이 원리를 가져오면 안 되는 맥락                                 |
| 시점        | 도입·변경 연월(출처 기준)                                       |
```

## 수록 기준

- 출처는 공식 도움말·정책·보도자료·공식 블로그·규제 기관 문서를 먼저 쓰고, 없을 때만 믿을 만한 기사를 쓴다. 한 사례에 출처 하나 이상, 주장마다 출처 ID를 단다.
- 같은 문제를 맥락 때문에 다르게 푼 사례만 싣는다. 「좋은 기능 소개」는 싣지 않는다.
- 알림·로딩·입력 컨트롤·제스처·모션·내비게이션 패턴 자체의 쓰임, 기만 패턴 목록, 별점 노출 여부는 이 사례집의 주제가 아니다. 패턴 쓰임은 `ux-review`의 대조표, 기만 패턴은 `ux-dark-patterns`가 맡는다.
- 원문 문장을 복사하지 않고 내 말로 요약한다. 화면 캡처를 싣지 않는다.
