# 비교 대상 고르기

비교 대상은 「유명한 곳」이 아니라 「우리의 결정적 맥락 칸을 공유하는 곳」으로 고른다. 직접 경쟁만 보면 업계의 관행을 되풀이하게 되고, 다른 업종에서 같은 맥락을 푼 사례를 보면 관행 밖의 해법이 보인다.

## 세 겹

| 겹        | 고르는 기준                                                       | 얻는 것                                    | 위험                               |
| --------- | ----------------------------------------------------------------- | ------------------------------------------ | ---------------------------------- |
| 직접 경쟁 | 같은 일을 같은 사용자에게 파는 서비스                             | 사용자의 기대치, 업계 관행, 규제 대응 수준 | 관행을 정답으로 착각한다           |
| 같은 맥락 | 업종은 다르지만 결정적 맥락 칸의 값이 같다                        | 관행 밖의 해법, 같은 제약을 푼 방식        | 업종 차이를 놓치고 그대로 적용한다 |
| 극단 사례 | 같은 칸의 값이 더 극단이다(위험이 더 크거나 사용자가 더 취약하다) | 가장 엄격한 보호 장치, 실패했을 때의 대가  | 우리 규모에 과하다                 |

### 고르는 법

1. 맥락 카드의 결정적 맥락 2~3칸을 적는다.
2. 직접 경쟁에서 2~3곳을 고른다. 시장 점유가 다른 곳(선두, 신생, 해외)을 섞는다.
3. 결정적 맥락 칸마다 「이 칸의 값이 같은 다른 업종은?」을 묻는다. 칸을 키워드로 바꿔 업종 목록을 만든다(예: 「구매자와 사용자가 다름」 → 선물, 어린이 용돈, 부모 돌봄, 법인 카드).
4. 같은 칸의 값이 더 극단인 곳을 1~2곳 찾는다(예: 실수 비용이 더 큰 곳 — 송금, 의료, 항공).
5. 총 5~8곳(서비스 단위). 곳마다 「겹치는 맥락 칸」을 한 줄로 적는다. 칸을 못 적으면 뺀다. 한 곳에서 나오는 사례(인사이트) 수에는 제한이 없다.
6. 한 겹이라도 비면 비교 대상 표를 다시 짠다 — 한 겹에만 있는 목록은 반증을 받지 못한다.

예시 (가상의 서비스 「동네 약속」, 결정적 맥락: 약속을 어긴 지연, 구매자와 수령자 분리, 저녁 응대 불가):

| 서비스 유형               | 겹        | 겹치는 맥락 칸             | 고른 이유                                 |
| ------------------------- | --------- | -------------------------- | ----------------------------------------- |
| 다른 반찬·식료품 정기배송 | 직접 경쟁 | B2 사업 방식, B3 가치 약속 | 같은 구독·시간 약속 모델의 지연 안내 관행 |
| 선물 배송 서비스          | 같은 맥락 | U6 구매자와 수령자 분리    | 주문자와 받는 사람에게 각각 알리는 방식   |
| 병원·약국 처방 배송       | 같은 맥락 | B3 가치 약속, B4 운영 역량 | 시간이 정해진 약속과 운영 시간 밖의 응대  |
| 항공편 지연 안내          | 극단 사례 | B3 가치 약속, S2 감정      | 지연·변경을 가장 규칙적으로 안내하는 영역 |

위 표는 양식을 보여 주려는 예시다. 실제 서비스 이름과 사실은 조사해서 채운다.

## casebook.md를 출발점으로 쓰는 법

[`casebook.md`](./casebook.md)는 같은 문제를 맥락 때문에 다르게 푼 사례를 모아 둔 곳이다.

1. 결정적 맥락 칸 이름으로 사례집 파일을 고른다(표의 「결정적 맥락」 열).
2. 그 파일에서 상황이 비슷한 사례를 찾고, 사례의 「대조」 열에 있는 서비스도 후보로 올린다.
3. 사례집의 사례는 출발점일 뿐이다. 제품은 바뀌므로 인용 전에 출처를 다시 열어 지금도 그런지 확인한다.
4. 사례집에 없는 상황이면 아래 「찾는 법」으로 새로 조사하고, 필요하면 사례집 양식으로 정리한다.

## 찾는 법

| 자료                                  | 찾는 검색어·위치                                                                                                              | 얻는 것                                              |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 화면 레퍼런스 모음                    | 유아이볼(uibowl.io, MCP를 연결하면 대화 안에서 검색 — S4)에서 화면 유형·흐름·화면 속 문구(예: 「선택 안 함」)·컴포넌트로 검색 | 국내 앱이 실제로 그린 화면·단계·문구                 |
| 공식 도움말                           | `<서비스> 도움말 <상황 키워드>`(예: 「배송 지연」, 「취소」, 「한도」)                                                        | 예외 처리와 사용자에게 보이는 선택지                 |
| 정책·약관                             | 약관 속 책임·환불·한도·대리인 조항                                                                                            | 되돌릴 수 있는지, 책임이 누구에게 있는지             |
| 릴리스 노트·앱 스토어 「새로운 기능」 | 버전별 변경 내역                                                                                                              | 변경 시점과 바뀐 이유의 단서                         |
| 디자인·기술 블로그                    | `<서비스> 디자인 블로그`, `<서비스> 엔지니어링 블로그` + 상황 키워드                                                          | 왜 그렇게 했는지, 실험 결과                          |
| 규제 기관 보도자료                    | 기관 보도자료에서 업종·상황 키워드                                                                                            | 규제가 만든 제약, 변경 일정                          |
| 공개 발표                             | 컨퍼런스 발표, 공개 슬라이드, 인터뷰                                                                                          | 의사결정 배경                                        |
| 리뷰                                  | 앱 스토어·커뮤니티 리뷰에서 상황 키워드                                                                                       | 사용자의 반응(기간·건수·분류 기준 기록)              |
| 국내 법령·행정규칙                    | 국가법령정보센터 `law.go.kr/법령/<법령명>/제<N>조`, `law.go.kr/행정규칙/<규칙명>`                                             | 조문·지침 원문(스크립트로 그리는 페이지 — 아래 참고) |
| 기관 가이드라인                       | 소관 기관 누리집의 자료실·법령 메뉴(개인정보위·공정위 등), 첨부 PDF                                                           | 해설·예시, 개정 일자                                 |

스크립트로 그리는 페이지(법령정보센터·일부 도움말 센터)는 일반 가져오기로 본문이 비어 나온다. 브라우저로 렌더한 뒤 화면 글자를 읽으면 `observed`로 인정하고, 주소와 연 날짜를 적는다. 브라우저 도구가 남긴 스냅숏·캡처 파일은 작업 저장소 밖 임시 폴더에 두고 조사가 끝나면 지운다. 저장소에 커밋하지 않는다.

화면 레퍼런스 모음의 캡처는 화면을 직접 본 것이라 `observed`지만, 시점은 캡처한 날이다. 날짜가 보이면 적고 없으면 시점을 `NOT_CHECKED`로 둔다. 결정이 지금 화면에 달려 있으면 실제 앱이나 도움말에서 다시 확인한다. 검색 결과 몇 개로 「대부분의 앱이 이렇게 한다」고 쓰지 않는다(무료 회원은 검색당 3개). 캡처 이미지는 산출물과 저장소에 넣지 않고 링크와 분해한 내용(단계 수·패턴 이름·기본값·문구의 의도)만 적는다. 가입과 멤버십은 사용자가 직접 정하고, 연결이 없으면 이 자료는 `NOT_CHECKED`다.

찾기 순서: 공식 도움말·정책·화면 레퍼런스 → 릴리스 노트 → 블로그·발표 → 기관 보도자료 → 기사. 앞의 것이 사실에 가깝고 뒤의 것이 이유에 가깝다. 두 가지를 모두 모아야 「무엇을」과 「왜」가 같이 선다.

## 증거 수준

사례마다 한 가지를 단다.

| 수준          | 뜻                                               | 예                                                                             |
| ------------- | ------------------------------------------------ | ------------------------------------------------------------------------------ |
| `observed`    | 화면이나 공개 페이지에서 직접 확인               | 공개된 도움말 페이지, 비로그인 화면, 화면 레퍼런스 모음의 캡처(캡처한 날 기준) |
| `reported`    | 공식 발표·기사·글로 확인했지만 화면은 보지 못함  | 보도자료, 블로그 글                                                            |
| `NOT_CHECKED` | 적용되지만 열지 못함 — 내용을 짐작해 쓰지 않는다 | 로그인 뒤 화면, 유료 보고서                                                    |

- 출처마다 ID(`S1`…), 주소, 연 날짜를 표에 적는다.
- 같은 사례에서 공개 화면은 `observed`, 로그인 뒤 동작은 `reported`나 `NOT_CHECKED`처럼 부분마다 다르게 단다. 로그인 뒤 화면이 핵심이면 단계 수를 「3+ (로그인 뒤 `NOT_CHECKED`)」처럼 확인한 만큼만 센다.
- 기억으로 아는 사례는 사례로 쓰지 않는다. 열어서 확인하기 전에는 `NOT_CHECKED`다.

## 최신성 확인

- 출처의 날짜(발행·최종 수정)와 사례가 말하는 변경 시점을 둘 다 적는다.
- 1년이 넘은 사례는 릴리스 노트와 현재 도움말에서 지금도 같은지 다시 확인한다. 달라졌으면 달라진 이유가 인사이트다.
- 날짜가 없는 출처는 시점을 `NOT_CHECKED`로 적고 근거로 쓰는 강도를 낮춘다.
- 사업 방식·규제가 바뀐 서비스는 바뀌기 전후를 별개 사례로 본다.

## 하지 말 것

- 로그인 벽, 유료 자료, 비공개 베타를 우회하지 않는다. 가입을 요구하는 화면은 공개 자료로 확인되는 만큼만 쓴다.
- 화면·문구·브랜드 요소를 복제하지 않는다. 단계 수, 패턴 이름, 기본값, 예외 처리, 핵심 의도만 분해한다.
- 경쟁사가 하니까 한다는 근거를 쓰지 않는다. 「왜 거기서 통했나」를 못 적으면 인사이트가 아니다.
- 직접 경쟁만 보지 않는다. 한 겹에 몰린 목록은 비교 대상 표 단계에서 고친다.
- 검색 결과의 요약만 읽고 사례로 쓰지 않는다. 출처를 열어 본문을 확인한다.

## 비교 대상 표 양식

| 서비스 | 겹                           | 겹치는 맥락 칸 | 고른 이유 | 출처 ID | 증거 수준                         | 열람일 | 최신성                |
| ------ | ---------------------------- | -------------- | --------- | ------- | --------------------------------- | ------ | --------------------- |
| …      | 직접 경쟁 · 같은 맥락 · 극단 | B3, U6 …       | …         | S1, S2  | observed · reported · NOT_CHECKED | …      | 확인 · 다시 확인 필요 |

점검: 세 겹이 모두 있는가, 곳마다 겹치는 맥락 칸이 적혀 있는가, 열지 못한 곳이 `NOT_CHECKED`로 표시되어 있는가.
