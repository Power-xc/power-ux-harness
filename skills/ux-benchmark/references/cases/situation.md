## 사례

### SI-01 ★ 보내기 취소 — 메일은 몇 초, 메신저는 하루

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 잘못 보내거나 감정이 식은 뒤 후회하는 메시지를 되돌리고 싶다.                                                                                                                                                                                                                                                                       |
| 해법        | 메일: 보낸 직후 하단에 「실행취소」가 뜨고, 취소 가능 시간을 5·10·20·30초 중에서 사용자가 고른다(`reported`, S1). 메신저: 보낸 메시지를 24시간 안에 「모든 대화 상대에게서 삭제」로 지운다. 지우면 대화방에 「삭제된 메시지입니다」 표시가 남는다(`reported`, S2, S22). 비밀채팅방과 나와의 채팅방에서는 이 기능을 쓸 수 없다(S22). |
| 대조        | 같은 메신저의 이전 방식: 2018년 도입 때 전송 후 5분이었고 2025년 8월 24시간으로 늘렸다(`reported`, S3). 2026-11 현재 카카오 고객센터 본문도 24시간 이내로 안내한다(S22). 메일은 몇 초 안의 철회, 메신저는 보낸 뒤의 사후 삭제로 구조가 다르다.                                                                                      |
| 결정적 맥락 | 위험(되돌릴 수 있는지): 메일은 이미 상대에게 간 뒤에 되돌릴 수단이 이 문서에 없다(S1). 해석: 그래서 보내기 직후의 짧은 취소 시간이 해법이 됐다. 사용자(감정 상태): 대화의 부담을 낮추고 소통 환경을 만들려고 삭제 기능을 개선했다고 카카오가 설명했다(S3). 후회가 늦게 온다는 점이 그 이유라는 연결은 `가정`이다.                   |
| 대가        | 메일은 취소 시간이 최대 30초라 그 뒤에는 방법이 없다(S1). 메신저는 삭제 표시가 남고, 삭제한 메시지는 복구할 수 없다(S22). 1대1 방이 아니면 누가 지웠는지 알 수 없다(S3). 상대가 이미 본 뒤 지웠는지는 이 출처로 알 수 없다.                                                                                                         |
| 가져갈 원리 | 되돌리기 창의 길이는 「서비스가 사후에 대화를 고칠 수 있는가」와 「보낸 사람의 후회가 얼마나 늦게 오는가」로 정한다. 사후 고치기가 불가능하면 보내기 전후의 짧은 지연, 가능하면 길고 흔적이 남는 삭제.                                                                                                                              |
| 안 맞는 곳  | 송금처럼 돌려받는 데 상대의 동의가 필요한 거래, 법적 증거가 남아야 하는 메시지(삭제 표시만으로 충분한지 따로 판단한다).                                                                                                                                                                                                             |
| 시점        | 메신저 5분 → 24시간 변경 2025-08 보도(S3), 2026-11 고객센터·쉬운 설명서 모두 24시간(S2, S22). 검색 결과에 보이는 오래된 고객센터 문장은 5분 기준이므로 인용하지 않는다. 메일 설정은 현재 도움말 기준(S1).                                                                                                                           |

### SI-02 「계속 보고 계세요?」 — 기기에 따라 묻는 기준이 다르다

| 칸          | 내용                                                                                                                                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 다음 화가 자동으로 이어지는데 보는 사람이 없을 수 있다.                                                                                                                                                             |
| 해법        | TV와 TV 스트리밍 기기는 3편과 90분을 입력 없이 이어 보면 묻고, 그 밖의 기기는 3편을 이어 보는 동안 재생 컨트롤을 쓰지 않았을 때 묻는다(`reported`, S4). 사용자는 닫거나 다음 화 자동 재생을 끌 수 있다(S4).         |
| 대조        | 기기 종류에 따른 두 가지 기준이 같은 서비스 안에서 공존한다(S4). 자동 재생을 끄면 묻는 일 자체가 없다(S4).                                                                                                          |
| 결정적 맥락 | 상황(기기·환경): 서비스가 든 이유는 보던 위치를 잃지 않게 하고, 아무도 보지 않을 때 인터넷 데이터를 쓰지 않게 하는 것이다(S4). TV는 리모컨 입력 없이 틀어 두기 쉽다는 점이 시간 조건이 붙은 이유라는 건 `가정`이다. |
| 대가        | 몰아 보는 흐름이 끊기고 한 번 더 눌러야 한다. 이 문서는 끄는 설정을 따로 제공한다고 적지 않았고, 자동 재생 끄기만 안내한다(S4).                                                                                     |
| 가져갈 원리 | 자동으로 이어지는 소비에는 「사람이 아직 있는가」를 확인하는 장치를 두고, 그 신호(입력 유무·연속 시간)는 기기가 주는 신호로 정한다.                                                                                 |
| 안 맞는 곳  | 사용자가 계속 손으로 넘기는 피드, 오디오를 틀어 두는 것이 목적인 서비스(수면 음악 등)는 재확인이 방해가 된다.                                                                                                       |
| 시점        | 현재 도움말 기준 확인(도입 연월은 이 출처에 없다).                                                                                                                                                                  |

### SI-03 충돌 감지 — 응답이 없다는 신호를 40초 기다린 뒤 대신 전화한다

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                            |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 심각한 교통사고 직후에는 사용자가 직접 신고하지 못할 수 있다.                                                                                                                                                                                                                                                                                   |
| 해법        | 충돌을 감지하면 10초 동안 경보와 화면을 띄우고, 그동안 통화를 시작하거나 취소하지 않으면 30초 카운트다운이 이어진다. 카운트다운 끝에도 응답이 없으면 긴급 전화를 걸어 충돌과 무응답을 알리는 녹음 메시지와 추정 좌표를 보낸다. 설정에서 끌 수 있다. iPhone 14 이상에서 기본으로 켜져 있다(`reported`, S5).                                      |
| 대조        | 응답할 수 있는 사용자는 경보 화면에서 긴급 통화 슬라이더로 직접 걸 수 있다(S5). 서울시 안심이 앱은 반대로 사용자가 직접 누르거나 흔드는 호출이다(SI-06).                                                                                                                                                                                        |
| 결정적 맥락 | 위험(실수 비용): 의식이 없는 사람의 늦은 호출과 멀쩡한 사람의 잘못된 호출 중 앞쪽이 훨씬 비싸서, 자동 호출을 택하고 취소 시간을 길게 줬다는 해석은 `가정`이다. 상황(위급): 응답할 수 없는 사용자가 전제다(S5).                                                                                                                                  |
| 대가        | 오작동이 현실의 비용이 됐다. 2022년 10월 놀이공원 롤러코스터 탑승객의 폰이 충돌로 오인해 자동 신고한 사례(한 곳은 관제센터가 6건 이상 접수)가 보도됐고(S6), Apple은 심각한 충돌 감지가 매우 정확하다면서 앞으로 개선하겠다는 입장이었다(S6). 2022-11-30 업데이트에 iPhone 14 계열 「충돌 감지 최적화」가 들어갔지만 내용은 공개되지 않았다(S7). |
| 가져갈 원리 | 사용자 대신 행동하는 자동화는 「취소 창의 길이」와 「오탐이 만드는 외부 비용」을 함께 설계한다. 외부 기관을 호출하는 자동화는 끄는 설정이 반드시 있다.                                                                                                                                                                                          |
| 안 맞는 곳  | 오탐 비용을 사용자 본인이 아닌 제3자(응급 센터)가 지는 서비스에서 카운트다운만 늘리는 것은 해법이 아니다. 오탐 환경(놀이기구·스키)이 흔한 앱은 감지 조건부터 다시 본다.                                                                                                                                                                         |
| 시점        | 2022-10 오작동 보도(S6), 2022-11-30 최적화 업데이트(S7). 시간 값(10초+30초)은 Apple 지원 문서(2026-05 게시) 기준이다(S5). 같은 문서의 개요 문단은 10초 경보 없이 「30초 카운트다운 뒤 전화」라고만 적어 상세 문단과 다르다. 다른 문서의 20초 등은 직접 열지 못해 쓰지 않았다.                                                                   |

### SI-04 운전 중 메시지 — 막고 예외만 통과시키기 vs 읽어 주고 말로 답하기

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 운전 중에 메시지가 오지만 화면을 볼 수 없다.                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 해법        | 폰 쪽: 운전 집중 모드가 문자와 알림을 줄이고, 통화는 CarPlay·차량 블루투스·핸즈프리 액세서리에 연결됐을 때만 받게 한다. 사용자가 고른 대상(없음·최근·즐겨찾기·모든 연락처)에게 자동 응답이 가고, 급하면 「urgent」를 보내 통과시킬 수 있다. 움직임 감지·차량 블루투스·CarPlay 연결 중 골라 자동으로 켠다(`reported`, S8). 차 쪽: Android Auto가 메시지를 알림으로 보여 주고 읽어 주며, 음성 답장은 내용을 되읽어 준 뒤 보내기·취소·수정을 고르게 한다(`reported`, S9, S10). |
| 대조        | 두 해법의 갈림: 폰은 「오는 것을 줄이고 급한 것만 통과」, 차는 「오는 것을 소리로 바꿔 받기」. 차 쪽은 알림 기반 메시징과 규격화된 대화 템플릿으로 읽기·답하기를 제공한다(S9, S10).                                                                                                                                                                                                                                                                                         |
| 결정적 맥락 | 상황(기기·환경): 운전 중이라 눈과 손을 쓸 수 없다. 위험: 놓친 메시지가 급한 일일 수 있어 예외 통로(urgent, 허용 목록)가 필요하다(S8). 사업·플랫폼 구조(폰만 vs 차 화면 포함)가 두 해법을 갈랐다는 것은 `가정`이다.                                                                                                                                                                                                                                                          |
| 대가        | 막으면 상대는 답이 늦다는 사실을 자동 응답으로만 안다. 음성은 잘못 알아들은 답장을 보낼 위험이 있어 확인 단계를 넣는다(S9). 동승자 처리는 Apple 문서가 적지 않았다(S8). 차 화면에 메시지 본문을 숨기는지는 Android Auto 문서에 없다(S9) — `NOT_CHECKED`.                                                                                                                                                                                                                    |
| 가져갈 원리 | 사용자가 다른 일에 눈을 빼앗긴 상황에서는 「차단 + 예외 통로」와 「채널 바꾸기(눈→귀)」 중 하나를 고르고, 둘 다 되돌릴 확인 단계(자동 응답, 보내기 전 되읽기)를 둔다.                                                                                                                                                                                                                                                                                                       |
| 안 맞는 곳  | 동승자가 쓰는 화면, 주차 중, 대중교통 이용 중에는 같은 제한을 걸면 쓸 수 없는 기능이 된다(자동 켜짐 조건을 운전에 한정).                                                                                                                                                                                                                                                                                                                                                    |
| 시점        | 운전 집중 모드는 iOS 15 이후(S8). 차 화면 메시징 템플릿은 일부 베타 단계(S10).                                                                                                                                                                                                                                                                                                                                                                                              |

### SI-05 활동 지도 — 집 앞 구간을 기본으로 감춘다

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 달리기·자전거 기록을 공유하면 집·직장에서 출발하는 경로가 낯선 사람에게 노출된다.                                                                                                                                                                                                                                                                                                       |
| 해법        | 첫 활동을 올린 뒤 새 활동 지도의 처음과 마지막 200미터를 기본으로 숨긴다. 주소를 넣으면 1마일 반경(과거·미래 활동 모두)을 숨기고, 모든 활동의 시작·끝이나 지도 전체 숨기기(둘은 앞으로의 활동만)도 고를 수 있고, 겹치면 넓은 쪽이 적용된다. 활동별 편집은 기본값보다 우선한다(`reported`, S11).                                                                                         |
| 대조        | 서울시 안심이 앱은 반대로 위치를 보호자·관제센터에 보내는 것이 목적이다(SI-06). 두 서비스 모두 위치가 위험의 핵심이지만 누구에게 보이는가가 다르다.                                                                                                                                                                                                                                     |
| 결정적 맥락 | 위험(낯선 사람 간 신뢰): 공유가 가치인 서비스라 공개 범위가 넓다(해석: 한번 노출되면 되돌리기 어렵다). 2018년 1월 전 세계 활동 히트맵으로 아프가니스탄·이라크·소말리아·시리아 등의 군사 시설 위치를 알아볼 수 있다는 보도가 나왔고, Strava는 개인정보 기능을 단순하게 만들고 기능을 검토하겠다고 밝혔다(`reported`, S12). 공개 범위를 넓게 둔 서비스에서 노출이 위험으로 이어진 사례다. |
| 대가        | 숨긴 구간도 남은 정보로 추정될 수 있다. 지도 공개 설정은 활동 공개 설정을 대신하지 않고, 이 설정은 Strava 안에서만 적용된다(S11). 이 기본값이 히트맵 사건 뒤에 생겼는지는 출처에서 확인하지 못했다 — `NOT_CHECKED`.                                                                                                                                                                     |
| 가져갈 원리 | 위치가 곧 신원·주소가 되는 공유 서비스는 「공개 범위 선택」보다 앞서 「출발·도착 구간 가리기」를 기본값으로 둔다. 가리는 정도는 거리 숫자로 보여 준다.                                                                                                                                                                                                                                  |
| 안 맞는 곳  | 위치를 보여 주는 것이 핵심 가치인 서비스(실시간 이동 공유, 길 안내 동행)에서는 기본값을 감추기로 두면 목적이 사라진다.                                                                                                                                                                                                                                                                  |
| 시점        | 히트맵 사건 보도 2018-01(S12). 기본값·옵션은 현재 지원 문서 기준(S11).                                                                                                                                                                                                                                                                                                                  |

### SI-06 서울시 안심이 앱 — 밤길에는 위치를 일부러 먼저 보낸다

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 밤에 혼자 귀가하다 위협을 느끼면 폰을 제대로 조작하기 어렵다.                                                                                                                                                                                                                                                                                                                                                                                 |
| 해법        | 큰 긴급신고 버튼으로 관제센터와 연결하고, 누를 수 없을 때는 흔들어 신고한다. 일상 흔들림과 구분하려고 횟수와 세기를 조절한다. 잘못 신고하면 취소 버튼으로 취소한다. 신고는 자치구 통합관제센터로 가고 주변 CCTV를 본다(`reported`, S14). 2023-12에는 안심친구(최대 3명에게 실시간 위치 공유)와 안전시설이 많은 경로를 최대 3개 추천하는 안심경로를 더했다(`reported`, S15). 2026-03 안내 페이지에는 긴급신고·안심친구·안심경로가 나온다(S16). |
| 대조        | 운동 앱은 위치를 기본으로 감춘다(SI-05). 자동 호출은 응답 없음을 기다린 뒤 대신 건다(SI-03). 이 서비스는 사용자가 신호를 보내거나 귀가를 시작하는 순간 위치를 공유한다.                                                                                                                                                                                                                                                                       |
| 결정적 맥락 | 위험: 해석 — 본인의 신체 안전이 위치 노출 위험보다 크다고 본 설계다. 상황(위급·기기 조작 제약): 버튼을 누를 수 없을 때를 위해 흔들기 같은 보조 입력이 있다(S14). 사업(공공 서비스): 기존 CCTV 관제 인프라를 활용하고 취약계층까지 고려한다고 서울시가 밝혔다(S13).                                                                                                                                                                            |
| 대가        | 흔들기는 오작동을 막으려고 횟수·세기를 조절하는 방식이고(S14), 출시 보도자료는 앱을 실행한 상태에서 흔들면 호출된다고 설명했다(S13, S14). 2026-03 안내 페이지(S16)에는 흔들기가 나오지 않아 지금도 되는지는 확인하지 못했다. 안심친구는 앱을 켜면 등록된 보호자에게 위치가 가고 사용자가 끄는 방식이라고 보도자료가 설명한다(S15). 취소 가능 시간은 자료에 초 단위로 없다(S13, S14).                                                          |
| 가져갈 원리 | 위협 상황에서는 한 번의 큰 동작(버튼·흔들기)으로 시작하게 하고, 위치처럼 민감한 정보는 그 목적이 분명한 순간에만 보내며 누구에게 가는지 보여 준다.                                                                                                                                                                                                                                                                                            |
| 안 맞는 곳  | 위협 상황이 아닌 일상 서비스에서 흔들기 같은 숨은 입력을 쓰면 오작동만 늘린다. 위치 공유를 기본으로 켜는 방식은 보는 사람이 신뢰 관계인 경우(보호자 등록)에 한정한다.                                                                                                                                                                                                                                                                         |
| 시점        | 2017-05 출시(S13), 2018-10 25개 자치구 확대 기사(S14), 2023-12 안심친구·안심경로(S15), 2026-03 페이지 갱신(S16). 흔들기의 현재 지원 여부(`NOT_CHECKED`)와 서울 밖에서의 연결 방식은 확인하지 못했다.                                                                                                                                                                                                                                          |

| 칸          | 내용                                                                                                                                                                                                                                                                           |

| 가져갈 원리 | 사용자가 도움을 요청하기 어려운 환경에서는 이상 신호를 서비스가 먼저 감지하고, 「괜찮아요」 한 번으로 끝낼 수 있는 가벼운 확인부터 시작해 단계를 올린다.                                                                                                                       |

| 시점        | 2019-09 미국 출시(S17). 현재 미국 안전 페이지에도 RideCheck가 안내된다(S21).                                                                                                                                                                                                   |

S19는 켜짐 기본값을 적지 않았다. 긴급 통화 자동 공유는 일부 국가·지역에서만 된다(S19). 보안 문서는 이 기능을 안전과 사생활의 균형을 사용자가 정하는 선택 기능이라고 설명한다(S20).                                                                                                                                  |

## 이 파일에서 뽑은 원리

- 되돌리기 창의 길이는 서비스가 사후에 고칠 수 있는지와 후회가 얼마나 늦게 오는지로 정한다(SI-01).
- 사용자가 응답할 수 없는 상황에서 서비스가 대신 움직인다면 취소 시간과 오탐의 외부 비용을 함께 설계한다(SI-03, SI-07).
- 눈과 손을 빼앗긴 환경에서는 차단하고 예외만 통과시키거나, 눈을 귀로 바꾼다(SI-04).
- 위치·건강 같은 민감 정보는 위험의 방향(누구에게 보이나, 위급한가)에 따라 기본값이 정반대가 된다(SI-05, SI-06, SI-08).
- 상황별 기본값은 기기가 주는 신호(입력 유무, 차량 연결, 센서)로 나누고, 그 신호가 틀릴 때의 비용을 먼저 본다(SI-02, SI-04).
