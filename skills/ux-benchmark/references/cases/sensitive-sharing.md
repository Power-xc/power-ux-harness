# 맥락 사례 — 민감한 기록 공개

출처: 아래 출처 표의 공식 안내·개인정보 처리방침·도움말·규제 기관 발표와 기사. 확인일 2026-11-03. 양식과 수록 기준은 [`../casebook.md`](../casebook.md)를 따른다.

이 도메인에서 정답을 바꾸는 맥락은 위험(내용 민감도·재식별, 되돌릴 수 있는지)과 사업(콘텐츠 공급, 사업 방식)이다. 건강·신체 기록은 한 번 퍼지면 거둘 수 없고, 이름을 지워도 사진·지역·질환의 조합으로 사람을 알아볼 수 있다. 그래서 「누구에게 보이나」보다 「그 경계를 서비스가 실제로 지킬 수 있나」가 정답을 가른다. 스크립트로 그리는 도움말은 브라우저로 렌더한 본문을 읽었고 `observed`로 적었다.

## 사례

### SS-01 강한 익명은 기본값이 아니라 선택 — 잃는 것을 먼저 보인다

| 칸          | 내용                                                                                                                                                                                                                                                                                                     |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 생식 건강 기록이 법 집행 요청의 대상이 될 수 있다는 우려가 커졌다(2022년 미국 대법원 판결 뒤, S2).                                                                                                                                                                                                       |
| 해법        | 익명 모드를 고르면 이메일·계정 ID·결제·IP·광고 ID 없는 새 계정을 만들고 건강 기록만 옮긴 뒤 원래 계정을 지운다. 다시 잇거나 되살릴 수 없다. 전환 전에 못 쓰게 되는 구독·연동·이메일과 지원팀이 도울 수 없는 일(내보내기·삭제·복구)을 목록으로 보이고, 막히는 경우마다 푸는 법을 적는다 (`observed`, S1). |
| 대조        | 기본값이어야 한다는 비판이 있었고, 기기를 압수당하면 소용없어 「완전한 익명」은 과장이라는 지적도 나왔다 (`reported`, S2).                                                                                                                                                                               |
| 결정적 맥락 | R5 내용 민감도와 R2 되돌릴 수 있는지 — 강한 보호의 대가가 복구 불가와 함께 쓰는 기능의 상실이라 모두에게 기본으로 걸 수 없었다. 서비스는 기기를 잃으면 기록을 되살릴 수 없기 때문에 기본값이 아닌 선택으로 둔다고 스스로 밝혔다 (S1).                                                                    |
| 대가        | 복구·계정 지원·가족·파트너 공유·웨어러블 연동을 잃는다 (S1). 가장 위험한 사용자가 켜지 않을 수 있다(`hypothesis`).                                                                                                                                                                                       |
| 가져갈 원리 | 대가가 큰 강한 보호는 기본값 대신 선택으로 두되, 잃는 것과 기본값이 아닌 이유를 전환 전에 밝힌다.                                                                                                                                                                                                        |
| 안 맞는 곳  | 공개 범위를 좁히는 것처럼 대가가 작은 보호 — 이런 것은 기본값으로 건다.                                                                                                                                                                                                                                  |
| 시점        | 2022-09 출시 (S2), 현재 안내는 2026-11-03 확인 (S1)                                                                                                                                                                                                                                                      |

### SS-02 지정한 사람에게만 — 지킬 수 있는 만큼만 「지워진다」고 약속한다

| 칸          | 내용                                                                                                                                                                                                                                                                                                                               |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 건강 데이터와 알림을 가족·간병인에게 보여 주고 싶다.                                                                                                                                                                                                                                                                               |
| 해법        | 연락처에서 받는 사람을 먼저 고르고, 「제안된 주제 보기」나 「수동 설정」으로 공유할 주제를 고른다. 공유한 데이터는 언제든 다시 보고 바꾼다 (`observed`, S3). 공유를 멈추면 상대 기기에서 공유했던 과거 데이터가 지워지고, 의료 기관에 보낸 정보는 멈추기 전까지 보낸 만큼 기관 기록에 남을 수 있다고 따로 적는다 (`observed`, S4). |
| 대조        | 누구나 가입하는 커뮤니티에 올리는 공개(SS-03) — 거기서는 서비스가 철회를 지킬 수 없다.                                                                                                                                                                                                                                             |
| 결정적 맥락 | R5 내용 민감도 — 받는 사람이 같은 생태계 안의 지정된 사람이라 철회를 기기에서 집행할 수 있다. 집행할 수 없는 범위(의료 기관의 기록)는 약속하지 않고 밝힌다.                                                                                                                                                                        |
| 대가        | 받는 사람 → 주제 → 여러 화면 → 공유 → 완료로 단계가 길다 (S3). 여러 사람에게 한 번에 공개하는 방법은 없다.                                                                                                                                                                                                                         |
| 가져갈 원리 | 「멈추면 지워진다」는 서비스가 기술로 집행할 수 있는 범위에서만 약속하고, 지울 수 없는 곳은 따로 알린다.                                                                                                                                                                                                                           |
| 안 맞는 곳  | 받는 사람이 서비스 밖에 있거나 캡처할 수 있는 공개 공유 — 같은 약속을 하면 거짓이 된다.                                                                                                                                                                                                                                            |
| 시점        | 개인정보 안내 2026-10-30 (S4)                                                                                                                                                                                                                                                                                                      |

### SS-03 「회원만 보기」는 경계가 아니다 — 누구나 가입하는 환자 커뮤니티

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 상황        | 환자들이 진단·증상·치료 경험을 서로 나눈다.                                                                                                                                                                                                                                                                                                                        |
| 해법        | 공개(비회원까지)·커뮤니티(로그인한 회원)·개인(다른 회원에게 숨김) 세 단계를 둔다. 공개 프로필은 검색엔진에 색인될 수 있고 나중에 좁혀도 검색 결과에 남을 수 있다고, 드문 질환·성별·지역의 조합만으로도 알아볼 수 있다고 정책에 적는다 (`observed`, S5). 도움말은 누구나 가입할 수 있으니 회원끼리라도 실명·연락처를 쓰지 말라고 하고 (S6), 수익원을 나열한다 (S7). |
| 대조        | 지정한 사람에게만 보이고 철회를 집행할 수 있는 공유(SS-02).                                                                                                                                                                                                                                                                                                        |
| 결정적 맥락 | B5 콘텐츠 공급 — 가입이 쉬워 회원 경계가 실제 경계가 아니다. R5 재식별 — 드문 질환은 조합만으로 사람을 가리킨다. B2 사업 방식 — 비식별·집계 데이터를 연구·제약·보험 파트너와 나누고 일부는 판다 (S5).                                                                                                                                                              |
| 대가        | 사용자 기록이 비식별 형태로 파트너에게 간다 (S5). 공개 단계의 위험을 정책 문서로만 알린다(화면 안내는 `NOT_CHECKED`).                                                                                                                                                                                                                                              |
| 가져갈 원리 | 가입 문턱이 낮은 곳에서는 「회원 공개」를 보호 단계로 세지 않고, 공개 단계마다 검색 노출과 조합 재식별을 밝힌다.                                                                                                                                                                                                                                                   |
| 안 맞는 곳  | 신원 확인을 거친 폐쇄 집단 — 회원 경계가 실제로 작동할 수 있다.                                                                                                                                                                                                                                                                                                    |
| 시점        | 정책 2025-10-11 시행 (S5)                                                                                                                                                                                                                                                                                                                                          |

### SS-04 반례 — 참여자끼리의 공개가 계정 하나를 넘어 수백 배로 번졌다

| 칸            | 내용                                                                                                                                                                                                                                                                                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 무엇을 했나   | 유전 친척 찾기는 선택 참여다. 참여하면 다른 참여자에게 표시 이름·예상 관계·공유 DNA 비율이 보이고, 위치·출생연도·사진·조상 정보는 따로 골라 공개한다 (`observed`, S8).                                                                                                                                                                                     |
| 무엇이 터졌나 | 재사용 비밀번호로 계정 약 0.1%가 뚫렸고, 그 계정들에서 친척 찾기를 통해 약 690만 명의 프로필(이름·출생연도·우편번호·가족 관계 등)이 조회됐다 (`reported`, S9). 영국 ICO는 2025-06-17 £231만 과징금을 매겼다 — 다중 인증 의무 없음, 약한 비밀번호 규칙, 원시 유전 데이터 접근에 추가 확인 없음, 위협 탐지와 대응의 늦음 (`observed`, S10, 효과 근거 1단계). |
| 왜 터졌나     | 연결이 가치인 기능이라 「참여자끼리」 범위가 계정 하나의 침해를 수백 배로 키웠다(B5·R5). 민감도에 맞는 인증 장치가 없었다(R3, S10).                                                                                                                                                                                                                        |
| 우리의 금지선 | 회원·참여자 사이의 공개를 보호 경계로 세지 않는다. 다른 사람의 정보까지 보이게 하는 연결 기능에는 강한 인증을 기본으로 건다.                                                                                                                                                                                                                               |
| 시점          | 침해 2023-04~09, 보도 2023-12 (S9), 제재 2025-06 (S10)                                                                                                                                                                                                                                                                                                     |

### SS-05 광고로 버는 커뮤니티의 병원 글 — 금지 대신 표시와 몰아주기 차단

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                           |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 탈모 당사자 커뮤니티의 모발이식 사진 후기. 병원 광고가 수익원이라 병원이 쓴 글이 섞인다.                                                                                                                                                                                                                                                                       |
| 해법        | 병원이 직접 올리는 사례는 제목을 「@병원명」으로 쓰게 하고, 병원의 지원·편의가 글에 영향을 줄 수 있으니 참고로만 쓰라고 알린다 (`observed`, S11). 같은 병원 후기가 여러 아이디로 연속 세 개 올라오면 도배로 지우고, 가입하자마자 특정 병원을 추천·비방하면 신고 즉시 가리고 아이디를 막는다 (`observed`, S12). 실패 후기 게시판을 따로 둔다 (`observed`, S13). |
| 대조        | 병원 글 전면 금지(정보량과 수익을 함께 잃음)나 무표시(광고 구분 표시 위반 소지 — `ux-dark-patterns`의 광고 구분 점검).                                                                                                                                                                                                                                         |
| 결정적 맥락 | B2 사업 방식 — 광고 수익이라 전면 금지가 어렵다. R5 내용 민감도 — 신체 사진이라 실패 경험이 묻히면 피해가 크다. B5 콘텐츠 공급 — 오래된 커뮤니티라 몰아주기를 제보할 회원이 많다(`hypothesis`).                                                                                                                                                                |
| 대가        | 표시는 병원이 직접 쓴 글에만 걸리고, 지원을 받은 회원 글은 스스로 밝히지 않으면 구분되지 않아 고지로 대신한다 (S11). 규칙이 2013년 공지 그대로이고 제보·삭제에 운영 인력이 든다(`hypothesis`).                                                                                                                                                                 |
| 가져갈 원리 | 광고로 버는 커뮤니티는 광고성 글을 금지하기보다 표시를 의무로 하고, 몰아주기 패턴(연속 게시·갓 가입한 계정)을 규칙으로 막고, 실패 경험이 묻히지 않을 자리를 따로 둔다.                                                                                                                                                                                         |
| 안 맞는 곳  | 병원이 쓰는 치료 경험담은 의료광고 제한과 겹칠 수 있다 — 공지도 의료법이 허용하는 범위에서만 허용한다고 적는다 (S11). 옮기기 전에 법무 확인이 필요하다.                                                                                                                                                                                                        |
| 시점        | 공지 2013-01-07, 상단 고정 2026-11-03 확인 (S11)                                                                                                                                                                                                                                                                                                               |
