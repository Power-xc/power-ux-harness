# 맥락 사례 — 돈·신뢰

돈이 걸린 화면에서는 같은 기능도 정답이 바뀐다. 이 파일에서 정답을 바꾸는 맥락 칸은 위험(실수 비용 · 되돌릴 수 있는지 · 낯선 사람 간 신뢰 · 규제)이고, 이 위험을 키우거나 줄이는 사용자 칸(연령 · 충동적인 순간의 감정 상태 · 미성년)이 뒤따른다. 사례마다 무엇을 했는지보다 왜 그 맥락에서 맞았는지를 먼저 읽는다. 양식과 수록 기준은 [`../casebook.md`](../casebook.md)를 따른다.

모든 사례는 화면을 직접 보지 않고 공식 문서·정책·규제 기관 자료·기사로 확인했으므로 근거 수준은 `reported`다. 확인일은 2026-11-02이고(출처를 모두 다시 열어 대조했다), 서비스는 바뀌므로 인용 전에 지금도 그런지 다시 확인한다. 숫자는 출처 문서에 적힌 값만 썼다. 출처가 언론뿐인 사실은 「언론」으로 따로 적었고, 출처에 없는 작성자의 판단은 「해석:」으로 표시했다. 「가져갈 원리」와 「안 맞는 곳」은 작성자의 제안이다.

### MT-01 ★ 같은 완료 축하라도 돈이 걸리면 오답이 된다

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 첫 거래·입금 같은 순간에 완료 축하 연출을 보여 줄지 정해야 한다.                                                                                                                                                                                                                                                                                                                                                     |
| 해법        | Robinhood — 첫 거래 뒤 화면 위에서 쏟아지던 색종이를 2021-03-31 기준으로 거두고, 첫 거래 화면에는 다른 이미지를 넣었다(`reported`, S1, S2). 2024-01 합의서는 매사추세츠 고객에게 그 색종이와 거래 빈도에 직접 이어진 다른 축하 이미지를 앞으로 쓰지 않도록 했다(S2). 색종이가 적힌 사실관계 부분에 대해 회사는 인정도 부인도 하지 않았다(S2).                                                                        |
| 대조        | Asana — 업무 도구라서 작업을 끝내면 가끔 축하 연출(유니콘 같은 캐릭터)이 나오고, 사용자가 프로필 설정의 화면 탭에서 켜고 끌 수 있다(`reported`, S3, S4). 설정 위치는 2016년 글과 2018년 운영진 답변이 같고, 현재 기본값은 확인하지 못했다. 이후 커뮤니티 글에는 어떤 설정이 어떤 연출을 끄는지 엇갈려 적혀 있어 현재 화면에서 다시 확인해야 한다.                                                                    |
| 결정적 맥락 | 위험(실수 비용 · 규제) + 사용자(초보 투자자). 출처로 확인되는 것: 당국이 투자 앱의 게임화 전략을 비판했고(S1), 합의서는 색종이를 매사추세츠 고객 보호를 위한 감독 절차 없이 만든 디지털 참여 장치의 하나로 열거하며 거래 빈도와 직접 이어진 축하 이미지를 금지 대상으로 적었다(S2). 해석: 작업 완료 축하는 더 해도 잃을 것이 없지만, 거래 완료 축하는 거래를 한 번 더 하게 만드는 보상으로 읽힐 수 있어 문제가 됐다. |
| 대가        | 회사는 색종이를 오랫동안 시장에서 소외됐던 신규 투자자를 향한 긍정적 강화로 설명했고, 비판이 그 취지에서 주의를 흩뜨린다고 밝혔다(S1). 격려와 첫 경험의 감정적 보상을 포기했다. 첫 거래 화면의 대체 이미지는 이미지로만 알려졌고 세부는 확인하지 못했다(S1).                                                                                                                                                         |
| 가져갈 원리 | 완료 축하는 그 행동을 더 하게 만들어도 괜찮을 때만 쓴다. 돈이나 위험이 걸린 행동의 완료 화면은 결과를 중립적으로 보여 준다.                                                                                                                                                                                                                                                                                          |
| 안 맞는 곳  | 돈과 위험이 걸리지 않은 작업·학습 완료(S3의 업무 도구처럼). 이 경우는 오히려 축하가 완수의 보상이 된다.                                                                                                                                                                                                                                                                                                              |
| 시점        | 2021-03-31 중단(S1, S2). 2024-01 합의서로 매사추세츠 고객 대상 영구 중단(S2) — 회사의 합의 제안은 2024-01-17이고 합의서 날짜의 일(日)은 PDF에 비어 있다. 합의 효력은 매사추세츠 고객에 한정된다.                                                                                                                                                                                                                     |

### MT-02 ★ 받는 사람 이름을 은행이 대조해 알려 주는 나라와, 화면에 보여 주고 사람이 대조하게 하는 나라

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 처음 보내는 계좌로 송금할 때 계좌번호를 잘못 넣었거나 사기 계좌인 경우.                                                                                                                                                                                                                                                                                                                                                                                               |
| 해법        | 영국 Confirmation of Payee — 새 수취인으로 보낼 때 보내는 사람이 이름과 계좌 유형(개인·법인)을 입력하면 받는 계좌 정보와 대조해 결과를 알려 준다. 결과는 일치, 비슷함, 불일치, 확인 불가로 나뉜다. 비슷함이면 제시된 이름이나 계좌 유형이 맞는지 확인하게 하고, 불일치면 입력을 다시 확인한 뒤 상대에게 직접 계좌 정보를 확인하라고 안내하며 그래도 이상하면 사기일 수 있다고 알린다(`reported`, S7).                                                                 |
| 대조        | 한국 계좌 이체 — 금융위원회가 은행 앱 모범 사례로 제시한 화면은 입력한 계좌의 예금주명과 금액 확인창, 이체 직전 계좌번호·예금주·금액 재확인창이다(`reported`, S8). 이름을 보여 주고 사람이 맞는지 판단한다. S8은 보내는 사람이 이름을 직접 입력하는지는 적지 않았다.                                                                                                                                                                                                  |
| 결정적 맥락 | 규제 + 위험. 영국은 규제 기관이 2019-08 지시로 대형 6개 은행 그룹에 의무를 걸었고(S5), 2022-10에 400곳 가까운 업체로 넓혔다(S6). S6은 이 도구를 속아서 보내는 사기(APP fraud)를 막는 장치로 소개한다. 한국 문서는 2021-07 이후 예금보험공사에 접수된 착오송금 14,717건 가운데 계좌번호를 잘못 입력한 경우가 66.8%, 최근 이체 목록에서 잘못 고른 경우가 28.3%라며 입력 실수를 주된 원인으로 본다(S8). 해석: 막으려는 위험이 사기냐 실수냐에 따라 장치의 모양이 다르다. |
| 대가        | 영국: 대조 결과가 나오려면 받는 은행도 참여해야 해서 지원하지 않는 은행이나 옵트아웃한 계좌는 확인 불가로 남는다(S7). 보내는 사람이 상대의 이름과 계좌 유형을 입력해야 한다(S7). 한국: S8은 거래가 많은 10개 금융회사에 개선을 요청하고 다른 196개사에 전파·협조를 당부한 모범 사례이며 구속력 있는 의무가 아니다. 모든 앱이 같은 화면을 갖는지는 문서에서 확인되지 않는다.                                                                                           |
| 가져갈 원리 | 되돌리기 어려운 이체 직전에는 사람의 눈에만 맡기지 않는다. 사용자가 아는 정보와 실제 계좌 정보를 시스템이 대조해 일치·비슷함·불일치로 나눠 알린다.                                                                                                                                                                                                                                                                                                                    |
| 안 맞는 곳  | 상대 이름을 정확히 모르는 소액 일회성 송금, 참여 금융사가 적어 확인 불가가 일상인 환경(확인 불가가 흔하면 경고가 무뎌질 수 있다는 점은 `hypothesis`).                                                                                                                                                                                                                                                                                                                 |
| 시점        | 영국: 2019-08 지시, 2020-07 시점에 지시 대상 6개 그룹 모두의 구성원이 적용(S5), 2022-10 400곳 가까운 업체에 지시, 2024-10 기준 Faster Payments·CHAPS 거래의 99% 넘게 적용(S6). 한국: 2024-05 모범 사례 공유(S8).                                                                                                                                                                                                                                                      |

### MT-03 되돌릴 수 없는 송금에 제도 차원의 복구 경로를 둔다

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                      |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 계좌번호를 잘못 넣어 엉뚱한 사람에게 간 돈을 돌려받아야 한다.                                                                                                                                                                                                                                                                                             |
| 해법        | 한국 예금보험공사 착오송금 반환지원 — 먼저 금융회사를 통해 받은 사람에게 자진반환을 요청하고, 안 되면 예금보험공사에 신청한다. 공사가 수취인 정보를 확인한 뒤 자진반환 안내나 지급명령을 진행한다(`reported`, S9). 시행 당시 대상은 5만원\~1,000만원, 신청은 착오송금일로부터 1년 이내였고(S9), 현재 규정은 건당 5만원\~1억원이며 같은 1년 기한이다(S10). |
| 대조        | 제도 이전에는 송금인이 소송을 거쳐야 했고, 시간과 비용 부담 때문에 소액은 포기하는 경우가 많았다(S9). 같은 문제를 예방으로 푸는 방식이 MT-02다.                                                                                                                                                                                                           |
| 결정적 맥락 | 위험 — 되돌릴 수 있는지 · 실수 비용. 송금은 받은 사람이 돌려주지 않으면 개인이 소송으로 풀어야 하는데, 소송 비용이 금액보다 크면 사실상 되돌릴 수 없다(S9). 이 간극을 공공 기관이 메우는 규제 해법이다.                                                                                                                                                   |
| 대가        | 회수 비용(우편 안내비, 지급명령 인지대·송달료, 인건비 등)이 회수 금액에서 빠진다. 시행 당시 안내로 10만원 기준 예상 지급률은 자진반환 86%, 지급명령 82%이고, 반환은 신청 접수일로부터 대략 1\~2개월 걸리며 강제집행이 필요하면 더 걸린다(S9). 수취인이 간편송금 계정이거나 수취인이 사망한 경우, 송금인이 이미 소송 중인 경우는 제외된다(S9).             |
| 가져갈 원리 | 제품이 되돌릴 수 없는 실수는 제도의 복구 경로로 곧바로 이어 주고, 걸리는 시간과 공제되는 비용을 미리 알린다.                                                                                                                                                                                                                                              |
| 안 맞는 곳  | 5만원 미만 소액, 착오송금 후 1년이 지난 건, 수취인이 간편송금 계정인 건(S9). 규정상 수취 계좌가 보이스피싱 등 범죄에 쓰인 것으로 의심되면 제외된다(S10).                                                                                                                                                                                                  |
| 시점        | 2021-07-06 시행(S9). 금액 기준은 2023-01-01, 2024-01-01, 2025-01-01 시행 개정을 거쳐 현재 상한 1억원이다(S10). 중간 금액은 출처에서 확인하지 못했다.                                                                                                                                                                                                      |

### MT-04 지연이체 — 되돌릴 시간을 만드는 설계

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                 |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 전화나 메신저에 속아 직접 이체했거나, 계좌번호·금액을 잘못 넣은 경우.                                                                                                                                                                                                                                                                                |
| 해법        | 국내 은행 지연이체 — 신청한 고객은 이체를 눌러도 일정 시간이 지나야 받는 계좌에 들어가고, 그 전에 취소할 수 있다. 금융위원회 문답은 최소 3시간, 입금 30분 전까지 취소 가능으로 설명한다(`reported`, S11). KB국민은행은 3시간이나 5시간 중 직접 고르고, 앱·홈페이지·지점에서 신청하며, 지정 시간이 끝나기 30분 전까지 취소할 수 있다고 안내한다(S12). |
| 대조        | 지연이 없는 즉시이체 — 신청하지 않은 고객의 기본이다(S12는 신청 방식으로 안내). 같은 문제를 받는 쪽에서 늦추는 방식으로 1회 100만원 이상이 입금되면 30분 동안 자동화기기(ATM 등)의 인출·이체를 지연하는 지연인출도 있고, 창구에서는 즉시 가능하다(S13).                                                                                              |
| 결정적 맥락 | 위험 — 되돌릴 수 있는지. 해석: 즉시이체는 누르는 순간 확정이라 속았다는 걸 알아챈 뒤에는 늦고, 시간 창을 만들면 알아챌 틈이 생긴다. 출처로 확인되는 설계는 위험을 스스로 느낀 고객이 신청해서 켜는 옵션이라는 점이다(S12).                                                                                                                           |
| 대가        | 급한 이체가 늦어진다. 그래서 KB는 본인 계좌와 미리 등록한 계좌는 즉시 이체하고, 즉시이체 가능 금액을 따로 정하면(100만원 이내) 그 한도 안에서도 즉시 이체한다(S12). KB 기준으로 해지는 지점에서만 가능하다(S12). 지연 시간과 세부 조건은 은행마다 다르다(S11의 3시간 최소, S12의 3시간·5시간 선택).                                                  |
| 가져갈 원리 | 되돌릴 수 없는 이체에는 취소할 수 있는 시간 창을 만든다. 마찰은 위험을 느낀 사람이 직접 켜게 하고, 급한 이체를 위한 예외를 함께 설계한다.                                                                                                                                                                                                            |
| 안 맞는 곳  | 즉시성이 약속인 흐름(상거래 결제, 정산 즉시 반영이 필요한 송금). 해석.                                                                                                                                                                                                                                                                               |
| 시점        | 은행권 시행 2015-10-16(언론, 메트로신문 2015-10-04 보도, S35 — 이용자 선택에 따라 이체 효력을 늦추게 한 개정 전자금융거래법에 따른 도입). 금융위원회 문답 2022-09-29(S11).                                                                                                                                                                           |

### MT-05 고령 고객: 나이로 막지 않고 본인이 고른 가족에게 알린다

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 고령 고객이 본인에게 맞지 않을 수 있는 위험 상품에 가입하거나, 창구에서 큰 현금을 인출하려는 경우.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 해법        | 고령자 지정인 알림 — 65세 이상 개인이 원할 때만, 종신·CI·변액보험과 ELS·DLS 같은 파생결합증권 등에 가입하면 본인이 지명하고 동의받은 지정인 1인에게 가입 사실을 문자로 알린다. 지정인 정보는 성명·관계·휴대폰 번호로 줄이고, 지정인과 상의해 상품이 맞지 않다고 판단하면 청약 철회 같은 조치를 하도록 돕는다. 대면 가입이 우선이고 인터넷 가입은 제외 대상이 많다(변액보험·파생결합증권은 인터넷 채널 제외). 월 보험료 5만원 이하 소액 계약과 전문투자자는 제외한다(`reported`, S14).                                                                                                                                   |
| 대조        | 창구 문진 — 금융감독원 보도자료(2022-08-25)는 2022-09-01부터 은행권에서 500만원 이상 고액 현금 인출 때 성별·연령 등 고객 특성에 맞춘 문진을 하고, 1천만원 이상이면 영업점 책임자가 용도와 피해 예방 사항을 최종 확인하며, 60대 이상에게는 직원이 인출 목적 등을 직접 묻는다고 밝혔다(`reported`, S31). 세부 항목인 40\~50대 남성 대출 빙자형·60대 이상 여성 가족·지인 사칭형 문진표와 통화 여부·앱 설치 여부 질문은 언론 보도(파이낸셜뉴스)에만 있다(S15). 2025-10 정책기자단 기사는 창구에서 고액 인출·이체 때 문진표 작성과 예방 영상 시청을 전 은행권이 공동 시행한다고 소개한다(금액·연령 기준은 기사에 없음, S16). |
| 결정적 맥락 | 사용자(연령 · 판단을 도울 사람의 필요) + 위험(부적합 상품의 실수 비용, 되돌릴 수 있는지). 가입 후에도 청약 철회로 되돌릴 시간이 있다는 점이 알림의 근거다(S14). 이 사례의 대상은 상품 가입이다.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 대가        | 가족에게 알리는 일은 사생활 침해가 될 수 있어 본인 희망, 지정인 동의, 정보 최소화를 모두 걸었다(S14). 인터넷 판매는 제외 대상이 많아 온라인 가입자는 보호 밖이 될 수 있다(S14). 해석: 문진을 연령·성별로 나누면 질문이 고정관념이 될 위험이 있다. 반면 통화 중인지, 앱을 깔았는지 묻는 항목은 속도를 늦추는 행동 신호라 연령 없이도 적용할 수 있다(`hypothesis`).                                                                                                                                                                                                                                                       |
| 가져갈 원리 | 나이를 이유로 기능을 막지 않는다. 본인이 고른 보호자에게 알리거나, 사기 신호(통화 중, 앱 설치)를 사람이 묻게 한다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 안 맞는 곳  | 본인 동의 없이 보호자에게 알리는 설계, 연령만으로 한도나 기능을 제한하는 설계.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 시점        | 2019-06-28 보도자료(게시 2019-07-01)에서 2019-10부터 제공 예정으로 발표(S14) — 실제 제공 여부와 현황은 확인하지 못했다. 창구 문진은 2022-08-25 발표, 2022-09-01 은행권 우선 시행(S31), 2025-10 재소개(S16). 은행별 기준은 다를 수 있다.                                                                                                                                                                                                                                                                                                                                                                                 |

### MT-06 같은 송금 앱도 기본 공개 범위는 상대와 사용자에 따라 다르다

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 송금 내역을 누가 볼 수 있는지 정해야 한다. 특히 모르는 사람에게 노출되는 범위.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 해법        | Venmo — 2021-07 앱을 개편하며 낯선 사람의 결제를 보여 주던 전체 공개 피드를 없앴다(`reported`, S18). 일반 송금의 초기 기본값은 공식 법적 안내에 공개로 적혀 있다(S19, 날짜 미표기). 반면 Venmo 직불·신용카드 구매와 승인된 가맹점 구매는 기본 비공개이고(S20), 10대 계정은 거래가 기본 비공개이며 부모나 보호자만 바꿀 수 있다(S21). 두 사람의 설정이 다르면 더 제한적인 쪽을 따른다(S20). 2026-05-11 Engadget은 개편 앱이 새 사용자의 게시물 기본값을 친구만으로 정한다고 보도했지만 기존 사용자 적용 여부는 밝히지 않았고(언론, S34), 공식 문서 S19는 아직 공개로 적혀 있어 서로 어긋난다. |
| 대조        | 같은 서비스의 이전 방식 — 2018-02 FTC는 거래가 기본으로 피드에 올라가고, 비공개로 하려면 두 설정을 바꿔야 하며, 상대방이 비공개 거래를 공개로 바꿀 수 있었다는 점을 문제 삼았다(S17).                                                                                                                                                                                                                                                                                                                                                                                                        |
| 결정적 맥락 | 위험(낯선 사람에게 노출 · 규제) + 사용자(미성년). 친구끼리 결제를 공유하는 것이 제품의 성격이라 공개를 전부 닫지는 못하고, 노출이 가치가 없는 맥락(상점 구매, 10대)만 기본값을 비공개로 바꿨다. 해석: 소셜 결제가 사업 핵심이라 공개를 전부 닫지 못했다(`hypothesis`).                                                                                                                                                                                                                                                                                                                       |
| 대가        | EFF는 전체 피드를 없앤 걸 환영하면서도, 공개 설정이면 프로필 페이지와 공개 API로 활동이 노출되고 거래와 친구 목록의 기본값도 여전히 공개라고 지적했다(S18). 연락처 자동 동기화로 선택하지 않은 사람이 친구 목록에 들어오는 문제도 지적했다(S18). FTC 합의는 설정이 주는 통제 범위를 오해하게 하지 못하게 하고 고지를 요구한다(S17).                                                                                                                                                                                                                                                          |
| 가져갈 원리 | 공개 범위의 기본값은 상대와 사용자 맥락별로 정한다. 낯선 사람에게 닿는 범위부터 닫고, 한쪽만 바꿔서는 비공개가 되지 않는 설정 둘을 두지 않는다.                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 안 맞는 곳  | 공개 노출 자체가 사용 이유인 서비스(`hypothesis`). 비공개 하나를 켜는 데 설정이 둘 필요한 설계는 어디서도 맞지 않는다(S17).                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 시점        | 2018-02 FTC 발표(S17), 2021-07 전체 피드 제거(S18), 2026-05 새 사용자 기본값 변경 보도(언론, S34). 현재 기본값은 S19·S20·S21이 가리키는 공식 문서 기준이며 S19는 날짜가 없고 새 앱 개편 안내 배너가 붙어 있어 앱에서 다시 확인해야 한다.                                                                                                                                                                                                                                                                                                                                                     |

### MT-07 도박 차단: 켜는 건 한 번에, 끄는 건 기다려서

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                  |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 도박 결제를 스스로 막아 둔 고객이 충동이 들어 그 차단을 풀려는 경우.                                                                                                                                                                                                                                                                                  |
| 해법        | Monzo — 도박 업종 코드가 붙은 가맹점의 카드 결제를 막는다. 켤 때 대기 기간을 2일\~1년 중 고르고, 대기 기간이 지나야 설정을 바꿀 수 있다. 대기 중에는 바꿀 수 없다(`reported`, S22). 2023-09에 대기 기간을 최대 1년까지 길렸고, 켠 이유를 미래의 자신에게 남기는 메모를 대기 시작과 종료 때 보여 주며, 도박 피해를 말한 고객은 전담팀으로 잇는다(S23). |
| 대조        | Barclays — 2020-09 도박 차단을 껐다가 다시 켜는 순간부터 도박 결제를 72시간 동안 막는 방식을 도입했다. 그 사이 시도는 자동 거절한다. 영국 대형 은행 중 이 길이의 대기를 처음 도입했다고 밝혔다(`reported`, S24). 대기 시간이 은행이 정한 고정값이다. Monzo는 사용자가 정한다. S24는 2020년 발표이고 현재 Barclays 안내가 같은지는 확인하지 못했다.    |
| 결정적 맥락 | 사용자(충동적인 순간의 감정 상태) + 위험(한번 쓰면 못 돌리는 돈). Monzo는 도박 결정이 충동적인 경우가 많아 마찰이 생각할 기회를 준다고 설명한다(S23). 해석: 켜는 쪽은 쉽게, 푸는 쪽만 느리게 해서 미래의 자신을 보호하는 설계다.                                                                                                                      |
| 대가        | 정당한 필요가 생겨도 기다려야 한다. 업종 코드가 잘못 붙은 도박 결제는 통과하고, 고객이 알리면 가맹점을 추가하는 방식이다(S22). 이전에 도박 문제로 상담한 고객은 끄려면 먼저 직원에게 메시지를 보내 질문에 답해야 한다(S22).                                                                                                                           |
| 가져갈 원리 | 자기 통제를 돕는 설정은 켜기는 쉽게, 끄기는 느리게 만든다. 기다리는 시간은 사용자가 정하게 하고, 켠 이유를 풀 때 다시 보여 준다.                                                                                                                                                                                                                      |
| 안 맞는 곳  | 해석: 사용자가 스스로 건 제약이 아닌 곳(강제 지연은 기만이 된다), 긴급 접근이 필요한 결제·안전 기능.                                                                                                                                                                                                                                                  |
| 시점        | 2020-09 Barclays 72시간(S24), 2023-09 Monzo 최대 1년과 메모(S23), 현재 대기 선택 범위는 S22 기준. S22(켤 때 선택)와 S23(다시 허용하기까지 최대 1년)의 표현이 달라 최신 페이지인 S22를 따랐다.                                                                                                                                                         |

### MT-08 중고거래 에스크로: 직거래 중심은 선택, 먼 동네 택배와 e쿠폰은 안심결제에 묶었다

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 서로 모르는 사람에게 돈을 먼저 보내고 물건을 받아야 하는 거래.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 해법        | 당근 안심결제 — 구매자 결제 대금을 맡아 두었다가 물건을 받고 구매를 확정하면 판매자에게 준다. 2024-10 도입 때는 선택 옵션이었고 서울 서초·강남·송파·동작·강동구에서 우선 시행해 연내 전국 확대를 예고했으며, 당근머니·계좌 송금도 그대로 썼다(`reported`, S25). 안심보상은 구매확정일로부터 15일 이내 접수하면 건당 최대 195만원으로 발표됐고(S26), 현재 고객센터는 최대 190만원으로 안내한다(S33). 2025-06에는 거래 완료를 누른 뒤에도 정산을 멈출 수 있는 구매확정 미루기를 시범 운영했다고 언론 한 곳이 보도했다. 기프티콘처럼 쓰기 전에는 진위를 알기 어려운 상품이 주 대상이다(언론, S27). 고객센터에는 이 이름의 안내가 없고, 택배 거래에서 배송 완료 후 48시간이 지나면 자동 구매확정되며 구매자가 「물품에 문제가 있어요」로 이를 잠시 보류할 수 있다는 안내가 있다(S33). 2026-01부터 e쿠폰 거래는 안심결제를 기본으로 하는 바로구매로 운영하고, 구매자가 쿠폰 유효성을 확인한 뒤 48시간 안에 구매를 확정하면 거래가 끝난다(S28). 고객센터는 구매 후 48시간이 지나면 자동으로 구매가 확정된다고 안내하고, 직거래가 불가능한 먼 동네 물품은 바로구매(안심결제)로만 거래할 수 있다고 적는다(S33). |
| 대조        | 번개장터 — 이용약관(2026-08-05 시행판)이 구매확정 전까지 대금 정산을 보류할 수 있게 하고, 사기 의심 같은 사유는 구매확정과 무관하게 보류한다. 회사가 제공하지 않은 방법의 결제·정산 시도는 이용 제한 사유다. 직거래도 구매자가 검수한 뒤 구매확정을 해야 한다(`reported`, S29).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 결정적 맥락 | 위험(낯선 사람 간 신뢰 · 되돌릴 수 있는지) + 사업 방식(직거래 중심이냐 비대면이냐). 당근은 중고거래가 대부분 직거래라서 결제 보호를 선택 옵션으로 두었다(S25). 2026-01 보도자료는 이미 쓴 쿠폰이 거래되거나 쿠폰 정보가 변조되는 악용 가능성을 막으려고 e쿠폰에 안심결제를 기본으로 했다고 밝혔고(S28), 구매확정 미루기는 쓰기 전에는 진위를 알기 어려운 상품이 대상이라고 보도됐다(S27). 해석: 비대면·진위 불명 상품일수록 에스크로를 선택에서 기본으로 올렸다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 대가        | 구매자 수수료가 든다. 2024-10 도입 때는 거래 금액의 2%였고(S25), 2026-01에는 e쿠폰 바로구매 3.3%를 2.2%로 한시 인하한다고 밝혔다(기간 미표기, S28). 현재 고객센터는 구매자 보호 수수료를 거래 금액의 3.3%로 안내하고 상황에 따라 할인이 적용될 수 있다고 적는다(S33). 정상 판매자의 정산이 늦어지는 불편이 남은 과제로 보도됐고(S27), 구매확정 미루기의 가능 시간은 악용을 막으려고 공개하지 않는다(S27).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 가져갈 원리 | 선결제가 필요한 거래는 돈을 중간에 맡겼다가 확인한 뒤 푼다. 확인할 수 없는 상품에는 확정 뒤에도 멈출 수 있는 장치와 사후 보상을 더한다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 안 맞는 곳  | 서로 아는 사이의 거래, 즉시 정산이 약속인 소액 상거래.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 시점        | 2024-10 도입(S25) → 2025-03 보상(S26) → 2025-06 미루기 시범(언론, S27) → 2026-01 e쿠폰 기본 적용(S28). 2026-11-02 확인한 고객센터(S33)는 수수료 3.3%, 안심보상 최대 190만원이다. 번개장터는 S29의 시행판 기준이며 도입 연월은 확인하지 못했다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

### MT-09 동네 인증: 거래 범위를 좁혀 낯선 사람 간 신뢰를 만든다

| 칸          | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상황        | 서로 모르는 사람이 만나 물건과 현금을 주고받는 중고거래.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 해법        | 당근 — 거래하려면 동네인증이 필요하고, 인증은 설정한 동네에 실제로 있을 때만 GPS로 받는다. 이웃임을 확인하려는 목적이다(`reported`, S30, S32). 인증은 대략 30일이 지나면 만료되고, 만료되면 다른 판매자에게 채팅을 보내거나 새 글을 쓸 수 없다. 이미 만든 채팅방과 구매 희망자가 먼저 보낸 채팅은 가능하다(S32). 프로필의 인증 횟수는 최근 30일 기준이라 상대가 이 동네를 얼마나 자주 썼는지 추정하게 한다(S30, S32). 짧은 시간에 너무 많은 동네에서 인증하면 인증이 제한될 수 있다(S32). 회사는 사기가 택배거래에서 많다며 직거래와 공공장소 만남을 권한다(S30, 근거 수치는 제시하지 않음). |
| 대조        | 대금 보류로 신뢰를 만드는 방식 — 번개장터의 구매확정 전 정산 보류(S29, MT-08).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 결정적 맥락 | 사업 방식(동네 기반 직거래) + 위험(낯선 사람과 대면). S30은 GPS로 동네를 인증한 진짜 이웃과 거래하게 한다고 밝힌다. 해석: 만날 수 있는 거리로 상대를 좁히면 사기 한 건의 비용이 줄고 서로 얼굴을 볼 수 있다는 것이 서비스의 약속이다.                                                                                                                                                                                                                                                                                                                                                        |
| 대가        | 인증을 받은 지역에서만 거래할 수 있고, 다른 지역에서 거래하려면 내 동네를 바꿔 그 동네에서 인증해야 한다(S32). 인증 후에는 그 지역에 없어도 만료 전까지 채팅할 수 있다(S32). 인증에는 휴대전화 위치 권한이 필요하다(S32). 먼 동네 물품은 바로구매로만 거래할 수 있다(S33).                                                                                                                                                                                                                                                                                                                   |
| 가져갈 원리 | 낯선 사람 간 신뢰는 상대를 믿게 만들기보다, 믿을 만한 범위(같은 동네, 얼굴을 볼 수 있는 거리)로 거래를 한정해 만든다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 안 맞는 곳  | 전국에서 희소 상품을 사고파는 시장, 위치 수집을 꺼리는 사용자층(`hypothesis`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 시점        | S30은 날짜가 없고 코로나19 수칙 항목이 남은 오래된 페이지다. S32 고객센터는 2026-11-02 확인 시점 현행이며 30일 만료·최근 30일 인증 횟수 기준이 여기서 확인된다. 도입 연월은 출처에서 확인하지 못했다.                                                                                                                                                                                                                                                                                                                                                                                        |

## 이 파일에서 뽑은 원리

- 되돌릴 수 없는 돈의 행동에는 축하나 속도보다 확인과 시간을 먼저 둔다(MT-01, MT-04, MT-07).
- 실수를 막는 장치와 실수 뒤 복구 경로를 한 쌍으로 설계한다(MT-02, MT-03).
- 마찰은 위험을 느낀 사람과 위험한 순간에, 가능하면 본인이 직접 켜게 한다(MT-04, MT-05, MT-07).
- 낯선 사람 간 신뢰는 범위를 좁히거나 돈을 맡겨 두는 방식으로 만들고, 공개 기본값은 상대와 사용자(미성년, 상점)에 따라 다르게 정한다(MT-06, MT-08, MT-09).
- 연령·성별은 설계 입력이 아니라 위험 신호(통화 중, 앱 설치, 부적합 상품)로 바꿔 쓴다(MT-05).
