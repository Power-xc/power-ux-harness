# 맥락 카드

같은 기능도 서비스의 규모·사업 방식·타깃·사용 상황이 다르면 정답이 바뀐다. 맥락 카드는 그 차이를 칸으로 쪼개 적는 양식이다. 칸마다 값과 근거, 설계 영향을 적고, 그중 정답을 가장 크게 바꾸는 2~3칸(결정적 맥락)을 골라 비교 대상과 제안의 기준으로 쓴다.

S5의 「사용 맥락」 개념(사용자·목표·과제·자원·환경을 함께 본다)을 이 양식의 뼈대로 삼았다. 사업과 위험 묶음은 서비스 디자인 실무에서 덧붙인 것이다.

## 쓰는 법

1. 칸마다 값을 쓰고 근거를 단다 — 출처 ID, `observed`, `reported`, `가정`, `NOT_CHECKED` 중 하나.
2. 묻기 전에 찾는다. 서비스 소개, 앱 스토어 설명과 연령 등급, 리뷰, IR·보도자료, 공공 통계에서 먼저 채운다.
3. 못 찾은 칸은 비워 두지 말고 `가정`으로 적는다. 결정적 맥락 후보인 `가정`만 한 번에 묻는다.
4. 값은 한 서비스 안에서도 세그먼트마다 다를 수 있다. 다르면 세그먼트별로 줄을 나눈다.
5. 칸의 값은 숫자나 짧은 구로 쓴다. 「젊은 층」·「시니어」 같은 말은 값이 아니다.

## 나이를 칸으로 푸는 법

「60대니까 글씨를 키운다」는 근거가 아니다. 나이 대신 아래 칸 중 무엇이 실제로 다른지 묻는다. 같은 나이대에서도 칸의 값은 사람마다 크게 다르다.

| 쓰려던 말            | 바꿔 쓰는 칸        | 확인하는 방법                                   | 근거                                                                                       |
| -------------------- | ------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 「시니어는 어렵다」  | U2 디지털 숙련도    | 설치·인증·오류 해결을 혼자 하는 비율, 문의 유형 | S4: 고령층 정보화 수준 71.4%, 역량 항목이 접근보다 훨씬 낮음(취약계층 평균 65.6% 대 96.5%) |
| 「눈이 나쁘다」      | U3 시력·대비        | 글자 200% 확대, 대비 비율 측정                  | S1 1.4.3·1.4.4·1.4.10                                                                      |
| 「손이 느리다」      | U4 손의 정밀도      | 대상 크기·간격, 끌기 대안 점검                  | S2 2.5.8·2.5.7                                                                             |
| 「기억을 못 한다」   | U5 인지 부담        | 기억·옮겨 적기가 필요한 단계 수, 재입력 단계 수 | S3 3.3.8·3.3.7                                                                             |
| 「사기에 잘 당한다」 | R4 사기 노출        | 사칭·유도 사기 유형과 노출 경로, 기관 주의 안내 | 기관 안내와 사고 사례(조사해서 출처 ID를 단다)                                             |
| 「자식이 해 준다」   | U6 보호자·대리 사용 | 대리 사용을 보여 주는 리뷰·문의 유무            | 열어 본 출처에 근거 없음 — 이 서비스의 리뷰·문의로 `observed`를 만든다                     |

연령 구간 숫자(S4의 71.4%)는 집단 평균이다. 이 서비스 사용자의 값이 아니므로 `reported` 참고치로만 쓰고, 실제 값은 이 서비스의 리뷰·문의·테스트로 `observed`를 만든다.

## 결정적 맥락 고르기

**뒤집기 시험** — 칸마다 묻는다. 「이 칸의 값이 반대라면 이 상황의 정답이 바뀌는가?」 바뀌지 않으면 결정적 맥락이 아니다.

| 단계 | 하는 일                                                                                             |
| ---- | --------------------------------------------------------------------------------------------------- |
| 1    | 설계할 상황 하나를 고정한다(예: 처음 보내는 계좌로 큰돈 송금).                                      |
| 2    | 20칸 각각의 값을 반대로 바꿔 상상한다(실수 비용이 작다, 사용자가 숙련자다, 취소가 된다).            |
| 3    | 반대로 바꿨을 때 기본안·확인 단계·예외 처리가 달라지는 칸에 표시한다.                               |
| 4    | 표시된 칸 중 바뀌는 폭이 가장 큰 2~3칸을 고르고, 고른 이유를 한 줄씩 쓴다.                          |
| 5    | 고른 칸이 `가정`이면 가장 먼저 확인한다. 안 고른 칸도 「왜 뒤집어도 정답이 같은가」를 한 줄 남긴다. |

고르기 어려울 때 점검한다.

- 4칸 이상이 표시되면 상황이 너무 크다. 상황을 둘로 쪼갠다.
- 모든 칸이 「중요하다」면 뒤집기 시험을 하지 않은 것이다.
- 한 묶음(예: 사용자 칸만)에서만 고르면 사업·위험 칸을 놓쳤을 수 있다. 한 번 더 본다.

## 채운 예시 (가상의 서비스)
