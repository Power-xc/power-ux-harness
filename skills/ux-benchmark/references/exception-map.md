# 상황·예외 지도

정상 경로만 설계하면 서비스가 실제로 평가받는 순간을 놓친다. 예외 지도는 정상 경로와 예외 12가지를 결정적 맥락의 세그먼트별로 펼쳐, 어느 칸부터 설계할지 순위를 매기는 양식이다.

## 출처

| --- | ----------------------------------------------- | ------ | ---- | ------------------------------------------------------------------------------------------------------------------- |
| S1  | Web Content Accessibility Guidelines (WCAG) 2.2 | W3C    | 2024 | 2.2.1 제한 시간은 끄기·늘리기·연장 중 하나가 가능해야 함, 3.3.7 같은 과정 안 재입력 금지, 3.3.8 인지 시험 없는 인증 |
| S2  | UX Research Cheat Sheet                         | NN/g   | 2017 | 발견 단계에서 현장 관찰과 경쟁 서비스 테스트를 쓰고, 출시 뒤에는 피드백·문의를 듣는 방법을 단계별로 정리            |

예외 유형 12가지 분류는 서비스 디자인 실무에서 쓰는 점검 목록이며, 표준이 아니다. 빠진 유형이 있으면 서비스에 맞게 더한다.

## 예외 유형 12가지

각 유형은 「사용자 눈에 어떤 일이 일어났나」와 「묻는 질문」으로 찾는다.

| #   | 유형          | 사용자 눈에 일어난 일          | 찾는 질문                                                                  |
| --- | ------------- | ------------------------------ | -------------------------------------------------------------------------- |
| 1   | 실패          | 요청이 처리되지 않았다         | 서버·결제·인증이 실패하면 사용자는 무엇을 잃고 무엇을 할 수 있나?          |
| 2   | 지연          | 결과가 늦다                    | 얼마 이상 걸리면 중복 요청이나 이탈이 생기나? 기다리는 동안 무엇을 보이나? |
| 3   | 부족          | 재고·잔액·한도·자리가 모자란다 | 모자란 사실을 언제 알리나? 대안(대기·일부 처리)을 줄 수 있나?              |
| 4   | 취소          | 하다가 그만둔다                | 어느 단계까지 취소되나? 취소하면 입력값·돈·예약은 어떻게 되나?             |
| 5   | 실수          | 잘못 눌렀거나 잘못 입력했다    | 되돌릴 수 있나? 확인은 보내기 전인가 후인가? 누가 책임을 지나?             |
| 6   | 중복          | 같은 일이 두 번 일어난다       | 두 번 누르면, 새로고침하면, 두 기기에서 하면 어떻게 되나?                  |
| 7   | 권한          | 허용·승인이 없거나 거절됐다    | 거절해도 쓸 수 있나? 다시 허용하는 길은 어디인가?                          |
| 8   | 오프라인      | 네트워크가 끊겼다              | 끊긴 사이 입력한 것은 남나? 다시 연결되면 이어지나, 중복되나?              |
| 9   | 처음과 오랜만 | 처음 쓰거나 오래 안 썼다       | 설명 없이 첫 행동이 가능한가? 오랜만에 오면 상태가 바뀐 것을 알리나?       |
| 10  | 한도          | 횟수·금액·용량 상한에 닿는다   | 한도를 미리 알리나? 한도를 풀 방법과 걸리는 시간은?                        |
| 11  | 사기 의심     | 거래·상대·메시지가 수상하다    | 시스템이 의심하면 누구를 막고 어떻게 알리나? 오탐일 때 풀 방법은?          |
| 12  | 대리 사용     | 다른 사람이 대신 쓴다          | 대리인이 할 수 있는 일과 못 하는 일은? 본인은 어떻게 알게 되나?            |

유형을 놓치지 않는 방법: 정상 경로 단계마다 위 12개를 한 번씩 묻고, 해당 없으면 `N/A`와 이유를 적는다. 해당되는데 확인하지 못했으면 `NOT_CHECKED`다.

## 세그먼트 × 예외 표

세그먼트는 맥락 카드의 결정적 맥락으로 나눈다(예: 구매자 / 수령자, 숙련자 / 비숙련자, 평일 낮 / 밤). 세그먼트가 같으면 처리도 같으므로 세그먼트를 늘리지 않는다.

| 예외 유형 | 세그먼트 A: <값> | 세그먼트 B: <값> | 세그먼트 C: <값> | 근거 |
| --------- | ---------------- | ---------------- | ---------------- | ---- |
| 1 실패    |                  |                  |                  |      |
| 2 지연    |                  |                  |                  |      |
| …         |                  |                  |                  |      |

칸에 적는 것: 일어나는가(예·아니오·`N/A`), 일어나면 사용자가 보는 것과 할 수 있는 것, 지금 서비스의 처리(있음·없음·`NOT_CHECKED`). 칸의 근거는 리뷰, 고객센터 문의 유형, 약관, 로그, 화면에서 관찰한 것이다. 근거가 없으면 `가정`이다.

## 순위 매기기

예외마다 세 값을 매기고 순위를 정한다. 숫자 점수보다 등급 표가 근거를 따지기 쉽다.

| 축                       | 높음                              | 중간                        | 낮음                   |
| ------------------------ | --------------------------------- | --------------------------- | ---------------------- |
| 빈도                     | 사용자 대부분이 한 번 이상 만난다 | 일부 세그먼트가 가끔 만난다 | 드물다                 |
| 실수 비용                | 돈·데이터·신뢰 손실, 기만 위험    | 시간 낭비, 왕복             | 짜증, 한 단계 되돌아감 |
| 되돌릴 수 있는지(역방향) | 되돌릴 수 없다                    | 사람 처리가 필요하다        | 사용자가 바로 되돌린다 |

1. 실수 비용이 「높음」이거나, 빈도 「높음」에 비용 「중간」 이상이면 첫 번째 묶음(먼저 설계)이다. 묶음 안에서는 되돌릴 수 없는 것을 위에 둔다.
2. 빈도 「중간」 이상에 비용 「중간」이면 두 번째 묶음이다.
3. 나머지는 세 번째 묶음이다 — 기본 처리(공통 오류 문구·재시도)로 덮는다.
4. 세그먼트마다 등급이 다르면 가장 높은 세그먼트를 기준으로 하고, 세그먼트별 등급을 표에 남긴다.
5. 등급이 `가정`이면 순위에 `가정`을 표시하고 검증 계획의 확인 항목으로 올린다.

순위 근거는 한 줄로 쓴다(예: 「되돌릴 수 없고 대리 사용자에게 자주 생김」). 순위를 정한 뒤 제안에서는 첫 번째 묶음 전부와 두 번째 묶음의 일부를 다룬다.

## 채운 예시 (가상의 서비스)

「동네 약속」 — 가상의 동네 반찬 정기배송 앱이다. 값은 양식을 보여 주려고 지어낸 것이며 실제 서비스의 사실이 아니다. 상황: 배송이 약속한 저녁 6시를 넘길 때. 결정적 맥락: 구매자와 수령자 분리(U6), 약속을 어긴 지연(B3), 저녁 응대 불가(B4).

| 예외 유형       | 구매자 (자녀, 앱 사용)                      | 수령자 (부모, 문자 위주)                    | 근거   |
| --------------- | ------------------------------------------- | ------------------------------------------- | ------ |
| 1 실패          | 결제 실패 시 구독 일시 정지 안내가 필요     | 해당 없음(`N/A`, 결제 안 함)                | `가정` |
| 2 지연          | 앱 푸시로 새 도착 시각과 선택지를 받는다    | 문자로 같은 내용을 받고 전화 한 번으로 확인 | `가정` |
| 3 부족          | 대체 메뉴 제안                              | 대체 메뉴를 문자로 알림                     | `가정` |
| 4 취소          | 이번 주만 건너뛰기, 전체 해지는 다음 주부터 | 직접 취소 불가 — 구매자에게 요청            | 약관   |
| 5 실수          | 수령 주소를 잘못 입력                       | 문 앞에 있는데 없다고 신고                  | `가정` |
| 6 중복          | 같은 주문을 두 번 눌러 이중 청구            | 해당 없음(`N/A`)                            | `가정` |
| 7 권한          | 알림 허용을 거절 → 지연을 모름              | 해당 없음(`N/A`, 앱 없음)                   | `가정` |
| 8 오프라인      | 신호 약한 지하철에서 주문 변경 불가         | 해당 없음(`N/A`)                            | `가정` |
| 9 처음과 오랜만 | 오랜만에 열면 일정이 바뀐 사실을 모름       | 첫 문자를 스팸으로 의심                     | `가정` |
| 10 한도         | 건너뛰기 횟수 한도에 닿음                   | 해당 없음(`N/A`)                            | 약관   |
| 11 사기 의심    | 배송 사칭 문자로 결제 링크 유도             | 같은 문자를 받고 링크를 누름                | `가정` |
| 12 대리 사용    | 주문자가 부모 계정으로 접속                 | 수령자가 주문자 명의로 전화 문의            | `가정` |

순위 (빈도 × 실수 비용 × 되돌릴 수 있는지):

| 순위 | 예외         | 빈도 | 실수 비용 | 되돌릴 수 있는지 | 한 줄 근거                                     |
| ---- | ------------ | ---- | --------- | ---------------- | ---------------------------------------------- |
| 1    | 11 사기 의심 | 낮음 | 높음      | 불가(돈 손실)    | 되돌릴 수 없어 빈도가 낮아도 맨 위에 둔다      |
| 2    | 6 중복       | 중간 | 높음      | 사람 처리        | 이중 청구는 신뢰 손실                          |
| 3    | 2 지연       | 높음 | 중간      | 사람 처리        | 약속을 어기는 가장 흔한 경우, 응대 불가 시간대 |
| 4    | 12 대리 사용 | 중간 | 중간      | 사람 처리        | 구매자·수령자 분리가 앱 전체에 걸친다          |
| 5    | 4 취소       | 높음 | 낮음      | 쉬움             | 많이 일어나지만 비용이 작아 기본 처리로 덮는다 |

제안에서는 순위 1~4를 구매자·수령자별로 처리하고(대상 상황이 지연이므로 3은 기본안에 둔다), 5 이하는 공통 처리에 맡긴다. 이 예시의 `가정`은 모두 검증 계획에 올린다.
