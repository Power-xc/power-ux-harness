# UX Flow

사용자가 목표에 닿는 모든 길을 그린다. 정상 경로만 그린 흐름도는 절반이다 — 취소·오류·뒤로·끝을 함께 그린다.

## Trigger

- `@ux flow <기능|목표>`: 과제 흐름과 화면 목록·상태 정의
- `@ux ia <서비스|메뉴>`: 정보구조와 내비게이션 설계
- 「흐름도 그려 줘」, 「화면 목록 뽑아 줘」, 「메뉴 구조 잡아 줘」, 「어떤 상태가 필요한지 정리해 줘」

## Input

- `goal`: 사용자가 끝내야 할 일과 완료 조건
- `entry`: 진입점(홈·알림·딥링크·검색·외부 링크)
- `roles`: 사용자 유형과 권한(비로그인·회원·관리자)
- `constraints`: 정책·법·기술 제약, 기존 화면
- `research`: 리서치 결과나 지표(있으면)

빠진 정책은 지어내지 않는다. 「정해야 할 것」 목록으로 올린다.

## Process

1. 목표, 진입점, 완료 조건을 한 문장으로 고정한다. 완료 화면이 무엇인지 적는다. 홈·랜딩처럼 여러 목적지로 갈라지는 허브 화면은 완료 화면 대신 진입 → 목적지 분기 표(목적지 · 찾는 사용자 · 진입 요소 · 도착 화면)를 완료 조건으로 쓴다.
2. 과제를 사용자 행동과 시스템 응답의 쌍으로 쪼갠다. 행동마다 다음 화면이나 상태를 적는다.
3. 정상 경로를 먼저 그리고, 각 단계에 예외 경로를 붙인다 — 뒤로, 취소, 건너뛰기, 입력 오류, 서버 오류, 다시 시도, 권한 없음, 세션 만료, 중간에 앱 이탈. `ux-benchmark`의 맥락 카드가 있으면 결정적 맥락의 세그먼트별로 예외 경로를 나눈다.
4. [`references/flow-notation.md`](./references/flow-notation.md)의 범례로 Mermaid 흐름도를 그린다. 화면은 사각형, 시스템 처리는 평행사변형, 분기는 마름모다. 노드 이름은 화면 ID와 화면명으로 쓴다.
5. 화면 목록을 만든다. 화면 ID는 고유하고 지운 뒤에도 재사용하지 않는다. 화면 ID·화면명·유형(페이지·대화상자·바텀시트·탭)·경로·로그인 필요 여부를 적는다.
6. 화면×상태 표를 만든다. 기본·빈 상태·로딩·오류·성공·권한 없음·끝(더 없음·마지막 단계)을 칸으로 두고, 해당 없으면 `N/A`와 이유를 적는다. 한 화면에 이유가 다른 빈 상태(첫 사용·결과 없음·오프라인·불러오기 실패 …)가 생기면 빈 상태 칸을 종류별로 나눈다. 기능 플래그·환경(데모·운영)에 따라 같은 화면이 다르게 그려지면 「데모=운영?」 열을 더하고, 다른 화면은 코드 분기 표(조건·플래그 | 데모 | 운영 | 화면 차이 | 코드 위치)로 적는다.
7. 정보구조가 범위에 있으면 메뉴 깊이를 3단계 안으로 두고, 이름은 사용자의 말로 쓴다. 이름이나 묶음이 불확실하면 카드 소팅·트리 테스트를 `ux-research`로 넘긴다.
8. 최상위 이동 패턴을 고른다. 몇 개의 최상위 목적지는 하단 탭, 많은 목적지는 드로어나 메뉴, 같은 화면 안 보기 전환은 탭이나 세그먼트 컨트롤이다. 고른 이유를 목적지 수와 사용 빈도로 적는다.
9. 뒤로 가기가 무엇을 되살리는지(입력값·스크롤 위치·필터) 적는다.
10. 결정되지 않은 정책을 「정해야 할 것」으로 모으고, 각 항목에 선택지와 영향받는 화면 ID를 적는다.

## Output

- 한 문장 목표와 완료 조건(허브 화면이면 진입 → 목적지 분기 표)
- Mermaid 흐름도(범례 포함) — 정상·예외·복구 경로
- 화면 목록 표, 화면×상태 표
- 정보구조 트리(범위에 있을 때)와 이동 패턴 선택 이유
- 정해야 할 것: 질문, 선택지, 영향 화면, 권장안(근거가 있을 때만)
- 판정: 아래 게이트를 모두 지나면 `READY`, 아니면 `NOT_READY`와 빠진 항목

## Hard Gates

| ID  | FAIL 조건                                                  |
| --- | ---------------------------------------------------------- |
| G1  | 완료 조건이나 완료 화면이 없음(허브 화면은 분기 표가 없음) |
| G2  | 취소·뒤로·오류 경로 없이 정상 경로만 그림                  |
| G3  | 화면 ID가 없거나 중복되거나 흐름도와 화면 목록이 서로 다름 |
| G4  | 적용되는 상태를 빼고 `N/A` 이유도 없음                     |
| G5  | 정해지지 않은 정책을 가정으로 채워 흐름에 넣음             |
| G6  | 메뉴 깊이가 3단계를 넘는데 이유가 없음                     |

## Skill Chaining

- 화면 한 장씩 상세 설계: `ux-spec`
- 메뉴 이름·묶음 검증(카드 소팅·트리 테스트): `ux-research`
- 그린 흐름을 실제 화면에서 점검: `ux-review`
- 메뉴·버튼 이름 다듬기: `ux-writing`
- 결제·구독·해지 흐름이면 해지 단계 수 점검: `ux-dark-patterns`
- 맥락별 예외 경로 근거와 다른 서비스 사례: `ux-benchmark`

## Constraints

- 사용자 흐름을 시스템 구조도(서버·DB)로 바꾸지 않는다. 사용자에게 보이는 화면과 상태만 그린다.
- 해지·탈퇴·취소 경로를 가입보다 길게 그리지 않는다.
- 흐름도 한 장에 노드가 많아 읽기 어려우면 단계별로 나눠 그린다.
- 경쟁 서비스의 흐름을 근거 없이 그대로 옮기지 않는다.
