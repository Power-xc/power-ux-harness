# 데스크 리서치

출처: NN/g Maria Rosala·Kate Moran「Synthetic Users: If, When, and How to Use AI-Generated "Research"」(2024) — 합성 사용자가 쓸모 있는 곳으로 데스크 리서치와 낯선 도메인 파악을 든다. 양식과 절차는 이 저장소에서 정리했다.

## 1. 출처 표

받은 자료와 직접 찾은 자료를 모두 여기에 올리고, 결과물의 모든 주장은 이 ID로 가리킨다.

| ID  | 종류          | 제목·주소                       | 연 날짜    | 열람 결과                   | 쓴 곳          |
| --- | ------------- | ------------------------------- | ---------- | --------------------------- | -------------- |
| S1  | 기획서        | 해지 흐름 개선 v0.3 (받은 파일) | 2026-11-02 | 열람                        | 결정 문장, 4장 |
| S2  | 우리 서비스   | 구독 관리 화면 (받은 주소)      | 2026-11-02 | 열람 — 해지까지 4단계       | 흐름 분해      |
| S3  | 앱 리뷰       | 앱 스토어 최신순 200건          | 2026-11-02 | 열람 — 기간 2026-05~10      | 리뷰 분류      |
| S4  | 규제          | 전자상거래법 기만 유형 조항     | 2026-11-02 | 열람                        | 규제 확인      |
| S5  | 비슷한 서비스 | 받은 주소                       | 2026-11-02 | `NOT_CHECKED` — 로그인 필요 | 쓰지 않음      |

- 종류: 기획서, 우리 서비스, 비슷한 서비스, 앱 리뷰, 규제·가이드라인, 표준, 통계·인구 데이터, 논문·아티클, 실제 사용자 데이터.
- 열지 못한 자료는 `NOT_CHECKED`와 이유를 적고, 그 자료에서 나올 법한 내용을 짐작해 쓰지 않는다.
- 1년 넘은 자료는 최신판이 있는지 다시 확인하고, 시행일·개정일을 함께 적는다.

## 2. 규제·가이드라인

해당 분야의 법·고시·가이드라인을 원문으로 연다. 판단은 `ux-dark-patterns`·`ux-a11y` 기준을 따른다.

| 분야               | 먼저 열 것                                                         |
| ------------------ | ------------------------------------------------------------------ |
| 구독·결제·환불     | 전자상거래법의 기만 유형 조항, 공정위 다크패턴 자율관리 가이드라인 |
| 개인정보 수집·동의 | 개인정보 보호법과 동의 관련 안내서                                 |
| 접근성             | WCAG 2.2, KWCAG 2.2, 모바일 앱 접근성 지침                         |
| 해외 사용자        | EU DSA 제25조, 미국 FTC 기만 설계 보고서                           |

## 3. 비슷한 서비스의 흐름 분해

- 화면을 베끼지 않고 단계 수, 쓰인 패턴 이름, 상태, 핵심 문구로만 분해한다.
- 직접 본 화면은 `observed`, 남의 글이나 영상으로 본 것은 출처 ID와 함께 `reported`로 적는다.

| 서비스 | 과제      | 단계 수 | 패턴(순서대로)                               | 눈에 띈 상태·문구      |
| ------ | --------- | ------- | -------------------------------------------- | ---------------------- |
| S2     | 구독 해지 | 4       | 목록 → 바텀 시트 → 해지 이유 → 확인 대화상자 | 완료를 토스트로만 알림 |

## 4. 앱 리뷰 분류

1. 스토어, 기간, 정렬 기준, 표본 수를 먼저 적는다.
2. 분류 기준을 읽기 전에 정하고, 읽다가 새 분류가 생기면 기준을 고친 뒤 처음부터 다시 센다.
3. 분류별 건수와 별점 분포를 함께 적는다. 대표 인용은 20자 안팎으로, 작성자 이름 없이 쓴다.
4. 리뷰는 불만이 많이 쓰이는 쪽으로 치우친다. 건수는 「얼마나 흔한가」가 아니라 「어떤 문제가 있는가」의 근거로만 쓴다.

```markdown
S3 · 앱 스토어 최신순 200건 · 2026-05-01~2026-10-31

| 분류                | 건수 | 대표 인용(20자 안팎)      |
| ------------------- | ---- | ------------------------- |
| 해지 경로를 못 찾음 | 38   | "해지 버튼이 어디 있나요" |
| 남은 기간 모름      | 21   | "해지하면 바로 끊기나요"  |
| 환불 문의           | 12   | "환불은 어디서 하나요"    |
```

## 5. 데스크 리서치 요약 쓰기

- 규제에서 꼭 지켜야 하는 것, 흐름 분해에서 나온 패턴 후보, 리뷰에서 나온 문제를 따로 적는다.
- 결정 문장과 관련 없는 발견은 「다음 결정의 재료」로 따로 둔다.
