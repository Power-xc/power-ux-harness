## 1. 후보안

- 2~3개. 같은 과제를 끝낼 수 있어야 하고, 패턴 이름·상태·문구로 쓴다(「해지를 쉽게」가 아니라 「구독 관리 → 해지 확인 대화상자(닫기·해지하기 같은 크기) → 완료 화면(남은 기간 날짜, 다시 구독)」).
- 후보 설명은 같은 틀(무엇을 보여 주나 · 장점 · 단점)로 쓰고 장점과 단점을 같은 수로 적는다. 현재안의 약점만 문장으로 적고 이미 있는 장점(화면에 있는 안내 문구 등)을 빼면 순위가 설명에 끌려간다.
- 후보끼리는 한 요소만 다르게 한다. 여러 요소(시간표 + 날짜 + 링크)를 한 후보에 묶어 그 후보가 이기면 어느 요소 덕인지 구분할 수 없다 — 요소별로 나눈 후보를 다음 실행에 넣거나 결과에 「요소 미분리」로 적는다.
- **미끼 안**: 결함이 분명한 안 하나를 섞는다(예: 해지 버튼이 없는 안, 다음 행동 없는 오류 문구). 순위만으로 확인하지 않는다 — 순위 밖에 「이 안으로 <핵심 행동>을 해도 되나요? 예/아니요와 이유」를 따로 묻고, 미끼에 「예」라고 하거나 미끼를 1위로 올린 실행은 무효다.
- 실행마다 후보안 이름표를 A·B·C 대신 의미 없는 기호(◇·△·○)로 바꾸고 순서를 섞는다. 모델은 보기 순서와 이름표에 끌린다. 숫자·가나다·ABC처럼 순서를 가진 계열은 쓰지 않고, 지시에 「답할 때 이름표를 그대로 쓰고 바꾸지 마세요」를 넣는다. 이름표를 바꿔 쓴 답은 버리고 다시 받는다.

## 2. 인지적 워크스루

과제를 정답 동작 순서로 나누고(단계 크기는 미리 정한다), 단계마다 페르소나의 입장에서 네 가지를 묻는다.

1. 이 단계에서 해야 할 일을 하려고 할까?
2. 올바른 동작이 있다는 걸 알아챌까?
3. 그 동작이 원하는 결과로 이어진다고 연결할까?
4. 동작한 뒤 과제가 나아가고 있다는 걸 알까?

- 하나라도 「아니요」면 그 단계는 실패다. 실패마다 실패 이야기 — 어떤 가정 때문에 막혔는지 — 를 한두 문장으로 쓴다.
- 지금까지 지나온 화면 이력을 맥락에 둔다. 이력이 있어야 사람이 헷갈릴 곳을 더 잘 찾아낸다.
- 합성 에이전트는 사람보다 과제를 더 잘 끝내고 막히는 곳을 덜 찾는다. 통과는 낙관적인 상한으로 읽는다.

## 3. 묻는 순서와 편향 줄이기

1. 자유 서술: 「이 화면에서 무엇을 하려고 하나요? 어디서 망설이나요?」
2. 반대 의견: 「이 안이 불편할 이유를 두 가지 말해 주세요」 — 회의적 페르소나에게는 꼭 받는다.
3. 마지막에 순위: 평점보다 순위를 받고, 역문항 하나를 섞는다.

- 가설과 「평가 중」이라는 사실을 알리지 않는다. 평가받는다고 느끼면 바람직해 보이는 답으로 쏠린다.
- 후보를 나란히 보여야 하는 비교 과제는 평가 중임을 숨길 수 없다. 첫인상과 자연스러운 행동은 한 실행에 후보 하나만 보여 주는 단일안 실행으로 받고, 순위는 비교 실행에서 받는다. 결과마다 어느 실행에서 나왔는지 적는다.
- 「좋은 점을 말해 주세요」처럼 한쪽으로 이끄는 질문을 쓰지 않는다.
- 숫자 척도만 직접 물으면 분포가 비현실적이 된다. 자유 서술을 먼저 받고 척도는 그다음에 매긴다.

## 4. 실행과 기록

| 항목   | 기준                                                                                                                                    |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| 단위   | 페르소나마다 독립된 맥락(가능하면 서브에이전트)                                                                                         |
| 반복   | 순서·이름표를 바꿔 기본 3회, 결정이 크면 5회                                                                                            |
| 교차   | 가능하면 다른 모델 계열로 1회 이상. 같은 결과도 검증은 아니다(편향을 공유한다)                                                          |
| 기준선 | 빈 페르소나, 인구통계만 있는 페르소나를 같은 방식으로                                                                                   |
| 기록   | 모델·버전, 프롬프트 원문, 온도 같은 설정(도구가 노출하지 않으면 그렇게 적는다), 순서 배치, 날짜, 데이터셋 버전                          |
| 조건   | 글자 200%·화면 낭독기 같은 접근성 조건은 서술만 주지 않고 그 조건으로 렌더한 캡처를 함께 준다. 캡처가 없으면 「조건 서술만」으로 적는다 |

| -------- | ------ | ----------------- | -------------------------------------- | ----------- |

| 미끼     | ◇      | 2 (모든 페르소나) | 해지 버튼을 찾지 못함 — 실행 유효      | —           |

## 6. 보고

- 순위와 안정성: 「3회 모두 B안 1위, A·C는 2회 자리 바뀜」.
- 일치율: 페르소나·실행·모델 사이에서 같은 판단이 나온 비율.
- 기준선 비교: 기준선과 같은 결과면 「페르소나 신호 없음」 — 순위를 정한 것은 페르소나가 아니라 후보 문구다. 추천 근거 사슬에서 페르소나 속성을 빼고 후보 문구 차이로 설명한다.
- 고유 답 수: 답이 몇 가지로 몰렸는지. 합성 응답은 가장 흔한 답에 쏠리고 드문 답과 세그먼트 차이를 지운다.
- 쓰지 않는 것: 「사용자의 70%가 선호」, 전환율 상승 예측, 효과 크기. 합성 결과는 방향은 맞힐 수 있어도 크기를 부풀린다.

## 7. 볼 수 없는 것

드문 답과 새로 떠오르는 주제, 작은 세그먼트의 차이, 감정과 신뢰, 실제 클릭·스크롤 같은 행동, 영어권 밖 사용자의 대표성. 이 목록을 결과물에 그대로 적고, 검증 계획에서 실제 사용자로 확인할 항목을 고른다.
